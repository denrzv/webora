## Hosted manifest preflight

Before emulator work, CI fetches the exact live manifest from:

`https://denrzv.github.io/.well-known/siteskin.json`

The run must fail fast unless all of the following are true:

- `presentation.hub == "drawer"`;
- `presentation.dock == ["catalog", "cart", "profile"]` in order;
- bottom navigation contains `home`, `catalog`, `cart`, `profile`;
- quick actions contain `call-shop`.

The fetched JSON is stored as `artifacts/hosted-siteskin.json` and the verdict as
`artifacts/hosted-siteskin-validation.txt`. Both are uploaded with diagnostics. This prevents a stale
remote fixture from surfacing minutes later as an opaque Compose tag failure.

## Automated contract

The hosted Pixel 6 / API 33 run executes `LiveSiteHostedSuite` in one emulator boot:

1. six-frame human-facing showcase;
2. deep live navigation smoke without extra screenshots.

The showcase requires:

- current integrated header and browser-owned Navigation Hub;
- projected Catalog/Cart/Profile dock slots;
- compact drawer containing Home + Call and excluding projected ids;
- scrim dismissal before Profile dispatch from the dock;
- Account page result;
- regular Google browsing with all SiteSkin state absent.

The smoke retains product navigation and browser Back/Forward, but after the initial deterministic
`Happy Days` click it observes route state through the projected Catalog selection instead of DOM link
visibility.

## Screenshot ownership

Run #41 exposed a legitimate Webora application subwindow whose generic focused title was
`Pop-Up Window`. CI-010 does not whitelist that title. The pure ownership policy accepts a generic
focused window only when the same `dumpsys window` snapshot proves Webora focused app, Webora package,
`APPLICATION_SUB_PANEL` / 1002, and a Webora parent window. Missing or foreign evidence remains blocked.

## Workflow contract

`Android screenshots` supports both manual dispatch and relevant `push` events on `main`. Path filters
cover Android/browser/SiteSkin/evidence code, scripts, Gradle inputs and the workflow itself. Docs-only
or report-only changes do not match. Runs share one concurrency group with
`cancel-in-progress: false`.
