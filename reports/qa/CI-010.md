protocol default SiteSkin action presentation. The fixture does not explicitly request bouquet, so
`auto -> drawer` is the hosted visual contract for this ticket.

visual evidence only when a real deployed fixture explicitly requests it.

## Automated contract

1. six-frame human-facing showcase;

The showcase requires the drawer hub before `04-bloom-actions.png`, trusted reference action ids,
Profile navigation, then ordinary Google browsing with SiteSkin drawer/action state absent. The smoke
retains product Back/Forward, drawer action dispatch, Home boundary and regular-origin teardown.

## Screenshot ownership

Run #41 exposed a legitimate Webora application subwindow whose generic focused title was
`Pop-Up Window`. CI-010 does not whitelist that title. The pure ownership policy accepts a generic
focused window only when the same `dumpsys window` snapshot proves:

- `mFocusedApp` belongs to Webora;
- the focused window block has exactly Webora's package;
- its type is `APPLICATION_SUB_PANEL` / Android type 1002;
- its parent window belongs to Webora.

Missing or foreign evidence remains blocked. Existing ANR/crash/unknown-window negative controls stay
in force.

## Workflow contract

`Android screenshots` supports both manual dispatch and relevant `push` events on `main`. Path filters
cover Android/browser/SiteSkin/evidence code, scripts, Gradle inputs and the workflow itself. Docs-only
or report-only changes do not match. Runs share one concurrency group with `cancel-in-progress: false`.
