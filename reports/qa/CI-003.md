## Edge cases

- **invalid manifest → regular browser mode** — N/A — no logic change. No manifest is parsed, fetched
  or validated by anything in this ticket. The frames depict manifest-driven UI; nothing
  manifest-driven influences the check, which reads only pixels and bounds the harness supplies.
- **origin change / redirect** — N/A — no logic change. No network request is made by the guard or
  the policy. The journey's own navigation is `CI-001`/`CI-002` behaviour, unchanged.
- **offline with cached manifest** — N/A — no logic change. The check reads an in-memory bitmap.
- **oversized or malformed payload** — **Applicable.** The "payload" is a sampled region. An empty
  sample array is `Blank` (scenario 5). Region bounds are clamped to the bitmap in `sampleRegion`, so
  a semantics rectangle larger than the screen cannot index out of range. Sampling is strided at 4 on
  both axes — ~110k samples of a ~1.9M-pixel region — and the whole check completed in 696 ms on the
  hosted runner, so `CI-002`'s contention concern is not re-created.
- **accessibility (TalkBack, font scale)** — N/A for the app; no Compose surface, string resource or
  semantics node changes, and `BrowserSurfaceConventionsTest` is green. For the evidence itself: the
  measurement now reaches the reviewer as text in `rendered-<frame>.txt`, so "did the page render"
  can be answered without opening an image.
