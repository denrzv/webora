## Edge cases

- invalid manifest → regular browser mode: PASS in existing mode/validation coverage; the branded
  dock is reachable only from trusted `BrowserMode.Integrated`, and regular mode shows the neutral shell.
- origin change / redirect: PASS in existing mode/publication coverage; exact-origin departure makes
  the dock unreachable and a late asset cannot publish against a different configuration.
- offline with cached manifest: PASS by unchanged pipeline contract; an accepted cached configuration
  may project guarded colors, while unavailable logo transport resolves to the stable monogram.
- oversized or malformed payload: PASS in unchanged core/brand pipeline coverage; no parsing or
  loader limits were bypassed and rejected assets never reach the Hub.
- accessibility (TalkBack, font scale): PASS in compiled semantics/geometry coverage; localized Hub
  description survives decorative pixels, disabled state remains native, and 200% targets compile.
  Runtime TalkBack/visual inspection is unavailable without a device.
- brand loading/supersession: PASS — the target is stable during monogram→bitmap replacement and
  existing identity guards reject prior-tab/config publication.
- dark theme: PASS in guarded presentation unit/Compose compilation; `onSecondary` and `onPrimary`
  come from the existing light/dark contrast projection rather than raw manifest colors.
- Hub open/close: PASS in existing lifecycle tests; hub visibility changes no lower chrome inventory
  and generation/mode changes close it.
