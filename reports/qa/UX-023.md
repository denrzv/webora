## Scope

The integrated header's response to constrained width and large font scale: one pure placement
decision, one `BoxWithConstraints` consuming it, and a new row the trust chip occupies when the brand
row cannot hold it. What the chip *says* — `UX-021`'s four `TransportSecurity` states and
`transportLabel`'s single ownership — is untouched and was verified only as *unchanged*, as were
`BROWSE-011`'s control row, `LOGO_SLOT_SIZE`, and the expressive header's own constants.

Verified on `c45fcfb` plus `TASK-FIX-1`, based on `origin/main` `c93c9a2`.

## Edge cases

- **invalid manifest → regular browser mode** — Unchanged by construction. The header composes only
  in `PROTECTED_INTEGRATED`; an invalid manifest never reaches it. The placement decision takes no
  configuration and cannot be reached by a manifest at all.
- **origin change / redirect** — No origin decision is touched. `UX-012`'s exact-origin teardown
  removes the whole header, both rows with it. The chip's content still comes from
  `SecurityPresentation`, derived only from the committed `SiteOrigin`.
- **offline with cached manifest** — N/A. No network, cache or asset path is implicated; the
  decision reads two platform values and a browser-derived string length.
- **oversized or malformed payload** — Bounded before it reaches this row, and irrelevant to the
  decision: a manifest cannot lengthen the registrable domain, which is the only content input.
- **accessibility (TalkBack, font scale)** — This ticket *is* the font-scale case. Verified by the
  gate: the decision is total across scale and width; the chip's `contentDescription`, ground and
  tints are unchanged so screen-reader output does not regress; no new colour enters the measured
  table. **Not verified on a device:** that a 13-character domain actually escapes the ellipsis at
  200%, which is scenario 21 and the single most important assertion in the ticket.

## Result

Status: QA_PASSED

Notes:

- **The review found a defect the tests could not.** `SECURITY_CHIP_MAX_WIDTH` still capped the chip
  at 160 dp on its own row, so the wrap produced a taller header showing the same truncated domain —
  criterion 1 failing with everything green. `SECURITY_CHIP_FLOOR` is 140 dp and a floor below the
  cap can never detect the cap. Fixed in `TASK-FIX-1`, and the new assertion requires *more* than the
  inline cap so the regression cannot return quietly.
- **The instrumented half is compiled, not executed**, and it holds three of the twelve acceptance
  criteria (1, 2, 7) — including the one the ticket is named for. Layout at 200% font scale is a
  text-measurement fact requiring a device and this checkout has none. Instrumented results are
  evidence and are never promoted to a gate claim (`A11Y-001`).
- The decision itself is fully covered by the JVM gate: every row of the measured table, totality,
  reachability of both branches, and the no-manifest-input scan all fail on a developer machine when
  their protection is removed.
