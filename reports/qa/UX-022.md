## Edge cases

- **invalid manifest → regular browser mode** — Unchanged and covered by construction. A `hub` value
  can never reject: the schema constrains it by pattern, and the security layer's only disposition
  for it is `warn`. `SpecCorpusTest`'s layer-order assertion would fail if a rejecting diagnostic
  were ever registered for `/presentation/hub`.
- **origin change / redirect** — The hub is composed only inside `PROTECTED_INTEGRATED`, and
  `UX-012`'s exact-origin teardown removes it with the rest of integrated chrome before the next
  projection. Hub state has one owner with its three existing resets, asserted structurally
  (scenario 23) because the state lives inside a composable.
- **offline with cached manifest** — N/A to the decision, but worth stating: the hint travels with
  the cached bytes and is re-validated for the observed origin like everything else, so a cached
  `drawer` cannot outlive the origin that published it. No network, cache or asset path was touched;
  the drawer takes the already-published `BrandAsset` and is asserted to contain no loader.
- **oversized or malformed payload** — Bounded before the app sees it. `hub` is at most 32
  characters by schema pattern, and what reaches any UI is a three-value enum, so no site-authored
  string exists for this field at the app layer at all. `carousel`, `https://evil.example/x` and
  `Drawer` all arrive as `AUTO`.
- **accessibility (TalkBack, font scale)** — Partially verified. Verified by the JVM gate: only
  navigation rows publish `selected` and a `stateDescription`, so state is never colour-alone; the
  active pair is `primary`/`onPrimary` against `secondary`/`onSecondary`, already in `SKIN-001`'s
  guarded set; labels stay bounded by `accessibleLabel`; every icon is decorative with the row
  carrying the accessible name. **Not verified on a device:** actual TalkBack output, the 320 dp /
  200% layout, and that twenty entries scroll rather than truncate — which is the acceptance
  criterion most in need of a device (scenario 19).
