# QA Report: CI-002
Status: QA_PASSED

## Scope

The screenshot pipeline's readiness, evidence-integrity and build-ordering behaviour. Unlike every
previous UI ticket in this repository, the runtime half is **not** environment-unavailable: the
deliverable is a hosted workflow, and two hosted runs were executed against the ticket branch. What
remains unavailable here is only what needs an emulator *in this checkout* — `AGENTS.md` forbids a
software-only one — and the artifact's PNG bytes, which require downloading the run artifact.

## Edge cases

- **invalid manifest → regular browser mode** → N/A. No validation, discovery or manifest code
  changed; the journey still drives the real consent flow.
- **origin change / redirect** → N/A for this ticket, and unchanged: the journey still asserts the
  exact canonical `https://denrzv.github.io` consent identity, which a redirect elsewhere cannot
  satisfy.
- **offline with cached manifest** → N/A. A fresh emulator has no cache; a live outage still fails
  the run with retained diagnostics, as `CI-001` established.
- **oversized or malformed payload** → N/A — no parser of remote input changed. The one new parser
  reads `dumpsys` output from the device, and its malformed cases (`no mCurrentFocus`, unreadable
  line, two disagreeing lines) are covered by scenarios 1 and 4.
- **accessibility (TalkBack, font scale)** → N/A — no UI changed. The guard reads the window manager,
  not the semantics tree, and adds no affordance to the product.
- **a dialog appears between the guard and the shutter** → Inherent and unclosable: the check is
  immediately before `takeScreenshot()`, but the two are not atomic. Bounded by the fact that the
  known cause of such dialogs has been removed rather than merely detected.
- **the emulator never settles** → Bounded by a 180-second deadline, then a red job with every
  sample recorded. Observed for real in run `31512048008`.
- **System UI hangs mid-journey** → The guard clears it twice at most, records each dismissal, and
  fails if it survives. Unexercised in CI (no ANR occurred); the decision it depends on is proven by
  scenarios 2–4.
- **a Webora crash or ANR** → Fails the capture with the observed window in the message, by the same
  path scenario 2 covers. Not induced on a hosted run: doing so would require breaking the product
  in `src/main`, which this ticket forbids, to demonstrate what the negative control already proves
  per decision.

## Known limits

1. **The PNGs were not looked at from this checkout.** Downloading a run artifact needs credentials
   this environment does not have. The supporting evidence is strong but indirect: the guard asserted
   that Webora owned the focused window immediately before each of the three captures, and any
   obstruction would have been either dismissed-and-recorded or fatal. The owner can confirm visually
   by downloading `webora-screenshots-api33-eb00683…`.
2. **A dismissal is recorded in the artifact, not in the job log.** With zero dismissals there is no
   file, so absence is quiet. Job-summary presentation belongs to `DEVX-002`, which lists it.
3. **The Docker-based shellcheck hook could not run here.** ShellCheck 0.11 was run directly over
   `scripts/*.sh` instead, which is the stricter of the two — it is what caught the SC2164 that the
   pinned 0.10 image had let through on `main`.
