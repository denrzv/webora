## Edge cases

- invalid manifest → regular browser mode: PASS — rejected input cannot construct Integrated mode;
  regular projection contains browser top/bottom chrome and no SiteSkin actions.
- origin change / redirect: PASS — complete-origin mismatch synchronously projects regular chrome;
  exact same-origin navigation retains integration.
- offline with cached manifest: PASS — no fetch/cache change; activation still requires an accepted,
  consented, current configuration, otherwise regular browser controls remain.
- oversized or malformed payload: PASS — parser/validator is unchanged and rejected input has no
  handoff API seam.
- accessibility (TalkBack, font scale): PASS for retained accessible names, browser-owned content
  descriptions, 48 dp controls, and compiled Compose tests. Runtime TalkBack/200% visual inspection
  is unavailable without a device.
- consent dismissed/permanently denied: PASS — neither outcome invokes activation; ordinary shell is
  independent of a consent grant.
- global SiteSkin disabled: PASS — existing deactivation changes Integrated to Regular without losing
  page state; projection switches both SiteSkin layers off.
- inactive tab callback: PASS — background tab state can update only its owner and active projection
  remains selected-tab-only.
- stale brand load: PASS — an asset is visible only when its configuration object is the selected
  integrated configuration; active configuration gets an immediate browser-derived monogram.
- Android system navigation: PASS by static boundary — existing `OnBackPressedDispatcher` and single
  `safeDrawing` owner are unchanged; runtime gesture/three-button verification is environment-limited.
