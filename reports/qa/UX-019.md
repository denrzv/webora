## Edge cases

- invalid manifest → regular browser mode: PASS by architecture; neither integrated surface is
  rendered without an accepted `BrowserMode.Integrated`, and existing regular-browser fallback is
  unchanged.
- origin change / redirect: PASS — page start and integrated-configuration changes dismiss both
  surfaces before a new origin can reuse stale actions.
- offline with cached manifest: PASS by ownership; no new network I/O was added, and a cached accepted
  configuration projects through the same bounded model.
- oversized or malformed payload: PASS — validation remains upstream; labels are bounded, item
  collections keep their existing caps, and the bouquet adds a hard five-item unique projection.
- accessibility (TalkBack, font scale): PASS — named 52 dp petals, selected navigation state,
  browser-owned labels, standard modal semantics, real Back tests, and 200% dock coverage. Manual
  TalkBack speech was not required for this visual/menu change.
- zero site actions: PASS — the flower remains a stable branded command and no empty popup is shown.
- fewer than five actions: PASS by layout logic — one to four actions use symmetric lift patterns;
  malformed counts cannot reach the popup because the projection is capped.
- duplicate action IDs: PASS — de-duplicated before the five-item cap in the unit test.
- rapid switching between flower and More: PASS by state transitions — opening one synchronously
  clears the other, so overlays cannot accumulate.
- dark theme: PASS by construction — browser sheet uses `MaterialTheme`; petals use validated
  SiteSkin on-colours. No new raw colour literal is introduced.
