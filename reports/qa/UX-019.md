## Edge cases

- **invalid manifest → regular browser mode** — N/A. The switcher reads no manifest and is composed
  in every mode; an invalid manifest changes a tab's `BrowserMode` to `Regular`, and `browserLabel()`
  already handles all three modes. Unchanged by this ticket.
- **origin change / redirect** — N/A to this surface, and verified as unchanged: a row's label is
  recomputed from the tab's current `BrowserMode` on every recomposition, exactly as before. An
  exact-origin departure that drops integrated mode changes the row from
  `Integrated.origin.registrableDomain` to `Regular.origin?.registrableDomain`, which are the same
  string for the same origin.
- **offline with cached manifest** — N/A. No network, no cache read, no I/O. The surface performs no
  work that can be offline.
- **oversized or malformed payload** — N/A. No remote payload enters this surface. The one bound that
  does apply is visual: the label is `maxLines = 1` with an ellipsis, and the underlying string is
  already a registrable domain or one of two compiled fallbacks, never arbitrary remote text.
- **accessibility (TalkBack, font scale)** — Partially verified. Verified by the JVM gate: no literal
  reaches `Text(` or an accessible name; the close control cannot ship nameless because
  `WeboraIconButton`'s signature requires a non-null `contentDescription`; the 48 dp target comes
  from `browserTouchTarget()` on the select surface and from the wrapper on the close control; the
  `selected` semantics property is retained and the `tab_description` sentence survives as the row's
  `contentDescription` rather than being deleted with the visible label. **Not verified on a device:**
  actual TalkBack output, and reflow at 200% font scale with eight tabs open. Scenarios 22–24 are the
  gap.
