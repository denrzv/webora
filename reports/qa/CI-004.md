## Edge cases

- **invalid manifest → regular browser mode** — N/A. No manifest, validator, origin or discovery code
  is touched; nothing in this ticket sits on the manifest path.
- **origin change / redirect** — N/A for the same reason. The harness's `requireAppOwnsScreen` runs
  between navigations and reads only `dumpsys window` and the accessibility tree.
- **offline with cached manifest** — N/A. No network path changed.
- **oversized or malformed payload** — the analogous case here is an unbounded node tree, and it is
  bounded: the view-id walk dequeues at most 400 nodes and records at most 60 ids, and after
  `TASK-FIX-1`/`TASK-FIX-3` it runs at most once per `requireAppOwnsScreen` call and only on the
  refusal path. A malformed or unreachable tree yields zero ids, which is a `NotYet` and a recorded
  reason, never a press.
- **accessibility (TalkBack, font scale)** — N/A to the product. Worth stating precisely because this
  ticket *uses* the accessibility APIs: it reads the automation's node tree to find a system dialog's
  button. It publishes no semantics, changes no `contentDescription`, and none of this code exists in
  any shipped variant — `src/androidTest` and `src/screenshotPolicy` are in no APK.

## Additional verification

- **The allow-list did not grow.** `DISMISSABLE_ANR_PROCESS` and `WAIT_VIEW_IDS` are unchanged in
  value; `WAIT_VIEW_IDS` moved file without an edit. Scenarios 9–12 are the new control, and it only
  ever *narrows* what may be searched relative to the old `rootInActiveWindow`, which had no package
  check at all.
- **`SETTLE_TIMEOUT_MILLIS` is unchanged at 20 s.** Raising the deadline instead of fixing the lookup
  is the shortcut the plan refused.
- **The change can only make the harness refuse later, never sooner-accept.** Every path that threw
  before still throws; the zero case throws at the deadline instead of on first contact. That is
  `CI-005`'s standing constraint, checked against this diff.
- **Complexity:** `:app:detektDebugAndroidTest` reports one finding, `captureWhenRendered` at 54
  lines, which predates this ticket. Recorded because `./gradlew detekt` **does not analyse
  `androidTest`** — verified directly by appending a 140-character line to the new file and watching
  the gate stay green. Out of scope here and flagged in `/review` for its own ticket.
