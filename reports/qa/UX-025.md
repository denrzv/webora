## Edge cases

- **invalid manifest → regular browser mode** — Unchanged. `presentation.dock` has no rejecting
  disposition at any layer: the schema constrains by pattern, and every security failure is a
  truncate, a drop or a warn.
- **origin change / redirect** — No origin decision added. The arrangement is derived per
  composition from the active tab's configuration, so `UX-012`'s exact-origin teardown removes it
  with the rest of integrated chrome. Nothing is retained that could outlive the origin.
- **offline with cached manifest** — The dock ids travel with the cached bytes and are re-validated
  for the observed origin like everything else, so a cached projection cannot outlive its origin.
- **oversized or malformed payload** — Bounded before the app sees it: at most three ids, each at
  most 64 characters by the id grammar, each already resolved to a validated item. The app layer
  caps again.
- **accessibility** — Verified by the gate: selection is published only for navigation rows, exposed
  as `selected` plus a `stateDescription` so it is never colour-alone; labels are the already
  `accessibleLabel`-bounded ones; icons come from the closed semantic map. **Not verified on a
  device:** the 48 dp targets at five slots on a 320 dp host, and RTL — scenario 22.

  serve until the companion PR merges — which is a working state, not a broken one, since an absent
