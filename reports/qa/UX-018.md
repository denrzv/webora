## Edge cases

- invalid manifest → regular browser mode: N/A to modal logic; settings is browser-owned and opens
  identically from regular or integrated chrome. Existing manifest fallback remains unchanged.
- origin change / redirect: PASS by ownership; settings stores no current-origin presentation and
  dismissal reveals whatever browser state remains selected without initiating navigation.
- offline with cached manifest: N/A to modal logic; no new network I/O exists. The emulator proxy
  issue was corrected separately and the consent dialog was observed before settings validation.
- oversized or malformed payload: N/A to modal logic; no parsing or remote payload reaches settings.
- accessibility (TalkBack, font scale): PASS for localized named controls, standard dialog Back,
  safe insets, scrollable content, connected semantics, and compiled 200% coverage. Manual TalkBack
  speech was not required for this narrow window-policy change.
- nested confirmation Back/Cancel: PASS for Cancel in the live journey; standard `AlertDialog`
  dismissal remains separately covered and settings visibility is independent.
- repeated open/close: PASS in live Back then reopen then Close journey; no stale overlay remains.
- dark theme: PASS by construction; the opaque surface uses app `MaterialTheme.background`, never a
  SiteSkin palette. No new raw color is introduced.
