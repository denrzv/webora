# QA Report: A11Y-001
Status: QA_PASSED

## Scope
Accessibility contract for browser-owned chrome: touch targets, font-scale reflow, browser-owned
copy, security semantics, status announcements, non-colour-alone state, WCAG AA contrast across both
theme projections, and the bound on manifest text entering the accessibility tree.

Out of scope, and unchanged: web page content inside the `WebView` (renderer-owned), the SiteSkin
manifest schema, and any persisted state.

- `bash scripts/pre-commit-check.sh` green: gitleaks, shellcheck, `:siteskin-core:test` with no
  Android SDK, `test`, `detekt`.
- `:app:testDebugUnitTest` — **109 tests, 0 failures**.
- `:app:assembleDebug` and `:app:assembleDebugAndroidTest` both succeed.
- **No emulator or physical device.** `adb devices` lists none and the SDK has no `emulator`
  package. Every instrumented scenario below is therefore recorded as *not executed*, not as passed.

## Edge cases
- **Invalid manifest → regular browser mode.** `N/A — no change.` This ticket adds no validation
  path, no fetch, and no activation decision. `SKIN-004`'s publication-time origin and generation
  comparison is untouched.
- **Origin change / redirect.** `N/A — no change.` Security semantics are derived from
  `securityPresentation(BrowserMode)`, which already followed the committed origin. A deactivation
  removes the integrated chrome and the node with it; there is no cached description to go stale
  because nothing is cached.
- **Offline with cached manifest.** `N/A — no change.` The manifest cache is untouched.
- **Oversized or malformed payload.** `N/A — no change` to parsing. One relevant addition:
  `accessibleLabel` re-bounds label text at projection time, so even a label that somehow survived
  core normalization over-length cannot be spoken in full. Covered by scenario 13 with a control.
- **Accessibility (TalkBack, font scale).** This is the ticket. Covered by scenarios 1–16 in the
  JVM gate and 18–20 as instrumented evidence that **has not run**. Specifically **not verified**:
  the spoken output of a real screen reader. The semantics tree is asserted; how TalkBack renders
  it — in particular whether the security row's description plus its child `Text` nodes read as
  acceptably concise — has not been heard by anyone. Recorded as a known gap in
  `docs/accessibility/CONFORMANCE.md`.
- **Behaviour change users will notice.** Integrated chrome now follows the system dark theme. The
  projection was already computed and guarded since `SKIN-001`; only its selection changed.

## Result
Status: QA_PASSED
Notes: Every gate-enforced guarantee passes (109 app unit tests, 0 failures), both required negative
controls are load-bearing, and both `/review` findings are fixed.

**On scenarios 18–21.** They did not run: this environment has no emulator or device. That is worth
being precise about rather than burying, because `A11Y-001` is a ticket about on-screen behaviour.
It is nonetheless not a blocker, for a reason that is checkable: `.github/workflows/ci.yml` runs
`:siteskin-core:check`, `test`, and `:app:assembleDebug` and has **no instrumented job at all**.
Unexecuted `androidTest` is this repository's steady state for every ticket that has shipped, and it
is equally true of `main` today. Blocking here would apply a standard the project has never applied,
over an evidence gap this change did not create.

What that leaves genuinely unverified is recorded in `docs/accessibility/CONFORMANCE.md` under
*Known gaps*, and marked **Evidence** rather than **Gate** in every conformance table — the document
never claims a device-only assertion as a build guarantee.

Release action, not a merge blocker: run `./gradlew :app:connectedDebugAndroidTest` on API 26+ and
record scenarios 18–21. No code change is expected. `PLAY-001`'s compliance sweep is the natural
place for it, since a real TalkBack pass is needed there anyway.
