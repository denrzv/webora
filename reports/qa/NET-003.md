## Edge cases

- invalid manifest → N/A to asset transport; only validator-accepted configuration can call the
  loader, and existing manifest discovery remains regular browser mode on rejection.
- origin change / redirect → initial and every redirected asset URL compare complete canonical
  origins; a new navigation cancels the old coordinator job and stale output cannot publish.
- offline with cached manifest → an accepted cached configuration may request its exact-origin
  asset, but asset transport failure returns the trusted-name monogram; no asset cache is introduced.
- oversized or malformed payload → declared/streamed bytes, signatures, decoder type, axes, and
  pixel count are bounded before full decode; all failures use the monogram.
- accessibility (TalkBack, font scale) → no visible UI in this ticket. Later SiteSkin chrome owns a
  browser-derived description and bounded slot; remote metadata is not exposed for semantics.
- process restart → no asset state persists, by design.
- runtime instrumentation/screenshots → instrumentation compiles, but this managed checkout has no
  `/dev/kvm` or connected Android device. Per repository policy no software-only emulator was
  provisioned. No visible UI changed, so a screenshot is not applicable.
