## Navigation smoke

`LiveSiteNavigationSmokeTest` must pass after the showcase and must not publish screenshots. It checks:

- bounded user-equivalent scrolling to the deployed clickable `Happy Days` storefront link;
- Happy Days product navigation under integrated chrome;
- displayed/enabled browser-owned Back and Forward traversal;
- native SiteSkin action bouquet presence and action inventory;
- return to native Webora Home through browser-owned navigation;
- ordinary `example.com` browsing with regular chrome and complete SiteSkin teardown.

`LiveSiteHostedSuite` runs `LiveSiteScreenshotTest` first and `LiveSiteNavigationSmokeTest` second so
persisted consent from the visual story is an ordinary product state the smoke must tolerate.

## Automated evidence

- `ExpressiveBloomJourneyContractTest` pins the exact six-frame order, rejects the retired eight-frame
  artifact, requires Google/profile/action markers, requires the hosted suite order, and requires the
  smoke to retain product/Back/Forward/handoff markers while forbidding screenshot capture there.
- `evidence-sheet` JVM tests require six tiles, filename ordering, caption ink, total decode and no
  stale preview.
- `scripts/android-screenshot-ci.sh` runs `LiveSiteHostedSuite`; therefore a smoke failure keeps
  `test_status` non-zero even if all six visual frames were already collected.
- Normal repository CI/guardrails remain applicable. Android runtime acceptance cannot be replaced by
  source compilation or JVM checks.
