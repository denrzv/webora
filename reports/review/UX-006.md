# Review: UX-006
Date: 2026-08-13
Status: RESOLVED

## Summary

Reviewed the informed-consent projection and dialog against the approved plan, the browser/site
identity boundary, untrusted-text handling, decision semantics, accessibility conventions, and the
recorded test evidence. No corrective finding remains.

| Complexity | PASS — projection helpers and dialog composables remain focused, and Detekt is green. |

## Security

| Property | Assessment |
|---|---|
| Identity preservation | PASS — the canonical origin remains browser-authored in the dialog title; manifest text is separately attributed below it. |
| Untrusted text | PASS — title and subtitle are flattened, format/control characters are removed, and lengths use core constants before rendering. |
| Capability isolation | PASS — logo URLs, action payloads, item labels, and all pre-consent I/O are excluded from the model. |
| Honest preview | PASS — counts use the rendering caps, and a swatch appears only for a supplied brand colour using the guarded chrome projection. |

## Findings

None.

## Not findings

- The model accepts a trusted `SiteSkinConfiguration`. This does not make website strings safe to
  blend into browser identity; the additional display bound is intentional because `site.name` is
  not core-clamped and format characters remain meaningful in UI.
- The preview omits item labels and the brand logo. Labels would create a multi-line site-authored
  message immediately above Allow, while a logo would require a pre-consent request; counts and a
  guarded colour describe the change without granting either capability.
- The colour is a Compose `Color` in an app-layer model. The model is pure and JVM-testable but is
  deliberately not a core domain type; this presentation projection belongs to `:app`.
- Existing stored decisions do not show the revised sheet again. That follows ADR-011's per-origin
  persistence contract and is not a migration gap.
