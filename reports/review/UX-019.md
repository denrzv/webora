# Review: UX-019
Date: 2026-08-16
Status: RESOLVED

## Summary

Reviewed the integrated action/menu separation against the UX-019 PRD, SiteSkin trust boundary,
typed navigation dispatch, popup and bottom-sheet window ownership, lifecycle dismissal, compact
geometry, accessibility semantics, and regression coverage. Site-authored actions and browser-owned
commands now use independent state and presentation paths. No actionable findings remain.

## Architecture

| Concern | Assessment |
|---|---|
| State ownership | PASS — `BrowserScreen` owns separate `siteActionsExpanded` and `browserMenuVisible` flags and makes the surfaces mutually exclusive. |
| Site action projection | PASS — `actionBouquet()` applies deterministic navigation → quick-action → menu priority, de-duplicates by validated ID, and caps output at five typed items. |
| Browser menu ownership | PASS — `IntegratedBrowserMenuSheet` accepts only browser commands, favourite state, and browser callbacks; it cannot consume SiteSkin presentation or action models. |
| Dispatch ordering | PASS — both surfaces dismiss before invoking their typed action callback, preventing stale overlays during navigation or screen changes. |
| Lifecycle | PASS — tab, integration, page-start, Home, and session changes clear both menu states. |
| Complexity | PASS — projection, petal layout, menu tiles, and dispatch remain in small focused functions below the project complexity limit. |

## Security

| Property | Assessment |
|---|---|
| Trust separation | PASS — remote SiteSkin data can populate only the flower bouquet; the Webora sheet uses a fixed local command enum and Material theme. |
| Payload bounds | PASS — validated labels/icons are reused and the visible action surface is capped at five unique items. |
| Typed actions | PASS — petals retain the original validated `NavigationItem`; no URL or action is reconstructed from display text. |
| Browser controls | PASS — Back, Forward, Tabs, More, security indicator, and browser menu commands remain browser-owned. |
| Dismissal priority | PASS — focusable `Popup` and Material `ModalBottomSheet` consume Back/outside dismissal before browser history. |
| Accessibility | PASS — 52 dp petals, named actions, selected-state semantics, standard sheet controls, and 200% fixed-dock coverage are retained. |

## Findings

None.

## Not findings

- **The flower bouquet uses SiteSkin primary and secondary colours.** This is the intended
  site-authored surface; the colours have already passed SiteSkin validation. Browser commands are
  deliberately rendered in a separate neutral Material sheet.
- **Petal labels are exposed to accessibility but not drawn under the icons.** The requested compact
  bouquet is icon-first; every petal still has a bounded accessible name and navigation state.
- **`Page information` currently dismisses without opening a new screen.** This preserves the
  existing command behaviour and is outside UX-019; the menu separation does not invent a new page.
- **The action popup has a fixed 96 dp lift.** It is anchored to the fixed 60 dp dock, capped at five
  60 dp slots, and verified on the Pixel 6 emulator; remote data cannot change its geometry.
- **The brand identity test now reads the unmerged semantics tree.** Moving to a real Activity rule
  is required for system Back tests; the clickable hub correctly merges its decorative child in the
  public accessibility tree.
