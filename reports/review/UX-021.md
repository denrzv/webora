# Review: UX-021
Date: 2026-08-17
Status: CLOSED

## Summary

Two changes in one ticket, correctly sequenced: a browser-owned four-state transport model derived
from observed navigation (TASK-1), and the compact inline chip that replaces integrated chrome's
full-width security row (TASK-4). The ordering was the right call — the pre-existing
`origin.scheme == "https"` classification reported `SECURE` for a page whose certificate had been
rejected, and rendering that as a green shield would have made an existing inaccuracy emphatic.

The security core is sound. `SECURE` is reachable only from `BrowserObservation.MainFrameCompleted`
with an `https` origin and no recorded failure; every other route lands neutral; `PageStarted` clears
unconditionally so no gap in the observation surface can preserve stale green. Writes go through
`routeRendererEvent` with the event's own `tabId`, and `BROWSE-009`'s established negative control
now fails on transport cases while its discriminator still passes.

Three findings, none of them in the state machine. One is a duplicated mapping that the ticket's own
documentation claims not to have; one is a bound that can erode the `ADR-006` guarantee this ticket
deliberately chose to preserve, with a test too weak to notice; one is a stale test name.

## Findings

### FINDING-1 · Medium · duplicated mapping

**File:** `app/src/main/java/app/webora/browser/browser/BrowserChrome.kt:107` and
`app/src/main/java/app/webora/browser/siteskin/SiteSkinTopBar.kt:139`

The transport→string mapping is written twice, verbatim. `CLAUDE.md`'s own `UX-021` section claims
the shared strings mean "one guarantee cannot be worded two ways depending on which mode the user is
in" — but only the *strings* are shared. The *mapping* has two copies, so a future state added to
`TransportSecurity` produces two compile errors that can legitimately be resolved differently, and a
re-pointed branch in one file drifts silently from the other. This is exactly `UX-020`'s recorded
lesson about a mapping with two copies, arriving one ticket later.

The extraction already exists on one side: `transportLabel` was pulled out of the chip to satisfy
detekt's `LongMethod`. It is `private` and lives in the SiteSkin package, so regular chrome cannot
reach it.

Current (`SiteSkinTopBar.kt`, and duplicated in `BrowserChrome.kt`):
```kotlin
@Composable
private fun transportLabel(transport: TransportSecurity): String = stringResource(
    when (transport) {
        TransportSecurity.SECURE -> R.string.security_secure
        ...
    },
)
```

Fix: move it to the browser package beside `SecurityPresentation`, make it `internal`, and have both
chrome variants call it. One `when`, one owner, and a fifth state becomes exactly one compile error.

### FINDING-2 · Medium · bound erodes the guarantee it protects

**File:** `app/src/main/java/app/webora/browser/siteskin/SiteSkinTopBar.kt:212`

`SECURITY_CHIP_MAX_WIDTH` is 160 dp. Inside it the chip spends 16 dp of horizontal padding, a 16 dp
shield and a 4 dp gap, leaving ~124 dp for the domain. At 200% font scale the domain renders at an
effective 24 sp, where `example.co.uk` needs roughly 156 dp — so it ellipsizes to about
`example.c…`.

That matters more here than a truncation normally would. This ticket's central decision was to keep
the registrable domain *visible* rather than take issue #104's bare-shield layout, on the grounds
that a coloured glyph beside a manifest-supplied title and logo is not enough contradicting signal.
A domain truncated to a few characters at large font scale is closer to the layout that was
rejected than to the one that was chosen, and large font scale is precisely the accessibility
setting where a user is least able to scrutinise chrome.

The instrumented assertion cannot catch it: `assertTrue(identity.width > 0f)` passes on a chip
showing one character and an ellipsis.

Current:
```kotlin
private val SECURITY_CHIP_MAX_WIDTH = 160.dp
...
assertTrue("identity must have width at 200% font scale: $identity", identity.width > 0f)
```

Fix: raise the cap so a typical registrable domain survives 200% scale, and assert a real floor. The
title already carries `weight(1f)`, so a wider chip takes its width from manifest-supplied text —
which is the correct priority and needs no other layout change. The instrumented assertion should
require a meaningful minimum width rather than a non-zero one, so a future shrink fails a test
instead of quietly degrading the guarantee.

The residual limitation — a genuinely long domain still ellipsizes, and a single row is the wrong
layout at extreme scale — should be recorded rather than solved here; a responsive integrated header
is its own ticket.

### FINDING-3 · Low · stale test name

**File:** `app/src/androidTest/java/app/webora/browser/siteskin/SiteSkinTopBarTest.kt:76`

`compactLargeTextKeepsOwnedBrandIdentityAndBackSeparate` was named when identity was a separate row
below the brand. The body now asserts the opposite arrangement — identity inside the brand row,
bounded by the header. A name describing a layout the assertions no longer check is the kind of
thing a later reader trusts instead of reading.

## Not findings

- **`completedTransport` has no third scheme arm.** It looks like a missing allow-list branch. It is
  not: `SiteOrigin`'s constructor is private and `parse` refuses every scheme but `http`/`https`, so
  a non-HTTP(S) origin is unconstructible and arrives as the `null` row. An `ftp` test would pass
  through that null while appearing to exercise the scheme check — verified, and pinned by
  `a scheme outside the allow-list cannot reach the classifier at all`.

- **`BrowserSecurityIdentity` keeps `val secure = ... == TransportSecurity.SECURE` beside the
  exhaustive `when`.** It reads like a leftover of the two-valued enum. It is the icon selector, and
  it is correct precisely because only `SECURE` takes the lock: the other three share one glyph by
  design, per the issue's two-colour visible mapping. Making it a second exhaustive `when` would
  assert a three-way distinction the ticket's non-goals rule out.

- **`transportAcross` evaluates `mode.observedOrigin` twice.** A getter with a three-branch `when`,
  called once per page-change observation. Extracting it would read marginally better and changes no
  behaviour; not worth a commit against a hot path that is not hot.

- **`PageChanged` fires before `MainFrameCompleted` for the same navigation**, so a reader may worry
  the page-change branch clobbers the completion. It cannot: `onPageFinished` calls `onPageChanged`
  first and `onMainFrameCompleted` second, so the completion is the later write. Traced through the
  real callback order rather than assumed.

- **`securityChipSource()` extracts to end-of-file** because the chip is currently the last `private
  fun`. This looks fragile and is bounded in practice: the trailing region is tag and dimension
  constants, none of which contain a forbidden token, and a new `private fun` after the chip would
  shrink the window rather than widen it — the conservative direction for a scan that mostly
  forbids.

- **`ic_shield_unverified` covers three internal states with one glyph.** Deliberate. The issue's
  non-goals rule out a visible three- or four-way mapping, and the states stay distinct in the model
  for the later page-information surface.

- **The chip does not meet the 48 dp touch target.** It is a status indicator, not a control, so
  WCAG 2.5.8 does not apply. `SECURITY_SHIELD_SIZE` is deliberately a local constant and not a
  second name for `MINIMUM_TOUCH_TARGET`.

- **`LiveSiteScreenshotTest`'s identity assertion became a wait.** This is not weakening evidence.
  The node now legitimately reads `Not verified` for a moment before completion, so a point
  assertion would be racing; waiting for a state the app reaches unaided is `NET-004`'s rule, and
  the frame becomes stronger evidence because it can no longer be captured while the browser has
  confirmed nothing.

## Verdict

**Approve with three fixes.** The security model is correct and well evidenced, and no finding
touches it. FINDING-1 and FINDING-2 are both cases of the implementation being slightly weaker than
its own documentation claims — a mapping described as single-owner that has two copies, and a
visible-domain guarantee that a bound can erode where a test cannot see it. Both are small and both
should land before merge, because both are the kind of gap that reads as settled once the ticket
closes. FINDING-3 is cosmetic and rides along.

Instrumented assertions remain evidence, not gate claims; `CI-009`'s hosted acceptance is unaffected
and still pending on its own terms.

## Resolution (TASK-FIX-1..3)

**FINDING-1 — fixed as proposed.** `transportLabel` moved to `browser/TransportLabel.kt`, `internal`,
beside `SecurityPresentation`; both chrome variants call it. `BrowserChromeContractTest`'s
`the transport label mapping has one owner` asserts exactly one file maps the enum to resources, with
a negative control. Verified by reintroducing the duplicate into `BrowserChrome.kt`: the assertion
fails, then passes again on restore.

**FINDING-2 — symptom confirmed, proposed fix refuted, valuable half taken.** The truncation is real.
The cap is not what causes it, and raising it makes things worse. Measured:

| | chip content | cap | available | result |
|---|---|---|---|---|
| 100% scale | 117 dp | 160 | 164 | content-bound — the cap never binds |
| 200% scale | 198 dp | 160 | **164** | available-bound |

On a 320 dp host the brand row has 280 dp; Back, logo and three gaps take 116, leaving 164 dp for the
title *and* the chip. Raising the cap to 200 dp widens the chip from 160 to 164 and takes the title
from 4 dp to **0** — trading the site's name for roughly one more character of domain. So the cap was
left at 160 with the arithmetic recorded at its declaration, and the review's other half — that
`assertTrue(identity.width > 0f)` cannot tell a one-character chip from a healthy one — was taken:
the instrumented assertion is now `assertWidthIsAtLeast(140.dp)`.

The residual is a layout problem, not a constant: one row cannot hold Back, a logo, a manifest title
and a full domain at 200% scale. Filed as `UX-023` with the measurements.

**FINDING-3 — fixed.** `compactLargeTextKeepsOwnedBrandIdentityAndBackSeparate` →
`compactLargeTextKeepsBrowserIdentityInsideTheBrandRow`.

Full gate green; `:app:compileDebugAndroidTestKotlin` compiles. The instrumented floor is evidence,
not a gate claim — it has not run on a device from this checkout.
