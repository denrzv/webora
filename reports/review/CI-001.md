Date: 2026-08-11

## Summary

CI-001 adds a focused real-Activity instrumentation journey and a manual GitHub-hosted KVM emulator
workflow that retains full-device screenshots and failure diagnostics. Review covered the two task
commits `315772f` and `bd86b8d`.

## Architecture

| Concern | Assessment |
|---|---|
| Production boundary | No production source changed. The test drives Home, live discovery, consent and integrated mode through public UI semantics. |
| Module boundary | Instrumentation stays in `:app`; core gains no Android dependency. |
| Origin contract | Exact canonical consent text and browser-owned integrated tags gate evidence; fixture injection cannot counterfeit success. |
| CI scope | A separate manual-only workflow avoids slowing or destabilizing the required CI gate. |
| Diagnostics | Stable screenshot names, Gradle output, logcat, result summary and Android reports are uploaded with `always()`. |

## Findings

None.

## Not findings

- **The workflow uses a debug APK.** This is required for instrumentation and matches the existing
  demo distribution decision; it does not weaken the production SiteSkin implementation under test.
- **The live origin makes the test nondeterministic.** That is intentional: the requested evidence
  is how the integrated deployed site looks. Bounded waits and retained diagnostics distinguish this
  from a unit/conformance test.
- **`UiAutomation.takeScreenshot()` is used instead of Compose capture.** A full-display capture is
  necessary because WebView is a platform view and must appear in the evidence.
- **GitHub-owned actions use major tags.** The immutable-pin requirement is specifically applied to
  third-party workflow code; `ReactiveCircus/android-emulator-runner` is pinned to a commit.
- **Runtime was not executed in the managed checkout.** Repository policy forbids a software-only
  emulator here without `/dev/kvm`; the ticket's deliverable is the hosted KVM path.
