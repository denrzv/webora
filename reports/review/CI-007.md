## Findings

### FINDING-1 · Low · Localised browser-authored assertion
**File:** `app/src/androidTest/java/app/webora/browser/visual/LiveSiteScreenshotTest.kt`

Current:
```kotlin
string(R.string.security_identity, "Secure", REGULAR_DOMAIN)
```

The test hard-codes English browser copy even though the implementation composes the same identity
from `R.string.security_secure`. Hosted configuration is currently English, but duplicating copy
creates avoidable drift and weakens the claim that the assertion follows browser-owned resources.

Fix:
```kotlin
string(R.string.security_identity, string(R.string.security_secure), REGULAR_DOMAIN)
```

## Not findings

- `example.com` is a remote origin, but acceptance does not depend on its decoration or title. It is
  the IANA-reserved example destination already pinned by Webora's address-resolution test; rendered
  pixels only prove that some page content arrived.
- Returning through Back before address submission still exercises integrated-to-regular removal.
  The integrated layer is asserted immediately before the browser-owned escape, and every SiteSkin
  layer is required absent at the ordinary destination.
- The production composer and workflow do not hard-code four. Their dynamic totality is intentional;
  tests pin the current canonical inventory while production continues to compare actual counts.
- No screenshot mode or direct activity/controller state setup is needed. Waiting for naturally
  reached semantics does not alter what the app draws and can only time out/refuse more.
- Runtime instrumentation is not replaced by the compilation check. Hosted cold runs remain rollout
  evidence and cannot be claimed in a cloud checkout with no push-capable remote or device.
