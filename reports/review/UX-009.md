## Findings

### FINDING-1 · Medium · a second instrumented case that duplicated an existing one, and could have thrown

`TASK-2` added `consentDialogRendersTheCompleteHeadingWithinTheWindow`. Two problems, and the second
is what makes it worth a fix rather than a note.

**It asserted what the file already asserted.** `consentDialogNamesExactOriginAndBrowserOwnedBoundary`
already renders the dialog with `https://checkout.shop.example:8443` and matches the complete heading
string exactly. The PRD's criterion 5 was therefore *already satisfied before this ticket started*;
what was actually missing was the record that the assertion cannot detect clipping. A near-identical
second case adds a maintenance obligation and no coverage.

**And its added assertion was unsafe.** It read `compose.onRoot()`, and an `AlertDialog` composes
into its **own window**, so `isRoot()` matches two nodes — the empty host composition and the dialog.
`fetchSemanticsNode()` on a multi-match interaction throws. This session has no emulator, and the
screenshot job filters instrumentation to `LiveSiteScreenshotTest`, so nothing in reach would have
run it: a test that cannot be executed here and probably throws is worse than no test. The remaining
containment assertion was redundant anyway — `assertIsDisplayed()` already requires the node to lie
within its window.

Fixed: the case is deleted and its documentation moved onto the existing assertion, where it now
records that this file was green throughout the defect and names `WeboraThemeTest.a container role
never rounds a dialog into a stadium` as the gate.

### FINDING-2 · Low · a KDoc claiming something the code does not do

`DIALOG_SIZE`'s comment read "the narrowest and widest box Material lays an `AlertDialog` out in",
citing `DialogMinWidth` and `DialogMaxWidth`. But 560 is used as a **height**, not a width, and
`DialogMaxWidth` is a width. The number is fine — only the shorter side drives the clamp, so the
height merely has to exceed 280 — but a comment that misdescribes its own constant is how the next
reader "corrects" it to `Size(560f, 280f)` and silently makes the assertion measure the wrong side.

Fixed: the KDoc now says the width is the number that matters and why the height only has to exceed
it.

## Not findings

- **`999.dp` is still declared.** It is correct for the address field, the identity chip and the dock,
  which name it directly. Deleting it would have been the wrong fix to a problem about *who reads a
  shared default*.
- **The transcribed `280f`.** This repository distrusts transcribed constants (`DEMO-001`'s checksum
  rule) and `DialogMinWidth` is `internal` to material3, so it cannot be imported. It is safe here in
  one direction only, and the KDoc says which: corners are absolute and the clamp only shrinks, so
  clearing the ceiling at the narrowest width clears it at every larger one. A Compose release that
  narrows the minimum makes the assertion lenient, never wrong.
- **The ceiling is a quarter, not a half.** Half is the degenerate value — at half the width a side is
  already fully round — so the bound has to sit strictly inside it. 28 dp against 280 is a tenth and
  clears comfortably; the pill clamps to 140 and fails by a factor of two. There is deliberately no
  value between them that would tempt someone to raise the constant instead of fixing a shape.
- **`the pill is a control value…` looks redundant next to the geometry assertion.** It is not: the
  geometry one catches the consequence, this one names the cause, and a future pill on a role fails
  as itself rather than as a number that happens to be too big. The negative control failed both.
- **`Outline.Generic` throws rather than returning empty.** `RoundedCornerShape` never produces one,
  and an empty list would pass the assertion silently. Failing loudly is the correct branch for a
  case that cannot happen.
- **`HomeScreen.kt:102`'s fully-qualified `RoundedCornerShape` collapsed to the import.** Incidental
  to adding the import on line 11, zero behaviour change, and leaving one of two spellings in one
  file would be the odd choice.
- **The home address field's shape did change owner but not appearance.** It read
  `shapes.extraLarge` = 999 dp and now names `WeboraRadius.PILL` = 999 dp. Identical pixels; the
  point is that it no longer shares a default with every dialog in the app.

**The honest gap, stated rather than buried:** no test in this repository fails when a browser-owned
surface clips its own text. The geometry assertion catches *this* cause — an over-large container
radius — and would not catch a different one, such as a fixed height or a `Modifier.size` on a
scaled font. Closing that generally needs pixel comparison, which this repo does not have and which
`CI-003` established is the only layer where the question can be asked at all. The hosted frame
remains the check.
