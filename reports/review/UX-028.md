# Review: UX-028

Status: RESOLVED

Issue: [#130](https://github.com/denrzv/webora/issues/130)
Reviewed at `58f4713` on `claude/bloom-flowers-reference-y5ybs7`, based on `origin/main` `9fcb4aa`.

## Summary

A Copy JSON control on the inspector, a pure `inspectorJson(snapshot)` behind it, a six-shape JSON
writer under that, and one extended Gradle check. Six commits, all green through
`scripts/pre-commit-check.sh` and `:app:compileDebugAndroidTestKotlin`.

The load-bearing decision is not the serializer — it is **where the bounding lives**. The panel
applies `inspectorValue` at its fifteen render sites and `InspectorSnapshot` holds raw values, so the
obvious implementation reads the model's fields and exports strictly more than the surface it claims
to mirror. That is a widening of the export achieved without adding a field, and it is invisible in a
diff that only adds files.

## Architecture

| Concern | Assessment |
|---|---|
| Single source of truth | One `InspectorSnapshot`, two projections. Nothing new to keep in step; the drift risk is a *field* being added and not serialized, which the totality sweep covers reflectively. |
| Where the code lives | `src/debug/java`, beside the panel. The JVM gate reaches it (`SiteSkinChromeModelTest` already imports from that source set), and the release variants never compile it. |
| Dependency | None added. `kotlinx.serialization` stays an `implementation` dependency of `:siteskin-core`; a parser in every release artifact for a debug-only tool is the wrong trade. |
| Writer vs policy | Split. `JsonDocument.kt` is content-blind and can only fail at escaping or layout; `InspectorJson.kt` is the disclosure policy. One file doing both would let a test for either look like a test for both. |
| Determinism | A property of the type: `JsonObject` is an ordered `List<Pair<…>>`, not a `Map`. |
| Complexity | No detekt suppression, no baseline entry. Two test-side extractions (`acceptedRecord`, `appliedChrome`) rather than a `LongMethod` exemption. |

## Security

| Property | Assessment |
|---|---|
| Payload ceiling | The snapshot's, narrowed. Every string passes `bounded()`, the file's one `JsonString` construction site, applying the panel's own `inspectorValue`. |
| Untrusted text | The diagnostic pointer is arbitrary website text and arrives flattened and clamped at `MAX_SUBTITLE_LENGTH`; asserted by equality against `inspectorValue(hostile)`, not by a length ceiling. |
| Keys | Compiled literals only. No website value becomes a key, so a site cannot invent fields in a report a developer reads as the browser's. |
| Type closure | Reflective, over the reachable graph: numbers, booleans, strings, enums, lists, inspector records. A header `Map`, a `ByteArray`, a cookie or a DOM string cannot be added to the model without failing. |
| Cross-origin mixing | `inspectorJson` takes one parameter; the panel keys the document on the snapshot it renders; a scan forbids the recorder, `BrowserState`, `BrowserMode` and `.latest(` in the panel. |
| Egress | `ClipData.newPlainText` and nothing else. No share intent, no file, no socket, no automatic copy. |
| Release variants | Two independent mechanisms: source set, and compiled-output check now naming all three classes. |
| Escaping | `"`, `\`, the five short forms and every remaining sub-`U+0020` character. Second line of defence; `untrustedText` is the first. |

## Findings

### FINDING-1 · Medium · A second copy is silent to assistive technology
**File:** `app/src/debug/java/app/webora/browser/inspector/SiteSkinInspectorPanel.kt:57`

`copied` only ever goes `false → true`. A Compose live region announces when its content *changes*,
so the first tap announces and **every subsequent tap announces nothing** — while the clipboard is
genuinely replaced each time. The issue requires repeated taps to be safe *and* requires the
confirmation to be accessible; this satisfies the first and quietly drops the second on tap two.

A sighted user sees the same message and can reasonably infer it worked. A screen-reader user gets
silence, which is indistinguishable from a control that did nothing.

Current:
```kotlin
dismissButton = { InspectorCopyControl(snapshot) { copied = true } },
```

Fix: clear the flag when the write starts and set it when the write returns, so the node's content
changes on every tap. It also makes the panel honest while a write is in flight — the previous
`Copied` should not still be claimed for a copy that has not happened yet.

```kotlin
dismissButton = {
    InspectorCopyControl(snapshot, onCopyStarted = { copied = false }, onCopied = { copied = true })
},
```

### FINDING-2 · Low · The idle status region costs 8 dp of dialog height
**File:** `app/src/debug/java/app/webora/browser/inspector/SiteSkinInspectorPanel.kt:79`

`Arrangement.spacedBy(ROW_SPACING)` applies between children whatever their size, so the persistent
zero-height `Box` still pushes 8 dp under the heading before anything has been copied. The node must
stay persistent — that is `A11Y-001`'s rule and the reason it is a `Box` and not a conditional `Text`
— but the *spacing* need not be paid while there is nothing to space.

Fix: drop `spacedBy` from the title column and put the gap on the message itself, so the idle state
contributes exactly zero height and the persistent node is unchanged.

## Not findings

- **The document carries `record.origin` and `record.generation`, which the panel does not render.**
  That is deliberate and is what the issue asks for: *"complete payload, not a truncated preview"*.
  Both are in the diagnostic model already, both are browser-owned (a canonical origin the panel
  displays under another key, and a browser-incremented counter), and both are bounded like every
  other value. Copying only the currently-rendered subset would make the clipboard the truncated
  preview the issue explicitly forbids — the panel's row set is a layout decision, not a privacy one.

- **`diverged` is emitted although it is a computed `val` and not a field.** The totality sweep reads
  `declaredFields`, so it neither requires nor forbids it. It is included because a consumer reading a
  pasted document cannot derive "these two layers disagree" from two numbers without already knowing
  that is the question. `DEVX-001` records why the flag exists.

- **The absence check for `InspectorJson`/`JsonDocument` can only ever pass while the files are in
  `src/debug/java`.** The same was already true of `SiteSkinInspectorPanel`, and the value is the
  same: it catches a *future move*. `requiredClass` keeps the whole task from passing vacuously, and
  the negative control performed the move and watched it fail naming both classes.

- **The idle status `Box` publishes a node carrying only a `testTag`.** A `testTag` is not an
  accessible name and is not read aloud, so this is not `A11Y-001`'s nameless-node failure.
  `BrowserStatusRegion` has exactly this shape for exactly this reason.

- **The copy control sits in `AlertDialog`'s `dismissButton` slot without dismissing anything.** That
  slot is Material's name for the leading action, not a behavioural contract; `onDismissRequest` is
  still `onClose` and the copy path is asserted not to reach a dismissal callback at all.

- **Enum names go through `bounded()`, where the walk is a no-op.** That is the point: the rule
  "every string passes one bound" is enforceable only while it has no exceptions, and an exception for
  compiled identifiers is a second construction site with a justification attached.

**Two controls exposed defects in the tests themselves**, which is the outcome to want from a control:

- `Regex("\bremember\(")` matched a *wrongly keyed* remember and walked straight past an **unkeyed**
  one — the likelier mistake, and the exact shape of the issue's tab-change requirement. Now
  `\bremember\s*[({]`, which still misses `rememberCoroutineScope()`.
- The dismissal control did not compile at first: adding `onClose` as the last parameter re-binds the
  call site's trailing lambda. `UX-024`'s trap — a control that fails to compile reads exactly like a
  control that bit nothing.

## Verdict

Two findings, one of them a real accessibility regression against the issue's own requirement.
**`TASK-FIX-1` addressed both and is committed**; the rest of the change stands.

The fix carries its own paired rule rather than one merged assertion: `the confirmation is cleared
before the write` beside `confirmation follows the clipboard write`. Either alone is satisfiable by a
defect — the first by a confirmation that fires before the write, the second by a latch that never
resets — and the control proves they are two, failing the new rule alone while the old one stays
green.
