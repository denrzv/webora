# Review: NET-003

Date: 2026-08-09
Status: RESOLVED

## Summary

Reviewed the brand asset transport, format policy, Android decode seam, fallback loader,
coordinator lifecycle, and tests against the PRD, approved plan, specification, ADR-004, ADR-006,
and project rules. No blocking, major, or minor findings remain.

## Architecture

| Concern | Assessment |
|---|---|
| Module boundary | PASS — Android bitmap decoding and OkHttp remain in `:app`; core stays platform-free. |
| Trust pipeline | PASS — trusted configuration enters the pipeline, while response metadata and bytes remain untrusted through transport, signature, probe, and dimension checks. |
| UI boundary | PASS — the result is closed bitmap/monogram data and exposes no URL or general-purpose loader to later UI. |
| Lifecycle | PASS — one coordinator job owns each request, socket cancellation is propagated, and an active-job check suppresses stale publication. |
| Complexity | PASS — Detekt passes without a baseline change. |

## Security

| Property | Assessment |
|---|---|
| Origin isolation | PASS — initial and redirected URLs compare full canonical origins; distinct ports and subdomains reject. |
| Format allow-list | PASS — transport accepts only PNG/WebP declarations and the loader requires matching magic and decoder-reported type; SVG cannot reach full decode. |
| Resource bounds | PASS — declared and streamed input are capped at 512 KiB; bounds-only decode precedes full allocation and enforces axes and `Long` pixel count. |
| Failure behavior | PASS — every non-cancellation failure resolves to a deterministic trusted-name monogram; cancellation publishes nothing. |
| Data exposure | PASS — no asset URL, origin, body, MIME value, or bitmap content is logged or persisted. |

## Findings

None.

## Not findings

- **The pipeline is not wired into visible chrome.** Applying accepted SiteSkin configuration and
  rendering the bounded logo slot belong to `SKIN-002`/`SKIN-004`; NET-003 supplies the safe callable
  capability without prematurely activating website-controlled chrome.
- **Coil is not used despite already being a dependency.** A general image loader has redirect,
  decoder, and cache policies broader than the v1 contract; the narrow owned pipeline is deliberate.
- **A PNG `Content-Type` with parameters is accepted.** HTTP media-type parameters do not change
  the normalized type; signature and decoder agreement still enforce the bytes.
- **Cancellation does not return a monogram.** Cancellation means the navigation no longer owns an
  output. Publishing even a fallback from it could overwrite the current navigation.
- **No asset cache is added.** Persistence and cache identity were explicitly out of scope; bounded
  safe loading is complete without retaining browsing-derived images.
