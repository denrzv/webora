# Review: NET-001

Status: RESOLVED

## Summary

The fetcher correctly fixes the discovery path, rejects non-HTTPS input, disables automatic redirects, binds redirects to canonical exact origin, limits redirects and bytes, and silently falls back. The coordinator keeps validation in core and prevents stale outcomes. One lifecycle issue must be fixed before QA.

## Architecture

The module boundary is preserved: OkHttp remains in `:app`; core constants, canonical origins, `ManifestSource`, and `SiteSkinValidator` remain authoritative. Discovery is triggered from the main-frame page-start observation and its result is intentionally inert until later M3 tickets.

## Security

Exact-origin checks include scheme, canonical host, and effective port. Declared and streamed sizes are bounded. No remote body or URL is logged. Validation remains total and only accepted outcomes expose trusted configuration.

## Findings

### FINDING-1 · Medium · transport cancellation does not cancel the OkHttp call

`ManifestDiscoveryCoordinator` cancels a superseded coroutine, but `OkHttpManifestSource` uses blocking `Call.execute()` inside `withContext(Dispatchers.IO)`. Coroutine cancellation therefore suppresses the stale callback but does not stop the socket or release network work promptly. Use cancellable OkHttp enqueue/await plumbing that calls `Call.cancel()` on coroutine cancellation, and add a negative-control test.

### FINDING-2 · Low · duplicated assertion

The canonical-origin validation test repeats the same `Available` assertion and does not inspect anything additional. Remove the duplicate.

## Not findings

- The result callback is empty in `BrowserScreen` intentionally: applying chrome, consent, caching, and mode transitions are later tickets.
- The transport test rewrites HTTPS requests to a local HTTP MockWebServer in a test-only interceptor because Android local JVM tests have no functional platform TLS implementation without Robolectric; production policy still receives and checks HTTPS URLs.
- A missing/invalid manifest and transport failure share `Unavailable` intentionally because regular-mode fallback is identical and remote error detail must not reach UI.

## Test coverage

Focused tests cover fixed path, HTTP rejection, exact-origin redirect policy, redirect cap, status, declared/actual oversize, timeout, canonicalization, validation rejection, non-blocking dispatch, and stale result suppression.

## Verdict

Both findings were resolved in `TASK-FIX-1`; cancellable OkHttp awaiting now cancels the call and the duplicate assertion was removed. The change is ready for QA.
