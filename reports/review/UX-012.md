# Review: UX-012
Date: 2026-08-15
Status: RESOLVED

## Summary

The implementation centralises Home/regular/integrated layer ownership in an exhaustive pure
projection, makes the selected tab the only projection source, and removes the transient cross-origin
brand risk by associating loaded assets with configuration identity. The existing exact-origin,
consent, action-resolution, security identity, and system-Back boundaries remain intact. No review
findings require a fix task.

## Architecture

| Concern | Assessment |
|---|---|
| Single authority | PASS — `ChromeHandoff` projects every closed `BrowserMode` into one top/action/bottom layer set. |
| Rendering | PASS — `RegularBrowser` consumes the projection rather than repeating independent integrated checks for each chrome layer. |
| Session isolation | PASS — `BrowserSession.chromeHandoff()` reads only `activeTab`; inactive configurations cannot project visible chrome. |
| Async presentation | PASS — assets are matched by trusted configuration identity, with an immediate active-origin monogram fallback. |
| Scope | PASS — no changes to manifest validation, consent persistence, navigation resolution, WebView, or Android system navigation. |

## Security

| Property | Assessment |
|---|---|
| Origin binding | PASS — `BrowserState.observe` still drops integration synchronously unless the observed complete origin matches. |
| Browser identity/escape | PASS — integrated identity and Back are one browser-owned `PROTECTED_INTEGRATED` top variant. |
| Manifest isolation | PASS — the projection imports neither `SiteSkinConfiguration` nor `NavigationItem`; trusted configuration only populates already-authorised site layers. |
| Tab isolation | PASS — selected state drives the projection, and stale assets are rejected by configuration identity. |
| Native capability | PASS — no URI, intent, bridge, permission, scheme, or generic action surface was added. |
| Negative controls | PASS — tests deliberately compare against stale-tab projection and reject manifest types in the handoff contract. |

## Findings

None.

## Not findings

- `BrowserScreen` still has a top-level Home/content branch because Home has no WebView. This is
  surface composition, not a second chrome-authority model; Home and the page renderer both consume
  the browser-owned bottom contract appropriate to their projected mode.
- Integrated bottom navigation replacing `BrowserNavigationShell` is intentional. The browser escape
  and security identity remain in the fixed integrated top layer; showing both bottom systems would
  violate the one-slot product-navigation model.
- Falling back to a monogram when an integrated asset is absent is not website-controlled activation.
  The configuration is already trusted and active; the browser derives and bounds the fallback.
- A structural source-contract test complements behaviour tests deliberately. It is the negative
  control proving future API changes cannot quietly add manifest models to the authority seam.
- There is no handoff animation. Animation is explicitly out of scope; deterministic layer ownership
  precedes optional transition polish.
