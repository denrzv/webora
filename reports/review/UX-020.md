# Review: UX-020
Date: 2026-08-17
Status: CLOSED

## Summary

`TabSwitcher` moves from a 280 dp `AlertDialog` of stacked filled buttons to the full-window
`Dialog` + opaque `Surface` structure `UX-018` established, with tonal selectable rows, a sibling
icon close control and one primary action. The pure model, both callback signatures, the four tag
constants and `BrowserScreen`'s adapter are unchanged, so the blast radius is one file plus one
string.

The load-bearing decision is the selected-state colour pair, and the ticket got it right for a reason
that is documented, tested and reproduced by a negative control: the obvious
`surfaceVariant`/`primaryContainer` pairing is invisible in the dark projection. Two defects were
found in the review below, both in the *test* rather than the surface, and both of the kind this
repository has recorded before — an assertion that reads as stronger than it is.

## Architecture

| Concern | Assessment |
|---|---|

| Model/presentation split | `BrowserTabSummary`, `tabSummaries` and `browserLabel` are byte-identical. Only presentation moved. |
| Callback seam | `onSelect`/`onCloseTab`/`onNewTab`/`onDismiss` unchanged in name, arity and type; `BrowserTabSwitcher` in `BrowserScreen.kt` needed no edit. |
| Dialog/content split | `TabSwitcher` (window) / `TabSwitcherContent` (body) mirrors `PrivacySettingsDialog` / `PrivacySettingsScreen`, so instrumentation can ask the two questions separately. |
| Inset ownership | The dialog reads `safeDrawing` inside its own window; `BrowserScreen` keeps its single read. `Home and regular mode share one shell inside one safe drawing boundary` still asserts `countSubstring(...) == 1` and passes. |
| Complexity | `TabRow` was 49 lines and detekt's `LongMethod` caught it; the visible identity split out as `TabIdentity`, which is also where the labelling boundary is documented. |
| Modal vocabulary | `AlertDialog` is deliberately retained for the four short confirmations. A sentence and two decisions is not the same shape as a list of eight with a per-item destructive action. |

| Property | Assessment |
|---|---|

## Findings

### FINDING-1 · Medium · the colour assertion does not read the mapping the surface reads
**File:** `app/src/test/java/app/webora/browser/browser/TabSwitcherContractTest.kt:160`

The four helpers are introduced as "the four role reads `TabRow` performs, named once so the test and
the surface cannot drift". They are not. The test names **Webora** roles; the surface names
**Material** roles; `materialColorScheme` is the mapping between them and is not in the loop.

Current:
```kotlin
/** The four role reads `TabRow` performs, named once so the test and the surface cannot drift. */
private fun WeboraColorScheme.selectedContainer(): Color = primary
private fun WeboraColorScheme.unselectedContainer(): Color = chrome
```

`TabRow` reads `scheme.primary` and `scheme.surfaceVariant` off `MaterialTheme.colorScheme`. Today
`materialColorScheme` maps `surfaceVariant ← chrome`, so the two agree by coincidence of that
mapping, and nothing in the test consults it. That is the same defect class as the
`WeboraIconButton` KDoc that exempted its own file: a comment asserting a property the code does not
have.

**Correction, made while verifying the fix.** This finding was first written with the wrong
illustration — re-pointing `surfaceVariant` at `container`. Run as a control, that does **not**
collapse the row pair and the test correctly stayed green: the selected role is `primary`, a
saturated accent that differs from both `chrome` and `container` in both projections. The real
drift is a remap of Material's *own* role — `primary = scheme.chrome` in `materialColorScheme` — which
makes selected and unselected identical in both projections. Both directions were then run: the
fixed helpers fail on it, the original helpers pass. The finding stands and the fix is proven
necessary; only the example was wrong.

Fix: assert through `materialColorScheme(...)`, so the test performs the surface's reads.
```kotlin
private fun WeboraColorScheme.selectedContainer(): Color = materialColorScheme(this).primary
private fun WeboraColorScheme.unselectedContainer(): Color = materialColorScheme(this).surfaceVariant
```

### FINDING-2 · Low · two of the four tag assertions are satisfied by the declaration
**File:** `app/src/test/java/app/webora/browser/browser/TabSwitcherContractTest.kt:123`

`the instrumented tag contract survives the restyle` checks `source.contains(tag)` for the two
interpolated tags. `BrowserTabSummary.kt` declares `TAB_SELECT_TAG = "select_tab_"` in that same
file, so the substring is present whether or not the tag is ever *applied* to a node. The test would
pass over a switcher that had dropped both row tags entirely.

`isTonalSelectAffordance` does check application for the select tag, so nothing is currently
unguarded — but a check that cannot fail is the thing `DEVX-002`'s `tiles=0` rule and this file's own
counter-examples exist to prevent. Assert the interpolated *application* form.

## Not findings

- **`Close` sits below eight rows at 200% font scale.** Reaching it means scrolling. Accepted: Android
  Back dismisses, is pinned by `systemBackDismissesTheSwitcher`, and is the same trade
  `PrivacySettingsScreen` already makes. Hoisting the dismiss into a top bar would be a second modal
  shape, which is what this ticket is removing.
- **Full-window for a two-tab list is more chrome than the content needs.** Deliberate. One modal
  language across the two list surfaces is worth more than fitting each one, and it is the trade
  `UX-018` already made for a settings screen that is often a single toggle.
- **The row carries both a merged `text` and a `contentDescription`.** Intended. The description is
  the accessibility sentence the visible label no longer duplicates; `contentDescription` takes
  precedence in the node Compose publishes, and `onNodeWithText` still resolves the label for tests.
- **`no website-controlled value reaches the switcher` would fail on a KDoc that merely names one of
  the forbidden types.** True, and fail-safe in this direction — the inverse of the `UX-002` hole,
  where a mention granted an exemption. A future comment needing one of those words should be
  reworded, not the scan weakened.
- **The select surface applies `browserTouchTarget()` after `weight(1f)`.** `sizeIn` sets minimums;
  the parent's weight allocation is at or above 48 dp in every layout this surface reaches, and the
  minimum height is the axis that matters.
- **Negative control 3 failed to compile on the first attempt.** Not a gap: `WeboraButton` has no
  `shape`/`color`/`contentColor`, so the type system rejects that regression before the test can. The
  control was rewritten to a compilable filled row specifically so the *test's* catch was proven, and
  both facts are in the tasklist.
- **`tabs_title` still reads `Tabs: 3 of 8` as a headline.** Unchanged copy, unchanged string, and it
  carries the count the old dialog title carried. Rewording it is a copy decision outside this ticket.

## Verdict

**Resolved.** Two findings, both in the test layer, both the same kind of overclaim and both fixed in
`TASK-FIX-1`. The surface itself is sound and the security boundary is unmoved.

The verification of FINDING-1 refuted the example the finding was written with — the named palette
edit does not collapse the pair — and the correct one was found and run in both directions before the
fix was accepted. Recorded above rather than quietly rewritten: a review that cannot be wrong about
its own reasoning is not evidence either.
