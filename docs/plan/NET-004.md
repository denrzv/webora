# NET-004: Implementation plan
Status: PLAN_APPROVED

## Overview

The ticket is a diagnosis before it is a fix, and the diagnosis is blocked on an instrument that does
not exist. So the work is ordered: build the channel, take the measurement on a real device, then fix
what the measurement convicts.

Three things ship regardless of what the evidence says, because the backlog entry requires them
either way — "if the asset is legitimately refused, the inspector says so in one line and the reason
is recorded":

1. A typed refusal vocabulary for the brand-asset transport, mirroring `FetchRejection`.
2. A closed `BrandAssetOutcome` from the loader, so the seven refusals that currently collapse into
   one `Monogram` each name their stage.
3. That outcome in the trace and on one inspector line, and — because nobody is watching a panel
   inside a CI emulator — in the screenshot job's diagnostics artifact.

The fix itself is deliberately unplanned in its details. Four candidates remain live and the ticket
is only allowed to fix what the evidence convicts; `TASK-5` is where that evidence is read and
`TASK-6` is where it is acted on.

## Flow

- **discovery** — unchanged. `ManifestDiscoveryCoordinator` still emits its own trace.
- **activation** — unchanged. `candidateDisposition` → `activateSiteSkin` → `BrowserMode.Integrated`.
- **asset load** — `LaunchedEffect(integrated?.configuration)` seeds a monogram, calls
  `BrandAssetLoader.load`, and now receives `BrandAssetOutcome(asset, trace)` instead of a bare
  `BrandAsset`. The publication guard is unchanged in behaviour but extracted so it can be tested.
  The trace is forwarded to a sink; the asset is published exactly as before.
- **UI state** — `SiteSkinTopBar` receives the same `BrandAsset` it receives today. No composable
  learns about a reason.
- **inspection** — the panel gains one row. The trace is what the instrumentation reads.

## Data

**Trust boundary.** A website chooses whether a reason is *selected*; it cannot supply, extend or
phrase one. Both new types are closed enums with no `String` member. The two values that do originate
remotely — an HTTP status and the decoded pixel dimensions — are integers, so neither can carry text.
No URL, header value or server message becomes display text; the existing `inspectorValue` bound
still applies to anything that would.

```kotlin
internal enum class BrandAssetRejection {   // beside BrandAssetFetchResult
    NOT_HTTPS, MALFORMED_URL, CROSS_ORIGIN,
    HTTP_ERROR, REDIRECT_LIMIT, CROSS_ORIGIN_REDIRECT,
    UNSUPPORTED_MEDIA_TYPE, OVERSIZED,
}

internal enum class BrandAssetStage {       // what produced the published asset
    DECODED, NOT_DECLARED,
    TRANSPORT_REJECTED, TRANSPORT_UNAVAILABLE,
    SIGNATURE_MISMATCH, BOUNDS_UNREADABLE, BOUNDS_REFUSED,
    DECODE_FAILED, UNEXPECTED_ERROR,
}

internal data class BrandAssetTrace(
    val stage: BrandAssetStage,
    val rejection: BrandAssetRejection? = null,
    val httpStatus: Int? = null,
    val redirects: Int = 0,
    val width: Int? = null,
    val height: Int? = null,
    val elapsedMillis: Long = 0,
)

internal data class BrandAssetOutcome(val asset: BrandAsset, val trace: BrandAssetTrace)
```

`TRANSPORT_UNAVAILABLE` stays separate from `TRANSPORT_REJECTED` for the reason
`ManifestFetchResult` already documents: "no answer" and "the server answered and the browser refused
the answer" are identical to a user and are the whole diagnosis to a site owner.

`elapsedMillis` is here because it is the only field that can distinguish a systematically-losing
race from a deterministic refusal — the open question the research note could not close.

**Storage.** `SiteSkinTraceRecorder` gains a second bounded map keyed by the same full canonical
origin, evicted least-recently-recorded by the same helper the manifest map uses. No persistence, no
logging, no transmission; `BrowsingDataCleaner`'s existing `clear()` covers it because it clears the
recorder.

The reason has exactly one storage location. The inspector reads it from the record, the way it
already reads transport and validation, rather than from a second copy threaded through
`InspectorBrowserState`.

## Security

- **Origin binding** — untouched. Core's `SS-E-ASSET-CROSS-ORIGIN` check and
  `OkHttpBrandAssetSource`'s two independent `SiteOrigin` comparisons (initial URL, each redirect
  target) keep their exact conditions. Only the value returned on failure changes: `Rejected` becomes
  `Rejected(reason)`.
- **Allow-lists** — `BrandImageFormat` (PNG/WebP), the signature check, `BrandAssetLimits`
  (512 KiB / 1024 px per axis / 1,048,576 px) are unchanged. `NET-003`'s existing tests are not
  edited; they are the proof.
- **Fallback on failure** — every non-`DECODED` stage still publishes a monogram, and
  `CancellationException` still propagates rather than becoming a result.
- **Decorative logo** — `BrandLogo`'s `clearAndSetSemantics { }` is untouched. The outcome must not
  become an accessibility-visible property of the slot (`HARDEN-002`); the instrumentation reads the
  recorder, not the semantics tree, precisely so it never needs to be.
- **Release variants** — `inspectorRecorder()` still folds to `null` through
  `SITESKIN_INSPECTOR_AVAILABLE`, so no release build constructs a recorder or a trace.
  `assertInspectorAbsentFromReleaseVariants` continues to check compiled output.

## The one seam that changes shape, and why

`inspectorRecorder()` currently runs inside `remember { }`, so the recorder is **per-composition**
while its own KDoc calls it "a bounded, process-lifetime, in-memory store". Today that means a
configuration change discards every trace a developer was reading, and it means instrumentation
cannot read what the running browser decided.

It becomes a process-scoped instance in the debug variant, matching the documentation that was
already written for it. This is what closes research open question 3: the journey reads *the app's
own outcome*, not a second copy produced by a second loader that is free to disagree with it.

Release variants are unaffected — the constant folds the whole thing out at compile time.

## Harness

`LiveSiteScreenshotTest`, between Allow and frame 03:

1. Wait, bounded, until the brand-asset trace for `https://denrzv.github.io` exists — that is, until
   the pipeline has *decided*. Absence of a trace is "still loading"; it is not a state the harness
   creates or influences.
2. Record `brand-asset-03-siteskin-integrated.txt` into the diagnostics directory with stage,
   rejection, status, redirects, dimensions and elapsed time — on success as well as failure, per
   `CI-003`'s rule that a passing check recording nothing cannot be told from one that barely passed
   for the wrong reason. A wait that times out records `NEVER DECIDED` and the elapsed budget.
3. Capture the frame, unchanged, through `requireAppOwnsScreen` → `captureWhenRendered`.
4. **Then** assert the stage is `DECODED`.

The order is deliberate. The frame is captured before the assertion so a failing run still publishes
the picture that shows what went wrong; asserting first would destroy the evidence the assertion is
about.

Three constraints this respects:

- **Nothing is arranged for the camera.** `DEVX-003` refused a screenshot mode; this waits for a
  state the app reaches on its own and changes nothing about what is drawn.
- **It can only make the harness refuse more** (`CI-005`). A frame that passes today with a monogram
  fails after this change; no frame that fails today can start passing.
- **The assertion couples the job to a third-party host** — and adds no coupling that is not already
  there. Frame 02 waits on a consent dialog that only appears if `denrzv.github.io` served a valid
  manifest, so the journey already fails when that host does.

No workflow or `scripts/android-screenshot-ci.sh` change: the probe lives in the journey class the
instrumentation filter already selects. That closes research open question 2, and the cost of the
alternative — teaching `SCREENSHOT_TEST_CLASS` to hold a list — buys nothing here.

## File-by-file plan

### Modified: `app/src/main/java/app/webora/browser/siteskin/OkHttpBrandAssetSource.kt`
`BrandAssetFetchResult.Rejected` becomes a `data class` carrying `reason: BrandAssetRejection`,
`httpStatus: Int?` and `redirects: Int`; `Fetched` gains `httpStatus`/`redirects`. Each of the five
existing `return Rejected` sites names its reason. Conditions are not touched.

### Modified: `app/src/main/java/app/webora/browser/siteskin/BrandAssetLoader.kt`
`load` returns `BrandAssetOutcome`. Each refusal path names its `BrandAssetStage` instead of falling
into a shared `?: fallback`. Timing wraps the whole load.

### Modified: `app/src/main/java/app/webora/browser/inspector/SiteSkinTrace.kt`
Hosts `BrandAssetTrace` beside the manifest traces, with the KDoc that says what it is for.

### Modified: `app/src/main/java/app/webora/browser/inspector/SiteSkinTraceRecorder.kt`
A second bounded map and `recordBrandAsset` / `latestBrandAsset`, sharing one eviction helper with
the existing map. `clear()` clears both. `version` increments for both.

### Modified: `app/src/main/java/app/webora/browser/inspector/InspectorState.kt`
`inspectorRecorder()` returns the process-scoped instance.

### Modified: `app/src/main/java/app/webora/browser/inspector/InspectorSnapshot.kt`
`InspectorSnapshot` gains `brandAssetTrace: BrandAssetTrace?`, assembled from the recorder.

### Modified: `app/src/debug/java/app/webora/browser/inspector/SiteSkinInspectorPanel.kt`
One additional row beside the existing `Brand asset` row: the stage, and the rejection when there is
one. Browser-authored label as its own `Text` node, per the file's own convention.

### Modified: `app/src/main/res/values/strings.xml`
Labels for the new rows. Required by `BrowserSurfaceConventionsTest`'s no-literal rule.

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`
The effect consumes `BrandAssetOutcome`, publishes `outcome.asset` under the existing guard, and
forwards `outcome.trace` to the recorder. The guard itself moves into a named pure function.

### New: `app/src/main/java/app/webora/browser/siteskin/BrandAssetPublication.kt`
`publishesBrandAsset(mode, configuration): Boolean` — the `===` identity guard that `NET-003`'s
"superseded work cannot publish" rests on, as a pure function a JVM test can drive. It is the repo's
standard thin-wrapper-over-pure-function shape, applied to a guard that currently runs only inside a
composable.

### Deleted: `app/src/main/java/app/webora/browser/siteskin/BrandAssetCoordinator.kt` and its test
Dead since `SKIN-004`: referenced only by its own test, while `BrowserScreen` reimplements it inline.
A tested class that runs nowhere beside an untested path that runs everywhere is the wrong way round,
and the guard it existed to hold is preserved above as a tested pure function.

### Modified: `app/src/androidTest/.../visual/LiveSiteScreenshotTest.kt`
The wait, the record and the post-capture assertion described above.

### Modified: `app/src/androidTest/.../visual/ScreenEvidenceGuard.kt`
Only if `record` needs to be reachable from the journey; otherwise untouched.

## Tests

| Test | What it pins |
|---|---|
| `OkHttpBrandAssetSourceTest` (extended) | Each rejection reason for its own MockWebServer case. **Negative control:** collapse two reasons to one value and the new assertions fail. |
| `BrandAssetLoaderTest` (extended) | Seven refusals produce seven distinct stages. Today every one asserts `Monogram("B")` — the assertions are the control: before the change they cannot distinguish any two. |
| `BrandAssetLoaderTest` (unchanged assertions) | The published `BrandAsset` is byte-for-byte what it is today for every case, and cancellation still propagates. |
| `SiteSkinTraceNeutralityTest` (extended) | The published asset is identical with the recorder and with a discarding sink, across the whole refusal matrix, with a guard that the matrix is non-trivial. `DEVX-001`'s shape, applied one pipeline over. |
| `BrandAssetPublicationTest` (new) | A superseded configuration does not publish; the current one does. **Negative control:** relax `===` to `==` and the superseded case still fails; drop the guard entirely and it passes when it must not. |
| `SiteSkinTraceRecorderTest` (extended) | Brand-asset traces are bounded and evicted like manifest records, and `clear()` empties both. |
| `InspectorSnapshotTest` (extended) | The stage and rejection reach the snapshot; absence renders as absent rather than as a blank. |
| `:app:assertInspectorAbsentFromReleaseVariants` | Unchanged, and still passing. |
| `:app:assembleDebugAndroidTest` | Run by hand for every androidTest edit — `scripts/pre-commit-check.sh` never compiles that source set, which is how a compile error once survived a green gate. |

## Rollout / versioning

No manifest, schema, spec, fixture or diagnostic-code change. `spec/` is untouched, so none of the
five pinned copies of the reference manifest moves and no checksum needs recomputing.

Evidence is taken from `workflow_dispatch` runs of `Android screenshots` on the ticket branch. Every
claim cites run number and commit SHA, because `DEVX-002` records that a stale artifact looks exactly
like a current one.

## Open questions

1. **Which candidate holds.** Decided by `TASK-5`, not here.
2. Whether the fix in `TASK-6` is in the app or the harness. The plan deliberately does not choose:
   the whole point of `TASK-1`–`TASK-4` is that this stops being a choice.
