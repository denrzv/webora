# UX-001: Implementation plan
Status: PLAN_APPROVED

## Overview
Write one decision document and update two pointers to it. No code.

## Flow
No runtime flow. The document's job is to be the input `UX-002` and `UX-003` read instead of
reopening the appearance question.

## Data
No data, no storage, no trust boundary moved. The ADR *records* a boundary that already exists:
`SiteSkinColorScheme` stays the entire website-influenceable colour surface, and the browser's own
tokens will be compiled with no path from a manifest value into them.

## Security
The ADR is the artifact that keeps `ADR-006` enforceable through a visual rebuild, so its security
section is the part that has to be exact rather than descriptive:

- The selected direction's identity text comes from `securityPresentation(state.mode)`, derived from
  the committed `SiteOrigin` — never `state.addressText`, never document content, never a manifest
  field.
- The browser-authored semantics node carrying `BROWSER_SECURITY_TAG` survives the rebuild. It is
  half the guarantee; assistive technology reads the tree, not the pixels.
- **The violation is named, not implied:** display state and edit state are two states, and dropping
  the second — leaving the domain inside the editable field — violates `ADR-006` however it looks.
