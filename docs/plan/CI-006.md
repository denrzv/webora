# CI-006: Implementation plan
Status: PLAN_APPROVED

## Overview
Extend the existing repeated readiness gate with aggregate Android CPU-idle sampling. A sample counts
toward readiness only when all current signals pass and the interval since the previous valid CPU
counter sample is at or below a conservative busy-percentage threshold. Every observation remains in
the readiness artifact.
## Flow
- Read `/proc/stat`'s aggregate `cpu` row once per existing readiness-loop sample.
- Parse monotonically increasing total and idle counters; the first valid row establishes a baseline.
- Compute interval busy percent using integer counters and classify it with the four existing signals.
- Reset the consecutive-ready count on busy or invalid observations; succeed only after the existing
  number of consecutive quiet samples, or fail at the existing deadline.
## Data
- CPU input is untrusted shell text. Parsing accepts only the aggregate `cpu` row's numeric fields and
  returns explicit diagnostic tokens for absent, malformed, zero-delta, or reset observations.
- State is process-local previous counters only. Nothing is persisted except bounded text diagnostics.
## Security
- Origin binding is unchanged: the gate runs before remote content and cannot see manifest values.
- The quiet threshold is browser-owned configuration, not an environment or website input in hosted
  workflow YAML.
- Observation failure rejects the sample. It never triggers dialog dismissal or changes capture
  acceptance.
