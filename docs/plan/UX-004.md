# UX-004: Implementation plan
Status: PLAN_APPROVED

## Flow
The existing `MainActivity`/`BrowserScreen` routing stays unchanged. This ticket only replaces presentation inside the three existing composables. Each composable continues to receive typed state and callbacks from its current owner.

Home keeps a saveable address entry and resolves it only on IME submission. Onboarding keeps its saveable page index and existing completion callback. Settings projects stored decisions into visible canonical-origin rows and calls the same typed callbacks.

## Trust and origin boundary
Home address text is untrusted until `resolveAddressInput` accepts it. Suggested destinations remain compiled `SuggestedSite` values. Settings receives persisted trusted `SiteOrigin` objects and exposes the complete `canonical` value; no remote display name substitutes for browser-observed identity. Manifest content cannot reach `WeboraTheme`, action labels, icons, layout, or setting state. Onboarding is entirely browser-authored.

## Security and privacy
- Do not change URL resolution, suggestion validation, consent storage, global enablement, data clearing, or dialog confirmation.
- Keep complete canonical origins visible and bound into reset semantics.
- Keep the global toggle's explicit state description.
- Add no telemetry, URL logging, remote asset, intent surface, or dependency.
