# UX-014: Implementation plan
Status: PLAN_APPROVED

## Overview

Refactor `SiteSkinTopBar` to fill the UX-013 `ExpressiveSiteSkinHeader` with a fixed browser-owned
Back slot, bounded site-brand slot, and a Webora-token security identity surface. At the existing
`PROTECTED_INTEGRATED` composition seam, replace the direct colour scheme with the closed expressive
presentation derived from the already-trusted active configuration plus browser/platform dark and
reduced-motion inputs. Do not change bottom navigation, the site menu, WebView status/error layers,
or any core/protocol behavior.

## Flow

1. Existing discovery, validation, consent, and exact-origin activation produce a trusted
   `BrowserMode.Integrated` for the selected tab; this ticket adds no earlier pipeline stage.
2. `RegularBrowser` exhaustively projects the selected mode through `chromeHandoff()`. Only
   `TopChrome.PROTECTED_INTEGRATED` constructs expressive presentation.
3. Browser-owned system theme and animator enablement are read at the app composition boundary and
   passed as booleans to `ExpressiveSiteSkinPresentation.from` with the trusted configuration.
4. Existing configuration-identity asset association supplies either the accepted same-origin
   asset or immediate monogram. Existing `securityPresentation(state.mode)` supplies canonical
   identity from observed mode.
5. `SiteSkinTopBar` renders the named content inside `ExpressiveSiteSkinHeader`. It may reflow
   browser-owned/site slots for compact large-text layouts, but required identity and Back always
   compose and compiled geometry remains inside the component/primitive.
6. `BrowserStatusRegion`, WebView/error overlay, SiteSkin content actions, and current bottom
   SiteSkin navigation render unchanged after the new top surface.

## Origin-boundary implications and browser-owned contract

The exact committed HTTPS origin remains upstream in `BrowserMode.Integrated`; the UI neither parses
nor compares origins. Site-controlled input reaches the header only after validation as bounded
title/subtitle, accepted same-origin brand asset, and the six existing contrast-guarded colour roles.
The canonical registrable domain/TLS state, Back icon/label/enabled state/callback, browser
sub-surface palette, semantics tags/descriptions, geometry, insets, adaptive order, and motion policy
are browser-owned. `chromeHandoff()` remains the only authorization for the integrated header, so
cross-origin departure or active-tab change removes it before the next projection. Tabs/overflow
remain browser-authored and reachable in their current surfaces; moving them belongs to UX-015.

No failure widens trust: absent/failed/stale assets use the existing monogram/configuration-identity
guard, unavailable animator settings conservatively select reduced motion, and loss of integrated
mode falls back to ordinary browser chrome rather than leaving branded decoration behind.

## Data

- No DTO, core domain, schema, cache, persistence, or network change.
- `SiteSkinTopBarModel` remains the immutable display model containing bounded site text/asset plus
  browser-produced `SecurityPresentation`.
- `ExpressiveSiteSkinPresentation` remains the complete site-influenceable presentation seam.
- Animator state is ephemeral browser/platform input and is never stored or exposed to a manifest.

## Security

- Origin binding: retain existing exact-origin activation and configuration-identity asset guard;
  introduce no header-local suffix/domain comparison.
- Allow-lists: unchanged. Only accepted `BrandAsset` and trusted configuration roles enter.
- Browser identity: render the tagged domain/TLS row on a Webora-owned sub-surface with browser
  tokens and localized non-colour security wording, never SiteSkin foreground values.
- Browser controls: Back uses the closed local resource, localized label, observed enabled state,
  and explicit callback; no generic command or manifest input is introduced.
- Fallback: no integrated mode means no expressive header; unavailable/disabled animator scale
  produces immediate motion policy; branding failure retains monogram.

## File-by-file plan

### Modified: `app/src/main/java/app/webora/browser/siteskin/SiteSkinTopBar.kt`

Change the API to accept `ExpressiveSiteSkinPresentation`, host its content in
`ExpressiveSiteSkinHeader`, and add adaptive compiled layout that keeps Back, bounded brand content,
and security identity visible. Give identity a Webora-token sub-surface and keep existing tags and
localized descriptions. Add a stable brand-content tag if bounds testing needs it.

### New: `app/src/main/java/app/webora/browser/design/MotionPreference.kt`

Add a thin Android wrapper for animator duration scale and a pure function mapping the observed
nullable scale to reduced-motion state. Treat zero, invalid, and unavailable values conservatively;
keep the API browser-owned and independent of manifest/configuration.

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

At `PROTECTED_INTEGRATED`, build `ExpressiveSiteSkinPresentation` from the trusted active
configuration, system dark theme, and the browser motion preference; pass it to the refactored top
bar. Preserve status/error/bottom composition and all controller callbacks.

### Modified: `app/src/androidTest/java/app/webora/browser/siteskin/SiteSkinTopBarTest.kt`

Retain identity, hostile-branding, logo bounds, and Back dispatch checks; add 320 dp/200% font light,
dark, and reduced-motion cases that assert the expressive header, identity, Back, and brand bounds
remain displayed/non-overlapping and Back retains a 48 dp target.

### Modified: `app/src/test/java/app/webora/browser/siteskin/SiteSkinNavigationContractTest.kt`

Extend source negative controls to require the expressive primitive/presentation and browser-token
identity/Back while rejecting unsafe snippets that source identity, geometry, order, or motion from
SiteSkin configuration/colours.

### New: `app/src/test/java/app/webora/browser/design/MotionPreferenceTest.kt`

Test enabled, disabled, invalid, and unavailable animator-scale inputs, including a negative control
showing a permissive missing-value policy is rejected.

### Modified: `CLAUDE.md`

After review/QA, record the integrated expressive top contract, identity sub-surface, motion wrapper,
and the explicit UX-015 tabs/overflow/dock handoff.

### Modified: `docs/ROADMAP.md`

Mark UX-014 complete only after review is resolved and QA passes.

### New: `reports/review/UX-014.md`

Record the required security, correctness, accessibility, architecture, test, and scope review.

### New: `reports/qa/UX-014.md`

Map every PRD criterion to automated/manual evidence and distinguish compiled instrumentation from
device runtime/screenshots when the managed-cloud environment has no connected device.

## Tests

- Focused JVM: motion policy and top-chrome source/negative-control contracts.
- Focused instrumentation: top header identity/Back/branding at 320 dp and 200% font in light, dark,
  and reduced modes; execute only with a connected device.
- Existing JVM: expressive presentation/primitive contracts, handoff, top model, asset association,
  and browser state/origin teardown suites.
- Compile instrumentation with `./gradlew :app:compileDebugAndroidTestKotlin` regardless of device.
- Run `bash scripts/pre-commit-check.sh` before every task commit.

## Rollout / versioning

No schema, storage, migration, network, permission, consent, or staged rollout change. This is a
visible integrated-mode UI replacement guarded by the existing exhaustive mode projection. Capture
a screenshot if a connected device is available; otherwise record the mandated environment limit.

## Open questions

- Exact compiled spacing may be tuned from Compose bounds/device evidence, but the adaptive order,
  identity presence, and browser ownership are not tunable requirements.
- Standard motion may remain visually immediate if no safe decorative transition is necessary; the
  closed policy still must be wired so later decoration cannot bypass the platform preference.
