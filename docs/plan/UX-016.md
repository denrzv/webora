# UX-016 plan — Even regular dock command slots

Status: PLAN_APPROVED

## Flow

Keep the existing shared Home/regular shell and its safe-area placement. Inside the existing 60 dp
surface, make the command row consume the available width. Render each fixed command in an equal
weighted slot whose content is centered, while continuing to call the existing `WeboraIconButton`.

## Trust boundary

This is browser-owned presentation only. No manifest, page, URL, origin, or SiteSkin configuration
enters the slot model. Command identity/order, localized semantics, enabled state, callbacks,
dimensions, colours, and safe/system insets remain compiled. Protected integrated composition and
its separate SiteSkin hub/dock are not touched.

## Security and accessibility

- Preserve the closed command list and direct typed callbacks; introduce no generic dispatch seam.
- Preserve Back/Forward/Reload browser-observed availability.
- Center the existing minimum-48-dp buttons within equal wrappers rather than reducing button size.
- Use deterministic constraints, not hand-tuned per-icon padding.

## File changes

1. `BrowserChrome.kt`: fill the inner Row and introduce a small private equal-weight slot composable;
   expose stable test tags for the dock and six slots so geometry evidence observes the layout owner.
2. `BrowserChromeTest.kt`: measure dock and slot bounds at compact width; require equal widths,
   evenly spaced centers and symmetric edges within pixel rounding, while retaining target and
   callback/disabled-state coverage.
3. Workflow/report docs: record implementation, review, QA, visual evidence availability, and the
   enduring browser-owned distribution contract.

## Verification

- Focused JVM and compiled Compose instrumentation tests.
- Full `bash scripts/pre-commit-check.sh` before each task commit.
- Home screenshot from a connected runtime when available; otherwise record the prescribed managed
  cloud limitation without manufacturing an emulator.

## Rollback

Revert the full-width row/equal slot wrappers and their geometry tags/tests. No persisted data,
protocol, origin, or API migration is involved.
