# UX-028: Implementation plan
Status: PLAN_APPROVED

Input: `docs/research/UX-028.md` (`RESEARCH_READY`), `docs/prd/UX-028.prd.md` (`PRD_READY`).

## Overview

One tap in the inspector puts the current diagnostic snapshot on the clipboard as a JSON document.
Three pieces, all in `src/debug/java`:

```
InspectorSnapshot ──┬─→ SiteSkinInspectorPanel  (rows, already there)
   (src/main)       │
                    └─→ inspectorJson(snapshot) ─→ JsonValue tree ─→ render() ─→ ClipData
                          projection (policy)      closed type       writer
```

The snapshot is the single source of truth, and it already is one: `rememberInspectorSnapshot`
assembles it once and hands it to the panel as a parameter. This ticket adds a **second reader of
that same value**, not a second model.

The two halves are separated on purpose. `render()` is a total, generic, content-blind writer over a
closed tree; `inspectorJson` is the ticket's policy — which fields, in which order, bounded how. A
single function doing both would put escaping bugs and disclosure bugs in one place and let a test
for either look like a test for both.

## Flow

- **discovery** — none. Nothing is fetched, revalidated or re-scanned. `inspectorJson` is a pure
  function of the snapshot it is handed.
- **validation** — none at copy time. The document *reports* the validation that already happened,
  from `ManifestValidationTrace`.
- **normalization** — every string in the document passes through `inspectorValue`, i.e.
  `untrustedText` at `SiteSkinLimits.MAX_SUBTITLE_LENGTH`, the same bound the panel's rows use.
- **UI state** — the panel gains one `InspectorCopyState` (`IDLE` / `COPIED`) and nothing else. The
  host's `inspectorVisible` flag is untouched, so the modal cannot close as a side effect of copying.

## Data

### The document's shape

Top-level keys are the declared property names of `InspectorSnapshot`, in declaration order:

```json

  "siteSkinEnabled": true,

  "record": { "origin": "…", "generation": 3,
              "transport": { "manifestUrl": "…", "outcome": "FETCHED", "cacheState": "MISS",
                             "httpStatus": 200, "redirects": 0, "rejection": null },
              "validation": { "result": "ACCEPTED", "schemaVersion": "1.0",
                              "diagnostics": [ { "code": "SS-W-FIELD-UNKNOWN", "pointer": "/foo" } ] } },
  "applied": { "siteName": "…", "siteId": "…", "homeUrl": "…", "activeNavigationId": "cart",
               "counts": [ { "collection": "BOTTOM_NAVIGATION", "trusted": 5, "rendered": 5,
                             "diverged": false } ],

               "hub": { "requested": null, "effective": "DRAWER" },
               "theme": { "darkTheme": false,
                          "roles": [ { "role": "PRIMARY", "trusted": "#D94F8A",
                                       "applied": "#D94F8A" } ] } }

```

Keys mirror property names **one for one, and not because it reads nicely**. It is what makes the
totality test a reflective walk instead of a hand-written table — and `NET-004` already recorded why
that matters: a hand-written table is correct on the day it is written, and a reflective sweep covers
the field nobody remembered.

`brandAsset` and `brandAssetTrace` therefore stay two sibling keys rather than nesting into one
object, even though nesting would read better. They are two properties of the snapshot, kept
deliberately apart by `DEVX-001` because a disagreement between them is itself worth seeing.

### The tree

```kotlin
internal sealed interface JsonValue {
    data object JsonNull : JsonValue
    data class JsonBool(val value: Boolean) : JsonValue
    data class JsonNumber(val value: Long) : JsonValue
    data class JsonString(val value: String) : JsonValue
    data class JsonArray(val items: List<JsonValue>) : JsonValue
    data class JsonObject(val fields: List<Pair<String, JsonValue>>) : JsonValue
}
```

`JsonObject` holds an **ordered list of pairs**, not a `Map`. Determinism is then a property of the
type rather than of remembering to use a `LinkedHashMap`, and a duplicate key is representable rather
than silently swallowed — which the totality test can see.

`JsonNumber` is `Long` only. Every number in the model is an `Int` or a `Long`; there is no floating
point anywhere in the snapshot, and admitting `Double` would admit `NaN`, which has no JSON
representation and no failure mode better than a corrupt document.

### Trust boundary

The clipboard document's ceiling **is** the snapshot's ceiling, narrowed:

| | Panel | Document |
|---|---|---|
| Website text | `inspectorValue` at each render site | `inspectorValue` at the one construction site |
| Absent value | `—` (`R.string.inspector_absent`) | `null` |
| Enum | `.name` | `.name` |

The narrowing is real and is the point: the panel bounds at fifteen call sites and the document has
exactly one. **`InspectorJson.kt` constructs `JsonString(` on exactly one line**, inside

```kotlin
private fun bounded(raw: String?): JsonValue = raw?.let { JsonString(inspectorValue(it)) } ?: JsonNull
```

so an unbounded string is not a thing an edit can forget — it is a thing an edit has to add a second
construction site to do, and the scan counts them. Enum names go through the same helper: they are
compiled identifiers and the walk is a no-op on them, and routing them anywhere else would create the
second site.

`—` deliberately does not reach the document. It is a display convention; exporting it would make an
em-dash a sentinel every consumer has to know about, and would fail the issue's type-preservation
requirement while looking like it passed.

### Storage / cache keys

None. Nothing is persisted. The trace recorder is unchanged and is still cleared with browsing data
by `BrowsingDataCleaner`; `PRIV-001`'s zero-telemetry rule is untouched because the only egress is a
clipboard write the user asked for.

## Security

### Origin binding

Unchanged, and inherited rather than re-decided. The document describes **one** snapshot, and a
snapshot is assembled for one canonical origin by `rememberInspectorSnapshot`. The mixing risk the
issue names — "tab change / stale scan callback cannot merge another tab's state" — is prevented by
`inspectorJson` taking exactly one parameter of type `InspectorSnapshot` and reading nothing else.
That is a signature property, asserted two-sidedly (arity and erasure from the compiled method,
declared types from the declaration line) as `UX-026` established for `hubDrawerHeight`, plus a scan
proving the panel passes its own `snapshot` parameter and never names the recorder or browser state.

### Allow-lists

- **What may be in the payload** is a closed type graph: `String`, `Int`, `Long`, `Boolean`, any
  enum, `List`, and the inspector's own record types. Enforced reflectively over
  `InspectorSnapshot`'s reachable fields, so a `Map<String, String>` of response headers, a
  `ByteArray`, a `Bitmap`, a cookie or a DOM string cannot be added to the model — with or without
  this ticket's serializer — without turning the build red. This is the issue's requirement 10, and
  it is stronger than a test asserting the current payload has no cookie in it.
- **What may be a key** is a compiled string literal in `InspectorJson.kt`. No website value becomes
  a key; a site that could invent field names could forge a report a developer reads as the browser's.
- **Where the payload may go** is `ClipData.newPlainText` and nowhere else. No share intent, no file,
  no socket.

### Fallback on failure

The writer is total over the tree, and the tree is total over the model, so there is no partial
document. A snapshot with `record = null`, `applied = null` and `brandAssetTrace = null` serializes to
a valid document whose values are `null` — which is exactly the state a site owner debugging "nothing
happened" needs to paste.

The clipboard write itself can fail only by the platform throwing; it is not caught and turned into a
false `Copied`, because a confirmation that appears whether or not the copy happened is worse than no
confirmation. The feedback flag is set after `setClipEntry` returns.

### Release variants

Two independent mechanisms, per `DEVX-001`:

1. **Source set.** Every new production file is in `src/debug/java`. The release and `debugRelease`
   variants never compile it, and `src/release/java`'s stub host is unchanged.
2. **Compiled output.** `AssertInspectorAbsent` grows from one forbidden class prefix to a list, and
   the list names the serializer. Without this, moving the file into `src/main/java` later would ship
   the capability past a check whose name says it prevents exactly that.

The `requiredClass` half of that task is unchanged and still keeps the check from passing vacuously.

## File-by-file plan

### New: `app/src/debug/java/app/webora/browser/inspector/JsonDocument.kt`

The closed tree and `internal fun JsonValue.render(): String`. Two-space indent, `\n` separators, no
trailing newline. Escaping per RFC 8259: `"`, `\`, `\b`, `\f`, `\n`, `\r`, `\t`, and every remaining
character below `U+0020` as `\u00XX`. Non-ASCII is emitted literally — the clipboard is UTF-8 and
escaping it would only make the paste harder to read.

Content-blind: it takes a tree and knows nothing about inspectors, snapshots or websites. It is the
half a future second consumer could reuse, and the half whose only failure mode is an escaping bug.

### New: `app/src/debug/java/app/webora/browser/inspector/InspectorJson.kt`

`internal fun inspectorJson(snapshot: InspectorSnapshot): String` and its private per-record
projections. One `bounded()` helper, one `JsonString(` construction site, keys as literals in
declaration order.

### Modified: `app/src/debug/java/app/webora/browser/inspector/SiteSkinInspectorPanel.kt`

- `dismissButton` gains a `WeboraOutlinedButton` labelled `inspector_copy`, with
  `inspector_copy_description` as its accessible name. Outlined rather than filled: `Close` stays the
  primary action, and `UX-007`'s hierarchy vocabulary is the browser's own.
- The action row stays Material's `AlertDialogFlowRow` pair, which reflows onto two lines when the
  labels do not fit. `UX-007`'s explicit full-width vertical stack is *consent* policy — it exists so
  a security decision's three options cannot become a split row — and is deliberately not copied to a
  developer tool's two.
- `title` becomes a `Column`: the existing heading, plus a persistent feedback `Box` that carries a
  `contentDescription` and `LiveRegionMode.Polite` only once a copy has happened. The pattern is
  `BrowserStatusRegion`'s, for its reason: the node persists so the live region is not created and
  destroyed around the announcement, and no announcement means *no semantics at all* rather than a
  nameless node. The title is chosen over the body because the body scrolls, and confirmation that
  can be off-screen when it is published is confirmation the user does not get.
- A `rememberCoroutineScope()` and `LocalClipboard.current`, because `Clipboard.setClipEntry`
  suspends. The clip label is `inspector_copy_clip_label` from resources — Android 13+ shows it in
  the system clipboard preview, so it is user-visible copy.
- The JSON is `remember(snapshot) { inspectorJson(snapshot) }`. Keyed on the snapshot, so what is
  copied is what is displayed even as the browser moves under an open panel.
- The copy handler is extracted into its own private composable so `InspectorBody`'s and the panel's
  complexity do not cross detekt's ceilings. `UX-024` had to extract three functions for the same
  reason; extraction is the answer here, never the baseline.

### Modified: `app/src/debug/res/values/strings.xml`

`inspector_copy`, `inspector_copy_description`, `inspector_copy_clip_label`, `inspector_copied`.
Debug-only, so no inspector string ships in a release artifact — the existing comment in that file
states the rule and this obeys it.

### Modified: `app/build.gradle.kts`

`AssertInspectorAbsent.forbiddenClassPrefix: Property<String>` → `forbiddenClassPrefixes:
ListProperty<String>`, set to `["SiteSkinInspectorPanel", "InspectorJson", "JsonDocument"]`. The
failure message names the offending prefix so the diagnosis is not "something is in release".

### New: `app/src/test/java/app/webora/browser/inspector/JsonDocumentTest.kt`

The writer, alone: escaping, control characters, empty containers, nesting, key order, and the fact
that a `JsonNumber` is not quoted while a `JsonString` is.

### New: `app/src/test/java/app/webora/browser/inspector/InspectorJsonTest.kt`

The projection: a golden document for a fully populated snapshot, an all-null snapshot, bounding of a
hostile pointer, `null` rather than `—`, byte-identical repeat serialization, and the two reflective
sweeps (totality, type-graph closure).

### New: `app/src/test/java/app/webora/browser/inspector/InspectorCopyContractTest.kt`

The source-level rules: one `JsonString(` construction site in `InspectorJson.kt`; the panel copies
its `snapshot` parameter and names no recorder or browser-state type; the panel's copy path does not
call `onClose`. Executable lines only — comments stripped before matching, per `BROWSE-009`.

### New: `app/src/androidTest/java/app/webora/browser/inspector/InspectorCopyTest.kt`

One instrumented test for the thing no JVM test can reach: the real Android clipboard. Click copy,
read `ClipboardManager`, parse with `org.json.JSONObject`, assert a known value, assert the panel is
still displayed, click again and assert the clipboard still parses.

### Modified: `CLAUDE.md`, `docs/DEVELOPMENT_PLAN.md`

The convention this establishes, written where the next ticket will read it.

## Tests

Mapped to the issue's eleven test requirements:

| Issue requirement | Test |
|---|---|
| 1 completed scan → clipboard parses | `InspectorCopyTest` (instrumented), `InspectorJsonTest` golden |
| 2 copied values match rendered values | `InspectorJsonTest` bounding cases + the `bounded()` single-site scan |
| 3 large/nested payload not truncated by UI | `InspectorJsonTest` with 20 menu items and 5 nav items; the payload is built from the model, never from layout |
| 4 null/bool/array/object types preserved | `InspectorJsonTest` all-null snapshot + `JsonDocumentTest` |
| 5 modal stays open | `InspectorCopyTest`; `InspectorCopyContractTest` (no `onClose` on the copy path) |
| 6 feedback after clipboard update | `InspectorCopyTest` asserts the announcement node after the click |
| 7 repeated copies safe | `InspectorCopyTest` clicks twice |
| 8 error/partial state copies validly | `InspectorJsonTest` rejected-record and no-record snapshots |
| 9 no mixed payload across tabs | `InspectorJsonTest` signature assertion + `InspectorCopyContractTest` |
| 10 no cookies/headers/storage/DOM | `InspectorJsonTest` reflective type-graph closure |
| 11 320 dp / 200% font scale reachable | `InspectorCopyTest` at a forced font scale; the action row reflows |

### Negative controls

Each is applied to the **real source**, the run observed to fail, and then reverted — never written
as an in-test example. `UX-022` and `UX-024` each lost a control to a fragment that did not compile,
which reads exactly like a control that bit nothing.

| Control | Must fail |
|---|---|
| `bounded()` returns `JsonString(raw)` without `inspectorValue` | the hostile-pointer bounding case |
| Drop `applied` from the projection | the reflective totality sweep |
| Add `val headers: Map<String, String>` to `InspectorSnapshot` | the type-graph closure sweep |
| Emit `JsonObject` from a `Map` | the byte-identical repeat case |
| Panel serializes a `remember { }` with no key | the contract scan's snapshot-parameter rule |
| Remove `\\u` escaping for `U+0001` | the writer's control-character case |
| Move `InspectorJson.kt` to `src/main/java` | `assertInspectorAbsentFromReleaseVariants` |

The last one is the check that would otherwise pass vacuously, and running it is what makes the
Gradle change worth having.

## Rollout / versioning

No protocol change: `SPEC.md`, the schema, `spec/diagnostics.json` and the conformance corpus are
untouched. No manifest field is read, added or interpreted, and `spec/fixtures/valid/bloom-flowers.json`
and its five pinned copies are not involved.

No hosted-evidence change: `CI-009`'s canonical frame inventory, per-frame checks and contact sheet
are unchanged. The inspector is not in any canonical frame — `DEVX-003` moved its affordance into the
menus precisely so it is not — and this ticket adds no overlay, so no hosted acceptance is re-taken.

Debug variants only. A release build has no entry, no panel, no serializer and no clipboard write.
