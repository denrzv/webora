# UX-019 plan — The tab switcher joins the browser-owned modal language

Status: PLAN_APPROVED

## Overview

Rebuild `TabSwitcher`'s presentation in `BrowserTabSummary.kt` on the structure `UX-018` established
for privacy settings: a full-window opaque `Dialog`, a headline, tonal selectable rows with an
icon-only close control, one full-width primary action and a text dismiss. The pure model
(`BrowserTabSummary`, `tabSummaries`, `browserLabel`) and all four callbacks are untouched, so
`BrowserScreen`'s adapter and `BrowserSession` do not move.

The selected state becomes a **colour role**, and the role pair is chosen from the palette rather
than from Material's names — see the trust/geometry section, this is the one decision in the ticket
that can be wrong invisibly.

## Flow

1. Any of the three existing entry points sets `tabsVisible`; `BrowserTabSwitcher` is unchanged.
2. `TabSwitcher` opens a `Dialog(properties = DialogProperties(usePlatformDefaultWidth = false))`.
3. A `Surface(fillMaxSize, color = background)` paints the app ground and blocks the page.
4. Inside, `windowInsetsPadding(WindowInsets.safeDrawing)` and a scrolling `Column`:
   headline → tab rows → limit notice when capped → `New tab` → `Close`.
5. A row's select surface carries `TAB_SELECT_TAG`, `selected` semantics and the row
   `contentDescription`; its sibling close control carries `TAB_CLOSE_TAG`.
6. Select and New tab call through and dismiss exactly as today; close-tab does not dismiss.
7. Android Back is consumed by the dialog window and reaches `onDismiss` before browser history.

## Origin and trust boundary

Nothing website-controlled enters this surface, and the restyle adds no new input to it.

- A row's visible text and accessible name derive only from `browserLabel()` —
  `Home` / `registrableDomain` / `Page` — plus browser-authored ordinal copy from `strings.xml`.
  Manifest `site.name`, page titles, editable address text and document content have no path in.
  `TabSwitcherModelTest` stays **unedited**; needing to change it means the boundary moved.
- No per-tab remote asset. The one glyph is `R.drawable.ic_close`, already bundled.
- Colours come from `WeboraTheme` only. `SiteSkinColorScheme` is not read here even when the active
  tab is integrated — a tab list showing eight origins must not be painted by one of them.
- Geometry, order, row count, the eight-tab limit and every callback are compiled browser policy.

## Security, accessibility and the colour decision

**The selected role pair is `primary` / `onPrimary`, not `primaryContainer` / `surfaceVariant`.**
`materialColorScheme` maps `surfaceVariant ← chrome` and `primaryContainer ← container`, and in the
dark projection `chrome` and `container` are the same value (`0xFF1F2C2C`). A selected state built
from that pair is invisible in dark theme while passing every light-theme check. `primary`/`onPrimary`
separates in both projections and is already in `WeboraColorSchemeTest`'s measured table, so no
unmeasured colour is introduced. Unselected rows use `surfaceVariant`/`onSurface`, also measured.

- The distinction is a colour role, never an alpha multiplier (`UX-003`).
- The close control goes through `WeboraIconButton`, which makes a nameless icon a compile error and
  applies the one 48 dp `MINIMUM_TOUCH_TARGET`. No new touch-target token.
- The select surface and the close control are **siblings**, not nested, so `mergeDescendants` cannot
  make `TAB_CLOSE_TAG` unaddressable and `assertIsSelected()` keeps targeting the node it targets
  today.
- The visible label sheds the accessibility sentence; the sentence survives as the row's
  `contentDescription`, so screen-reader output does not regress.
- All copy stays in `strings.xml`; `A11Y-001`'s scan fails on a literal reaching `Text(`.
- The dialog owns its own `safeDrawing` read inside its own window. `BrowserScreen` keeps its single
  read; no second read is added to the shell.

## File-by-file plan

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserTabSummary.kt`

- Keep `BrowserTabSummary`, `tabSummaries`, `browserLabel` and the four tag constants byte-identical.
- Replace `AlertDialog` with `Dialog` + full-size `Surface`, matching `PrivacySettingsDialog`.
- Add `TabSwitcherContent` — the scrollable body — so the instrumented suite can drive the content
  without a dialog window, as `PrivacySettingsScreen` is drivable beside `PrivacySettingsDialog`.
- `TabRow` becomes: `Row` → `Surface(onClick, shape = shapes.medium, colour by selection,
  weight(1f), TAB_SELECT_TAG, semantics { selected; contentDescription })` containing the label and
  ordinal `Text`s, then a sibling `WeboraIconButton(ic_close, …, TAB_CLOSE_TAG)`.
- `New tab` stays a filled `WeboraButton(fillMaxWidth)` keeping `NEW_TAB_TAG` and its `enabled` flag;
  `Close` becomes `WeboraTextButton(fillMaxWidth)`.
- The `tab_limit_reached` notice stays visible and stays above the primary action.

### Modified: `app/src/main/res/values/strings.xml`

- Keep `tabs_title`, `new_tab`, `tab_limit_reached`, `close_tab`, `tab_description` as they are —
  `tab_description` becomes the row's accessible name rather than its visible label.
- Add one browser-authored ordinal string for the visible secondary line.

### Added: `app/src/test/java/app/webora/browser/browser/TabSwitcherContractTest.kt`

JVM, in the `BrowserChromeContractTest` idiom — each assertion with its own broken counter-example:

1. `selected and unselected tab rows separate in both projections` — asserts the chosen roles differ
   in `LIGHT` **and** `DARK`, with a negative control that the `chrome`/`container` pair collapses in
   `DARK`, so the reason the obvious choice was rejected is itself pinned.
2. `the switcher is a full-window modal, not a confirmation box` — source scan for `Dialog(` +
   `usePlatformDefaultWidth = false` and absence of `AlertDialog(`; negative control rejects an
   `AlertDialog` source.
3. `the four switcher tags survive` — the constants and their presence in the source.
4. `the row select affordance is not a filled button` — negative control rejects a `WeboraButton`
   carrying `TAB_SELECT_TAG`.

### Modified: `app/src/androidTest/java/app/webora/browser/browser/TabSwitcherTest.kt`

Instrumented evidence, never a gate claim:

- keep `switcherExposesSelectedTabAndVisibleLimit` (selected node, limit text, disabled `New tab`);
- add: selecting a row emits that tab's id and dismisses; close emits its id and does **not** dismiss;
- add: `Close` and `pressBack()` each dismiss once, in `PrivacySettingsScreenTest`'s idiom.

### Unmodified, deliberately

`BrowserScreen.kt` (the adapter, the three entry points, the single inset read), `BrowserSession`,
`BrowserSessionSnapshot`, `TabSwitcherModelTest`, `WeboraColorScheme`, `WeboraRadius`, the drawable
set.
