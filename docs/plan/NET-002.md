# NET-002 — Manifest cache plan

Status: PLAN_APPROVED

## Flow

1. The coordinator canonicalizes the browser-observed main-frame HTTPS origin and cancels superseded work.
2. It asks `ManifestCache` for that origin's active accepted entry. A fresh entry is validated again from its bounded bytes and returned without transport.
3. A stale entry contributes only browser-selected `If-None-Match` / `If-Modified-Since` validators to a metadata-aware fetch.
4. `Fetched` bytes are validated for the observed origin. Only acceptance writes a cache entry keyed by canonical origin and trusted `configuration.schemaVersion`.
5. `NotModified` refreshes the same exact entry's timestamps/metadata and returns its revalidated bytes.
6. `Unavailable` may return the stale exact-origin entry; `Rejected` returns unavailable and does not silently revive it.
7. Existing job cancellation prevents any superseded result from reaching browser state.

## Origin boundary and browser-owned contract

The cache key is a value object containing the complete `SiteOrigin.canonical` string and exact trusted schema-version string. The active-version index is also keyed by that canonical origin. Website input cannot supply either origin key or a longer lifetime. Redirect policy remains in the transport. Response metadata can shorten freshness but never exceed the core 24-hour limit. Cache bytes always pass `SiteSkinValidator` again before becoming an outcome, so possession of cached bytes is not treated as trust. Only explicit transport unavailability permits stale reuse; HTTP responses and invalid replacements fail closed. The cache does not apply UI or change immutable browser security chrome.

## Design

### Closed transport model

Add `ManifestRequestValidators` and a sealed `ManifestFetchResult` (`Fetched`, `NotModified`, `Unavailable`, `Rejected`) behind an app-layer `CacheableManifestSource`. Keep `OkHttpManifestSource.fetch` as the core-interface compatibility adapter. Conditional headers are copied only from stored response values. Redirect and size rules remain unchanged.

### Cache

`ManifestCache` is an internal, bounded in-memory map. `ManifestCacheKey(origin, schemaVersion)` prevents string-concatenation ambiguity. One active key per origin limits normal growth, while exact-key lookup remains available to test/version the identity contract. Entries defensively copy bytes, carry optional validators, a fetched monotonic timestamp, and an overflow-safe TTL parsed from a single valid `max-age`. Missing/ambiguous/malformed directives yield zero freshness; the maximum is `SiteSkinLimits.MAX_CACHE_TTL_SECONDS`.

## Security and privacy

No manifest bodies or URLs are logged. Entries are bounded to accepted manifest size and at most one active version per origin. In-memory lifetime avoids introducing persistent browsing history before `PRIV-001` defines clearing policy. Invalid cache state degrades to regular browsing.
