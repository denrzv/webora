# UX-025 plan — the dock projects ids the validator already trusted

Status: PLAN_APPROVED

PRD: `docs/prd/UX-025.prd.md`
Research: `docs/research/UX-025.md`
Issue: [#123](https://github.com/denrzv/webora/issues/123)

## Overview

Five layers in research F9's order, each independently green:

1. **Protocol.** `presentation.dock` — an optional array of at most three existing ids, carried into
   the trusted model as ordered ids and nothing else.
2. **Resolution.** One pure `dockArrangement(configuration, pageUrl)` producing a closed slot list.
3. **Composition.** `SiteSkinDock` renders the arrangement; the drawer subtracts what the dock drew.
4. **Reference integration.** Bloom's five pinned copies move together, in `denrzv/bloom-flowers`
   and here.
5. **Hosted journey.** Re-point `BloomReferenceContract`; acceptance re-taken elsewhere.

Layers 1–3 land in this repository and are what the gate can defend. Layer 4 crosses repositories.
Layer 5 cannot complete in this checkout — no emulator.

## Flow

```
presentation.dock: ["catalog","cart","profile"]   (ids only — no payload, no icon, no callback)
        │  validator: bound to 3, de-duplicate, drop unresolvable, warn
        ▼
SiteSkinConfiguration.presentation.dock : List<String>      (trusted, ordered, resolvable)
        │  + SiteSkinChromeModel (already bounded)  + browser-observed page URL
        ▼
dockArrangement ─► DockArrangement.Projected(site, site, site)   → 5 slots
                └► DockArrangement.BrowserOnly                    → UX-024's 3 slots
        ▼
SiteSkinDock renders slots; SiteSkinHubDrawer subtracts the rendered ids
```

## Origin and trust boundary

**The field names ids and can do nothing else.** Every id it may carry already denotes an item the
validator produced — origin-bound, scheme-checked, action-allow-listed, label-clamped. So
`presentation.dock` cannot introduce an action, widen one, supply a URL, an icon or a callback, or
reach a browser command. It selects among things the browser has already decided are safe, exactly as
`UX-022`'s `hub` selects among components the browser already compiles.

**The two item types stay apart, and this is the ticket's sharpest risk.** Research F2: browser and
site commands share a row here for the first time, and `UX-024` records that the moment they shared
an item type a manifest could publish something rendering identically to Back. So:

- `DockSlot` is a **sealed** hierarchy. `DockSlot.Brand`, `DockSlot.Tabs`, `DockSlot.More` carry no
  site data at all; `DockSlot.Site` carries the trusted `SiteSkinItemModel` and nothing else.
- No constructor accepts both an enum and a `NavigationItem`. A reflective field inventory keeps it
  closed as the model grows, the shape `UX-024` used.
- The Brand and More slots are produced unconditionally by the arrangement, in fixed positions, so
  "a manifest cannot replace them" is a property of the type rather than of a `when` branch.

**De-duplication hides, never deletes** (research F6). `SiteSkinChromeModel` keeps every item, so
`NavMatcher` still sees projected items and criterion 12's fallback is automatic: the drawer
subtracts the ids the dock *rendered*, so anything the dock did not render is still listed.

Teardown adds no path. Exact-origin departure, tab switch and configuration change already remove
the whole dock; the arrangement is derived per composition from the active configuration.

## Security and accessibility

- Pattern, never `enum`, and the id grammar is the existing `^[a-z0-9][a-z0-9_-]{0,63}$` — an
  unknown id must never be `SS-E-SCHEMA-INVALID` (`ADR-007`).
- Over-limit is `SS-W-LIMIT-TRUNCATED` at three, never a rejection (`SPEC.md` §8).
- Duplicates de-duplicate first-wins with `SS-E-DUPLICATE-ID`, the code that already means this.
- An id resolving to nothing is dropped with a new `warn`; the manifest is otherwise unaffected.
- Icons stay in the closed semantic map; labels stay bounded by `accessibleLabel`.
- Selected state comes from `NavMatcher` and is exposed as `selected` plus a `stateDescription`,
  never colour alone — and **only** on site slots: Tabs and More are actions, not routes.
- Every slot keeps `MINIMUM_TOUCH_TARGET`. Five slots at the 320 dp floor give 56.0 dp each, the
  measurement `UX-015` shipped and `UX-024` recorded.
