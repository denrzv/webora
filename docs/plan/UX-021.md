# UX-021: Implementation plan

Status: PLAN_APPROVED

Issue: [denrzv/webora#104](https://github.com/denrzv/webora/issues/104)
PRD: `docs/prd/UX-021.prd.md`
Research: `docs/research/UX-021.md`

## Overview

Two changes, deliberately sequenced, because the second one makes the first one's defect louder if
it ships alone.

1. **A browser-owned transport state.** `TransportSecurity` grows from two values to four, and stops
   being derived from `origin.scheme` at projection time. It becomes a field on `BrowserState`,
   written only by browser-observed navigation events through `routeRendererEvent`, and read by both
   chrome variants.
2. **The visible surface.** Integrated chrome's full-width `Secure · domain` row is deleted and
   replaced by one compact browser-owned chip inline after the site title, carrying a shield glyph
   and the registrable domain.

The order is not a preference. A green shield is a stronger claim than the 12 sp word `Secure`, and
the signal behind it is currently `origin.scheme == "https"` — true for a page whose certificate was
rejected. Shipping the visual first would make an existing inaccuracy emphatic. TASK-1 is the state
model; TASK-2 is the pixels.

## The three decisions research carried into this step

**1. The `ADR-006` tension — resolved without amending `ADR-006`.**

The issue's target layout (`[Back] [Logo] Bloom Flowers [shield]`) removes the visible registrable
domain from integrated chrome entirely. `ADR-006` requires it to be always visible, on the concrete
argument that a manifest supplying a title and logo with no contradicting signal renders
`evil.example` as a bank. Research confirmed the aggravating fact: the `UX-015` hub does not display
the origin either, so the literal layout leaves **zero** visible domain anywhere in integrated mode,
with a coloured glyph and a screen-reader string as the only contradiction.

The issue's stated complaint is that the row is *visually heavy* — "consuming roughly a third of the
expressive header". That complaint is satisfied by deleting the **full-width row**, not by deleting
the **domain**. So this plan builds a compact chip:

```
[Back] [Logo]  Bloom Flowers   ( ⛨ bloom.example )
                flower delivery
```

The full-width `surfaceContainer` pill, the `Secure` word and the `·` separator all go. The domain
survives in browser-owned type inside a bounded chip on the title row. `ADR-006` is untouched, no
amendment is written, and the anti-impersonation signal is not reduced. Decided with the repository
owner before planning; recorded here because the issue text says otherwise and a future reader will
notice the divergence.

This costs the title some width. Acceptance criterion 10 already requires the title to ellipsize
before the identity is displaced, so the constraint is unchanged — only the fixed sibling is wider.

**2. Where the state lives — a field on `BrowserState`, not on `BrowserMode`.**

`BrowserMode` participates in equality comparisons that decide security outcomes:
`forObservedOrigin` compares `this.origin == origin` to decide whether integrated mode survives a
page start, and `activateSiteSkin` compares a `Regular` origin before activating. Putting a
lifecycle value inside the mode would also break `NET-004`'s recorded behaviour: `forObservedOrigin`
returns the *same* `Integrated` instance for every same-origin page start, and `BrowserScreen` keys
the brand-asset effect on that instance. A mode that changed identity whenever transport changed
would re-run the brand-asset load on every navigation.

`BrowserState.transport` it is. Nothing that compares modes learns about transport.

**3. Glyphs — two new shield drawables, budget 18 → 20.**

The issue asks for a shield fifteen times, including in its title. `ic_lock`/`ic_warning` stay where
they are and keep meaning what they mean in regular chrome, which is a different job: there the
glyph supports the words `Secure · example.com`, and the regular toolbar is explicitly out of scope
for redesign. The two new drawables carry distinct internal marks so colour is never the only
differentiator, and must satisfy `BrowserIconContractTest`'s viewport / 1.9 stroke / single-colour /
no-fill contracts. `BUDGET` moves to 20 as a deliberate raise, with `UX-005` as precedent.

## Flow

```
onPageStarted            → WebViewEvent.PageStarted     → BrowserObservation.PageStarted
                                                        → transport = UNKNOWN                (always)

doUpdateVisitedHistory   → WebViewEvent.PageChanged     → BrowserObservation.Page
onPageFinished (part 1)                                 → transport preserved iff the observed
                                                          origin equals the committed origin,
                                                          otherwise UNKNOWN

onPageFinished (part 2)  → WebViewEvent.MainFrameCompleted
                                                        → BrowserObservation.MainFrameCompleted  ← new
                                                        → completedTransport(origin, failure)

onReceivedError          → WebViewEvent.MainFrameFailed → BrowserObservation.PageFailed
onReceivedSslError                                      → TLS_ERROR for LoadErrorKind.TLS,
                                                          UNKNOWN for every other kind

                         → securityPresentation(mode, transport) → BrowserChrome / SiteSkinTopBar
```

**The load-bearing detail, and the one place this goes wrong.** `WebViewEvent.PageChanged` and
`WebViewEvent.MainFrameCompleted` currently both map to `BrowserObservation.Page` in
`toBrowserObservation`. Research identified `MainFrameCompleted` as the only *successful*-completion
signal — `HardenedWebViewClient.onPageFinished` fires `onPageChanged` unconditionally and suppresses
`onMainFrameCompleted` for a URL that already failed — but the observation layer throws that
distinction away before `BrowserState` can see it. A rule written on the collapsed `Page` case goes
green on a failed page.

So `BrowserObservation` gains a distinct `MainFrameCompleted` case. Not a `completed: Boolean` on
`Page`: a new case makes `observe`'s `when` exhaustive over it, so the branch cannot be forgotten,
and it gives the two layers one vocabulary.

## Data

**Trust boundary.** No DTO, no manifest field and no remote byte participates. `TransportSecurity`
is written from exactly three inputs, all browser-observed: which `WebViewEvent` arrived, the scheme
of the `SiteOrigin` parsed from the browser-observed committed URL, and the browser's own
`BrowserLoadFailure`. Page content, document title, editable address text, `WebView.getUrl()` and
every manifest field are excluded by construction — none of them is in any signature on the path.

**Storage.** None. `BrowserSessionSnapshot` is untouched: it stores tab id/order/selection and one
bounded URL, and a persisted `SECURE` would be a claim nothing observed. A restored tab starts at
the `BrowserState()` default, which is `UNKNOWN`, and earns its state again by navigating.

**Cache keys.** Unaffected. `NET-002`'s key is origin + schema version; transport is not part of it.

## Security

**Origin binding.** Unchanged and untouched. `securityPresentation` still reads the committed
main-frame origin and only that, and still returns `null` when there is none — `A11Y-001`'s "no
origin yields no node rather than a blank one" is preserved, as is `BrowserScreen:698`'s
`checkNotNull` on the integrated path, which is safe because `Integrated.origin` is non-null. The
new `transport` parameter does not change the nullability contract.

The `PageChanged` rule is itself an origin-binding rule: transport survives a same-document URL
change only when the newly observed `SiteOrigin` equals the previously committed one, compared with
`ADR-004`'s canonical tuple. A `PageChanged` that crosses origins drops to `UNKNOWN` rather than
carrying the previous page's green.

**Fail closed, in four places.** `SECURE` is the only value that requires positive evidence, and
every route that lacks it lands on a neutral state:

| Situation | Result | Why |
|---|---|---|
| Navigation in progress | `UNKNOWN` | `PageStarted` resets unconditionally, so "no news" is never the previous page's good news |
| Completion with a recorded `loadFailure` | `UNKNOWN` | Defence in depth behind `HardenedWebViewClient`'s own suppression, which a redirect can slip past |
| Committed scheme is neither `http` nor `https` | `UNKNOWN` | An `else` branch that assumed insecure-but-known would be inventing evidence |
| `onReceivedSslError` could not identify the main frame | `UNKNOWN` | `mainFrameTlsFailure` publishes nothing when unsure; `PageStarted`'s reset is what makes that safe rather than silent |

**Allow-list.** The scheme test is an allow-list of two with an explicit `else`, not a deny-list.

**Colour ownership, and the trap this plan nearly walked into.** `secure` and `notSecure` are
documented in `WeboraColorScheme` as "on `[container]`" and `WeboraColorSchemeTest` measures them
only against `container`, at 6.80 (light) and 7.94 (dark). The existing `SecurityIdentity` row
grounds itself on `MaterialTheme.colorScheme.surfaceContainer` — and `materialColorScheme` maps
`surfaceContainer` to `scheme.chrome`, **not** `scheme.container`. That was harmless while the row
drew its text in `onSurface`; it is not harmless for a chip that draws a shield in `secure`.

The chip therefore grounds on `MaterialTheme.colorScheme.primaryContainer` / `onPrimaryContainer`,
which map to `container` / `onContainer` — the same ground `BrowserSecurityIdentity` already uses in
regular chrome. One measured pair, one ground, two modes, no new token and no new measured pair.

Grounding on `presentation.colors.background` instead would put a compiled browser colour on a
website-chosen surface with no contrast floor at all. That is `UX-002`'s `C2` violation arriving
through the one element whose entire job is to be trustworthy, and it is the error this ticket is
most likely to make.

**Manifest-controlled surface after this ticket.** Unchanged from research's table. A website
influences the header background the chip sits *near* (already contrast-guarded by `SKIN-001`, and
the chip does not read it) and the title it sits *after* (already bounded and ellipsized). It cannot
reach the chip's colour, glyph, size, position, presence, ground, description or classification. The
one new adjacency — a trust mark beside site-authored text — is bounded exactly as
`HARDEN-002`'s attributed preview is: one line, ellipsized, on a separately-grounded browser
sub-surface, with the domain inside the chip rather than beside it.

**Fallback.** Presentation and state derivation only. No change to discovery, consent, activation,
the session reducer, the renderer lifecycle or the snapshot. An unobserved or unrepresentable
transport degrades to `UNKNOWN`, never to an error, and browsing is never interrupted.

## File-by-file plan

### Modified: `app/src/main/java/app/webora/browser/browser/SecurityPresentation.kt`

- `TransportSecurity` gains `UNKNOWN` and `TLS_ERROR`. `UNKNOWN` is declared **first** so it is the
  natural default and an uninitialised-looking value is the safe one.
- `securityPresentation(mode)` becomes `securityPresentation(mode, transport)`. It no longer
  classifies; it projects the committed origin's registrable domain and carries the state through.
  The `?: return null` contract is preserved verbatim.
- New `internal val BrowserMode.observedOrigin: SiteOrigin?`, extracted from the existing `when` so
  `BrowserState` can compare origins without duplicating the extraction.
- New `internal fun completedTransport(origin: SiteOrigin?, failure: BrowserLoadFailure?)`. A named
  pure function rather than an inline `when`, because it is the rule a negative control targets.

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserState.kt`

- `BrowserState` gains `val transport: TransportSecurity = TransportSecurity.UNKNOWN`.
- `BrowserObservation` gains `data class MainFrameCompleted(url, canGoBack, canGoForward)`.
- `observe` gains its branch; `observePage` gains a `transport` parameter so every caller states the
  new value rather than inheriting one.
- `PageStarted` → `UNKNOWN`. `Page` → preserved iff observed origin equals committed origin.
  `MainFrameCompleted` → `completedTransport(...)`. `PageFailed` → `TLS_ERROR` for
  `LoadErrorKind.TLS`, `UNKNOWN` otherwise — never preserved.
- `navigateFromHome` resets to `UNKNOWN`; it is a new navigation.
- `activateSiteSkin` / `deactivateSiteSkin` deliberately do **not** touch transport. The same page
  over the same connection does not change its transport because chrome changed. Pinned by a test.

### Modified: `app/src/main/java/app/webora/browser/browser/RendererOwnership.kt`

- `toBrowserObservation` stops collapsing `MainFrameCompleted` into `Page` and maps it to the new
  observation case. This is the only change; routing, effects and `RendererPageBook` are untouched,
  and `WebViewEvent` gains no case.

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserChrome.kt`

- `BrowserSecurityIdentity` replaces `val secure = ... == SECURE` with an exhaustive `when` over the
  four states, with no `else`, selecting one of four strings. The icon stays `ic_lock` for `SECURE`
  and `ic_warning` otherwise. Ground and roles unchanged.

### Modified: `app/src/main/java/app/webora/browser/siteskin/SiteSkinTopBar.kt`

- `SecurityIdentity` is deleted and replaced by `SiteSkinSecurityChip`, composed as a **fixed
  sibling inside the title `Row`, declared after the `weight(1f)` title `Column`**. A flexible
  sibling would let a long title push it off-screen; a fixed one takes its width first.
- The chip: `primaryContainer` ground, `WeboraRadius.PILL`, shield painter tinted `secure` or
  `notSecure`, the registrable domain at one line with `TextOverflow.Ellipsis`, a
  browser-authored `contentDescription`, and `SITESKIN_SECURITY_TAG` — **same constant, same value**,
  moved onto the chip's node.
- The `Column(verticalArrangement = spacedBy(8.dp))` wrapper collapses to the single title `Row`
  once the second child is gone.

### New: `app/src/main/res/drawable/ic_shield_secure.xml`, `ic_shield_neutral.xml`

Stroke-only, 1.9 weight, single colour, no fill, the shared viewport. Distinct internal marks — a
check inside the secure shield, a neutral mark inside the other — so state is never colour-only.

### Modified: `app/src/main/res/values/strings.xml`

- Add `security_unknown` and `security_tls_error`.
- Delete `siteskin_tls_secure`, `siteskin_tls_not_secure` and `siteskin_security_separator`. All
  three become unreachable when the row goes, and research is explicit: leave nothing behind that
  reads like a live contract. `security_secure`, `security_not_secure`, `security_identity` and
  `security_description` all stay and are shared by both modes.

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

- One line: `securityPresentation(state.mode)` becomes `securityPresentation(state.mode, state.transport)`.

## Rollout / versioning

No protocol change. `SPEC.md`, the JSON schema, `spec/diagnostics.json`, the conformance corpus and
the Bloom fixture are all untouched — this ticket adds no manifest field and changes no validation
rule, so none of `DEMO-001`'s five pinned copies moves. No migration: transport is unpersisted and a
restored tab re-earns it.

## Open questions

None. The `ADR-006` question is decided above with the repository owner; the storage location and
the glyph budget are decided above on the evidence research gathered.
