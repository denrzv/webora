# UX-011: Implementation plan
Status: PLAN_APPROVED

## Overview

Evolve the existing `BrowserNavigationDock` into the one persistent browser shell for Home/new-tab
and ordinary browsing. Add direct Tabs and explicit reload availability, centralize dock padding,
and compose Home content above it. Preserve the existing active-tab controller and system-back
boundaries, then lock the browser/manifest separation and accessibility geometry with tests.

## Flow

1. `BrowserScreen` selects the active tab and its controller exactly as today.
2. Home renders its scrollable search/record content with weight above the shared shell. It supplies
   false for Back, Forward, and Reload and opens the existing tab switcher/settings/inspector.
3. A regular page renders address/security chrome, WebView content, then the same shell. Observed
   active-tab Back/Forward state and the presence of a committed HTTP(S) page control enablement;
   actions dispatch only to the selected tab's controller.
4. The dock renders the closed browser-authored sequence Back, Forward, Reload, Home, Tabs, More.
   Overflow continues to expose Tabs for compatibility plus settings and inspector.
5. Integrated mode remains on its current SiteSkin bottom navigation and top-bar Back affordance;
   `UX-012` owns the later explicit transition contract.

## Trust and origin boundary

Home has no origin. Regular state contains the active tab's canonical browser-observed origin.
`BrowserNavigationDock` accepts only browser-observed booleans and browser-owned callbacks; it does
not accept a manifest, trusted SiteSkin configuration, arbitrary icon/label/style, URL, or action.
Its control labels and vector resources are bundled, its Material scheme is Webora-owned, and its
order is fixed in code.

A manifest therefore cannot suppress, relabel, reorder, restyle, enable, or dispatch the Home or
regular shell. SiteSkin remains capable only of replacing the integrated-mode bottom product slot
through the existing validated model. No origin comparison, manifest discovery, or action
resolution moves into UI code.

## System and security boundary

- Continue applying `WindowInsets.safeDrawing` exactly once at `BrowserScreen`'s root. The shell
  stays within that boundary and adds no system-navigation replica or extra inset consumption.
- Keep `BrowserBackHandler` registered through AndroidX `OnBackPressedDispatcher`; its enabled state
  and dispatch target come from the active tab only.
- Home's detached controller cannot receive Back/Forward/Reload because all three controls are
  disabled and their callbacks are inert browser-owned lambdas.
- No network, persistence, telemetry, permission, protocol, or core-module surface changes.

## File-by-file plan

### New `app/src/main/res/drawable/ic_tabs.xml`

Add a browser-bundled semantic tabs glyph on the existing 24 dp vector grid.

### Modified `app/src/main/java/app/webora/browser/browser/BrowserChrome.kt`

Add `canReload`, render direct Tabs in the fixed browser-owned order, tag the shell for layout
tests, and centralize its full-width gutter modifier in a shared wrapper.

### Modified `app/src/main/java/app/webora/browser/browser/HomeScreen.kt`

Remove the separate Tabs button and callback. Keep Home focused on scrollable content and
navigation destinations.

### Modified `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

Compose Home content and the shared shell in one column, wire real switcher/settings/inspector
actions, and route regular pages through the same wrapper with active-tab state.

### Modified tests and resources

Update `strings.xml`, `BrowserChromeTest`, `HomeScreenTest`, `BrowserFontScaleTest`, and source
contract tests. Assert command order/browser ownership, disabled Home actions, direct Tabs dispatch,
minimum target dimensions, compact-width visibility, double-font visibility, and single inset
ownership.

### Modified project documentation and reports

Record the persistent-shell architecture in `CLAUDE.md`, mark `UX-011` complete in the roadmap, and
produce review and QA artifacts after task implementation.

## Tests

- After each code task: `./gradlew :app:testDebugUnitTest`,
  `./gradlew :app:compileDebugAndroidTestKotlin`, and `./gradlew detekt`.
- Before each task commit: `bash scripts/pre-commit-check.sh`.
- If a device exists, run focused Compose instrumentation for Home, chrome, and 200% font scale.
  Without `/dev/kvm` or a connected device, report runtime gesture/three-button and screenshot
  evidence unavailable; do not create a software-only emulator.
- Review includes a negative source/contract test proving no manifest-controlled input reaches the
  Home/regular shell.

## Rollout / versioning

No schema, storage, migration, feature flag, or compatibility change. The existing tab/session
snapshot remains valid. The visual change applies to Home and regular browsing immediately.
