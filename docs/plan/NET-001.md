# NET-001 implementation plan

Status: PLAN_APPROVED

## Flow and trust boundary

A browser-observed main-frame page start is passed to a discovery coordinator. It first canonicalizes the URL as an exact HTTPS `SiteOrigin`; non-HTTPS or malformed pages produce no request. The app fetcher builds the fixed well-known URL, manually processes at most two redirects, and compares every target's canonical scheme/host/effective-port tuple with the starting origin. It bounds the call and response stream, then returns bytes without interpreting trust. The coordinator passes those bytes to `SiteSkinValidator`; only its accepted outcome carries a trusted configuration. Results are not applied to chrome in this ticket.

WebView rendering remains browser-owned and independent: `onPageStarted` notification returns immediately, while a lifecycle coroutine performs discovery on IO. A newer main-frame navigation cancels the prior job and stale results are ignored. Transport and validation failures collapse to an unavailable result and regular mode. Remote URLs, headers, and bodies are not logged or surfaced.

## Changes

1. Add a bounded, manual-redirect OkHttp `ManifestSource` implementation in `:app`, using shared core constants and explicit call/connect/read/write timeouts.
2. Add a pure/injectable discovery coordinator that canonicalizes observed URLs, cancels superseded work, validates bytes through the total core validator, and exposes only closed outcomes.
3. Connect main-frame page-start observation to discovery without delaying WebView callbacks or rendering; keep the result inert for later SiteSkin runtime tickets.
4. Add MockWebServer transport tests and coroutine coordinator tests, including negative controls.
5. Record review, QA, validation, and roadmap closeout artifacts.

## Security and privacy checks

- Automatic redirects disabled; every follow-up is exact-origin and HTTPS.
- Both declared and actual response sizes are bounded at 128 KiB.
- No URL/body/header logging and no telemetry.
- Cancellation is rethrown/propagated; ordinary I/O and policy failure are silent fallback.
- Core remains Android/OkHttp-free and remains the only trust promotion seam.

## Validation

- Focused app JVM tests for fetcher and coordinator.
- Full `bash scripts/pre-commit-check.sh` before every task commit.
- Negative controls recorded in the tasklist.
- Review, QA, and `/validate` closeout after implementation tasks.
