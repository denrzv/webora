# CI-002: Implementation plan
Status: PLAN_APPROVED

## Overview

Four changes, in dependency order:

1. **Build before boot.** Assemble both APKs in a normal workflow step, so the emulator's start-up
   never shares a runner with a Kotlin compiler. The in-emulator script asserts the APKs exist
   instead of silently rebuilding them.
2. **A readiness gate that observes.** `scripts/android-emulator-ready.sh` polls device conditions,
   requires a settle window of consecutive good samples under a deadline, and writes every sample to
   the artifact. Its verdict function is a pure shell function with a self-test.
3. **A capture-time interference guard.** Before each canonical screenshot the test reads the
   focused window from the device and refuses to photograph anything that is not Webora — dismissing
   only the one known System UI ANR dialog, and recording it when it does.
4. **One owner for the decision, reachable by the JVM gate.** The classification lives in a source
   directory shared by `test` and `androidTest` and absent from `main`, so `./gradlew test` proves
   it here and the device consumes the same code.

Nothing in `src/main` changes. No production behaviour, permission, dependency or trust boundary
moves.

## Flow

```
workflow step: assemble debug + androidTest APKs        ← no emulator running
        ↓
emulator action boots the AVD
        ↓
scripts/android-screenshot-ci.sh
   ├─ require both APKs on disk                          ← else fail loudly
   ├─ scripts/android-emulator-ready.sh                  ← settle window, deadline, artifacts/readiness.txt
   └─ gradle :app:connectedDebugAndroidTest              ← install + run only; nothing left to compile
             ↓
        LiveSiteScreenshotTest
             └─ for each capture:  dumpsys window → ScreenEvidencePolicy.focusVerdict()
                    ├─ OwnedByApp              → screenshot
                    ├─ DismissableSystemAnr    → press Wait, record, re-check (bounded)
                    └─ Blocked                 → fail with the observed window
```

## Data

**Trust boundary.** Not an origin boundary — evidence integrity (`docs/research/CI-002.md` →
*Browser-owned remainder*). The rule the code must make unbreakable:

> The harness may remove interference owned by `com.android.systemui`, and nothing else. Everything
> else on top of Webora — including anything owned by Webora — is a failure carrying the observed
> window.

That is an allow-list of one, in the shape `PROJECT_RULES.md` already requires of manifest handling:
unknown input is refused, never guessed at. There is no `else → dismiss` branch to write.

**The policy's input is OS-supplied, never website-supplied.** The verdict is computed from the
window title AOSP builds from a *process name* (`"Application Not Responding: " + processName`), not
from dialog text, page content or manifest fields. A website cannot reach it.

**No storage, no cache key, no persisted state.** Diagnostics are written through
`PlatformTestStorage` into the existing connected-test additional-output tree, which the workflow
already uploads — so `DEVX-002` still owns artifact layout and this ticket adds files without moving
any.

## Security

- **Origin binding:** unchanged. The journey still asserts the exact canonical
  `https://denrzv.github.io` consent identity and still grants consent by clicking the browser-owned
  `Allow`.
- **Allow-list:** one process name, one dialog shape. A System UI *crash* dialog is deliberately
  **not** dismissable — "the known dialog" is `Application Not Responding: com.android.systemui` and
  nothing else. Widening it is what the negative control exists to catch.
- **Fail closed:** an unparseable dump, a missing `mCurrentFocus`, two different focused windows, a
  missing or ambiguous `Wait` affordance, or exhausted dismissal attempts are all failures. There is
  no path where the guard cannot decide and the capture proceeds anyway.
- **No new privilege:** no workflow permission change, no secret, no new runtime permission, no new
  Gradle dependency. The dialog is reached through the `UiAutomation` connection the test already
  holds for `takeScreenshot()`.
- **No test hook in the product:** nothing is added to `src/main` to make automation easier. The
  guard reads the device, exactly as a person looking at the screen would.

## File-by-file plan

### Modified: `.github/workflows/android-screenshots.yml`
A `Build the app and Android-test APKs` step before the emulator action, running
`./gradlew :app:assembleDebug :app:assembleDebugAndroidTest`. The emulator step is unchanged apart
from the comment explaining why the build is no longer inside it. Trigger, permissions, concurrency,
pinned action SHA, timeout and upload globs stay as `CI-001` left them.

### Modified: `scripts/android-screenshot-ci.sh`
- `require_prebuilt_apks` — both APK paths must exist; missing means the pre-build step regressed,
  which is a loud failure rather than eight quiet minutes of rebuilding inside the emulator step.
- Invoke `scripts/android-emulator-ready.sh` before Gradle; a non-zero verdict fails the run after
  logcat and diagnostics are still collected.
- Keep the existing PNG collection, `result.txt` and `png_count == 0` failure exactly as they are.

### New: `scripts/android-emulator-ready.sh`
`readiness_verdict boot_completed bootanim_exit pm_path focus_line` → `ready` / a reason string.
Pure: no `adb`, no globals, no I/O. `collect_sample` runs the four `adb` calls; `main` loops until
`READY_SETTLE_SAMPLES` consecutive `ready` verdicts or `READY_DEADLINE_SECONDS` elapses, appending
every sample to `artifacts/readiness.txt` with a timestamp. Sourcing the file runs nothing
(`BASH_SOURCE`/`$0` guard), which is what lets the self-test call the verdict function directly.

### New: `scripts/android-emulator-ready-selftest.sh`
Sources the gate and asserts `readiness_verdict` over recorded samples: a fully ready device, each
individual condition missing, and a device whose focus is null. Run unconditionally by
`scripts/pre-commit-check.sh` — a self-test that only runs when someone remembers it is not a gate.

### Modified: `scripts/pre-commit-check.sh`
One `run` line for the self-test, placed with the other unconditional checks.

### New: `app/src/screenshotPolicy/java/app/webora/browser/evidence/ScreenEvidencePolicy.kt`
Pure Kotlin, no Android imports. `focusVerdict(dumpsysWindowOutput, appPackage): FocusVerdict` with
`OwnedByApp`, `DismissableSystemAnr(processName, title)` and `Blocked(reason)`. Parses every
`mCurrentFocus=Window{… u0 <title>}` occurrence, requires exactly one distinct title, then
classifies:

| Focused window title | Verdict |
|---|---|
| `<appPackage>/…` | `OwnedByApp` |
| `Application Not Responding: com.android.systemui` | `DismissableSystemAnr` |
| `Application Not Responding: <anything else>` | `Blocked` |
| `Application Error: <anything>` | `Blocked` |
| anything else, `null`, absent, or two different titles | `Blocked` |

### Modified: `app/build.gradle.kts`
Shares `src/screenshotPolicy/java` into both the `test` and `androidTest` source sets with
`java.srcDir` **and** `kotlin.srcDir` — the same pairing the existing `debugRelease` block needs,
for the same AGP 9 reason. `main` does not get it, so it cannot reach the APK.

### New: `app/src/test/java/app/webora/browser/evidence/ScreenEvidencePolicyTest.kt`
The JVM gate for the decision. Runs here, in CI's `android` job, and in `scripts/pre-commit-check.sh`.

### New: `app/src/androidTest/java/app/webora/browser/visual/ScreenEvidenceGuard.kt`
The device half. `requireAppOwnsScreen()`:
1. `uiAutomation.executeShellCommand("dumpsys window windows")` → text.
2. `ScreenEvidencePolicy.focusVerdict(text, targetPackage)`.
3. `OwnedByApp` → return. `Blocked` → `fail()` with the reason and write the dump to
   `diagnostics/window-<label>.txt`. `DismissableSystemAnr` → find a clickable node by view id
   (`android:id/button2`, then `android:id/aerr_wait`), require exactly one, record view id, text
   and title to `diagnostics/interference.txt`, click, re-check; at most two attempts.

`FLAG_REPORT_VIEW_IDS` is set once on the `UiAutomation` service info — without it
`findAccessibilityNodeInfosByViewId` returns nothing, which would look exactly like "no Wait button"
and fail an otherwise recoverable run.

### Modified: `app/src/androidTest/java/app/webora/browser/visual/LiveSiteScreenshotTest.kt`
`captureDeviceScreenshot` calls `guard.requireAppOwnsScreen(name)` after `waitForIdle()` and before
`takeScreenshot()`. Journey, node matchers, file names and storage path are untouched.

### Modified: `docs/SCREENSHOTS.md`
What may be dismissed, what never is, where readiness and interference diagnostics live, and what a
red run means now.

### Modified: `docs/ROADMAP.md`, `CLAUDE.md`
Tick `CI-002`; add the note recording the evidence-integrity rule and the shared source root, so a
later ticket does not "simplify" the allow-list or move the policy into `src/main`.

## Tests

| Test | What it proves | Negative control |
|---|---|---|
| `ScreenEvidencePolicyTest` — Webora ANR | a Webora-owned ANR is `Blocked`, never dismissed | add `app.webora.browser.debug` to the allow-list → this case must fail |
| — System UI ANR | the one known dialog is `DismissableSystemAnr` | — |
| — System UI *crash* | `Application Error:` is `Blocked` even for System UI | broaden the prefix set → must fail |
| — app window | `OwnedByApp` for `<pkg>/<activity>` | — |
| — absent / null / two distinct `mCurrentFocus` | `Blocked`, i.e. fails closed | drop the distinct-title check → the two-window case must fail |
| — a dump with no match at all | `Blocked`, not "ready" | make the parser default to `OwnedByApp` → several cases must fail |
| `android-emulator-ready-selftest.sh` | each readiness condition is load-bearing | drop one condition from `readiness_verdict` → its case must fail |
| `./gradlew :app:assembleDebugAndroidTest` | the device half compiles | — |
| `bash scripts/pre-commit-check.sh` | the whole gate, after every task | — |
| Hosted `Android screenshots` run | three clean frames, readiness and interference diagnostics present | — |

The hosted run is evidence, not a gate: `AGENTS.md` forbids a software-only emulator here, so the
device half is compiled locally and executed in CI. The *decision* is proven by JVM tests precisely
because the dismissal path may never fire once contention is gone.

## Rollout / versioning

No schema, manifest, spec or APK-visible change. `versionCode`, signing, variants and the release
workflow are untouched. The screenshot workflow stays `workflow_dispatch`-only; its artifact name,
paths and retention are unchanged so `DEVX-002` starts from the layout it planned against.

## Open questions

None blocking. Whether the System UI ANR survives the contention fix is answered by the hosted run,
and both answers leave this design correct: the pre-build removes the cause, the guard refuses to
photograph a contaminated frame either way.
