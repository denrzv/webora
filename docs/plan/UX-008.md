# UX-008: Implementation plan
Status: PLAN_APPROVED

## Overview
Add one browser-owned leading Back affordance to the existing integrated top bar. It is always
present, enabled only by browser-observed WebView history, and rendered in a fixed Webora-token
container so SiteSkin colours cannot disguise its ownership. Site navigation remains the sole bottom
bar and the identity column retains its current title/subtitle/security ordering.
## Flow
- discovery: unchanged; manifest discovery never controls navigation chrome.
- validation: unchanged; `SiteSkinConfiguration` remains trusted only for the existing branded
  projection and never gains a Back field.
- normalization: unchanged.
- UI state: `RegularBrowser` passes `state.canGoBack` and `controller::goBack` to `SiteSkinTopBar`.
  The top bar composes a fixed Back slot before the logo; at root it remains visible and disabled.
## Data
- No DTO, trusted-domain, storage, cache, protocol, or persistence changes.
- The manifest-controlled projection remains `SiteSkinTopBarModel` plus `SiteSkinColorScheme`.
  Browser navigation arrives as two separate parameters: browser-observed `canGoBack` and the
  browser controller callback. They are intentionally absent from the model.
## Security
- Origin binding: integrated activation remains keyed to the committed exact origin. Back traverses
  WebView history and is not resolved through the SiteSkin action/origin pipeline.
- Browser-owned contract: manifest data cannot suppress, reorder, relabel, restyle, or dispatch the
  control. The local closed drawable and `R.string.back` define its meaning; `WeboraIconButton`
  defines its target and semantics; `WeboraTheme` tokens define its visual container.
- Fallback: if history is unavailable, the stable affordance is disabled. If integrated mode cannot
  activate, regular chrome continues to own navigation exactly as before.
- The browser-authored `SITESKIN_SECURITY_TAG` row remains after title/subtitle in the same column.
