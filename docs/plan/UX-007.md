# UX-007: Implementation plan
Status: PLAN_APPROVED

## Overview and flow

Replace the independently arranged AlertDialog action slots with one browser-owned, full-width
vertical hierarchy: primary Allow, secondary Not now, tertiary Never for this site. The existing
dialog body, outside-dismiss behavior, callbacks, and runtime persistence remain unchanged.

## Trust and origin boundary

The canonical origin continues to come from the current origin-bound candidate and remains the
browser-authored title. Manifest influence ends at the existing `SiteSkinConsentModel` used by the
body. The new action block accepts callbacks only and reads its labels, order, colours, shapes and
spacing from browser code/resources/theme; there is no configuration/model parameter through which
a site can modify the trust decision presentation.

## File-by-file changes

### `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

Add a private `SiteSkinConsentActions` composable. Compose a full-width spaced `Column` containing
`WeboraButton` for Allow, an outlined browser wrapper for Not now, and `WeboraTextButton` for Never.
Pass the block as the dialog's confirm content, omit dismiss content, and retain
`onDismissRequest = onNotNow`. Do not change `SiteSkinConsentDetails` or runtime callbacks.

### `app/src/main/java/app/webora/browser/browser/BrowserAccessibility.kt`

Add a browser-token `WeboraOutlinedButton` wrapper with the same minimum interactive target and
disabled semantics as existing wrappers. Keep raw Material control usage confined to this file.

### `app/src/androidTest/java/app/webora/browser/browser/SiteSkinConsentDialogTest.kt`

Pin all three visible decisions and callbacks, outside dismissal, fixed top-to-bottom order,
full-width geometry, and minimum target height under a compact width. Retain exact-origin and
protected-copy assertions unchanged.

### `app/src/androidTest/java/app/webora/browser/browser/BrowserFontScaleTest.kt`

Constrain the dialog to compact phone width at 200% font scale and assert all three labels remain
displayed with minimum-height bounds.

### `CLAUDE.md`

Record the browser-owned adaptive consent action hierarchy and the prohibition on manifest control.

## Tests

- Focused Android-test compilation for Compose API correctness.
- Existing JVM/unit, lint and detekt suite via the pre-commit gate.
- Connected Compose tests and Pixel 6 screenshot only when suitable Android runtime exists.
- Negative controls during implementation: restore split confirm/dismiss slots; swap a callback;
  remove minimum-target/full-width modifiers and confirm the relevant tests fail.

## Rollout

No migration or feature flag. Existing decisions and subsequent activation behavior are byte-for-
byte unchanged; only first-use dialog presentation changes.
