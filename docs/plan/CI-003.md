# CI-003: Plan
Status: PLAN_APPROVED

Input: [`../research/CI-003.md`](../research/CI-003.md) (`RESEARCH_READY`).

## Flow

```
LiveSiteScreenshotTest
  … Allow, wait for SITESKIN_SECURITY_TAG + SITESKIN_BOTTOM_NAV_TAG (unchanged, semantics)
  captureDeviceScreenshot("03-siteskin-integrated.png", requirePageContent = true)
        │
        ├─ guard.requireAppOwnsScreen(label)          ← CI-002, unchanged, runs first
        │
        └─ guard.captureWhenRendered(label, region)   ← new
              loop until deadline:
                bitmap  = uiAutomation.takeScreenshot()
                samples = strided ARGB read of `region`
                verdict = RenderedContentPolicy.verdict(samples)   ← pure, JVM-tested
                  Rendered  → return this bitmap (the one that satisfied the check)
                  Blank     → record sample, sleep, retry
              deadline → write rendered-<label>.txt, throw
```

The page rectangle comes from the semantics tree — `onNodeWithTag(BROWSER_CONTENT_TAG)
.fetchSemanticsNode().boundsInWindow` — so the check measures the region the frame is evidence *of*,
not the whole screen. A frame cannot pass on the strength of its own navigation bar.

Order matters and is deliberate: **ownership first, content second.** `CI-002` decides whether the
screen may be photographed at all; only then does this ticket ask whether it is worth photographing.
Reversing them would poll pixels of a screen Webora does not own.

## Trust boundary

This is harness policy one layer above the manifest pipeline, but unlike `CI-002` it is **not**
website-independent, and the plan says so rather than inheriting a claim that does not hold.

`CI-002`'s focus classification reads window titles AOSP builds from a process name, so no website
text reaches it. A pixel check on the page region reads pixels **the website drew** — unavoidably,
because those pixels are the thing being verified. The achievable property is directional:

> **Website content can only make the check refuse, never permit.** A site rendering a blank page
> fails the capture and reddens the run. No page content can cause a capture that would otherwise
> have been refused, and none can relax `CI-002`'s ownership rule, which has already returned before
> this check begins.

That is fail-closed in the same direction as every other guard in this pipeline. The bounded
consequence — a red run on a genuinely blank page — is one we want: a reference integration that
renders nothing is a defect, and the run should say so.

Two further boundaries this ticket does not cross:

- **It measures, it does not repair.** If the top bar turns out to be drawn blank, the check on the
  *page* region will not hide it — the bar stays visible (or absent) in the published frame. Widening
  the measured region to include chrome, or waiting until the bar appears, would convert a product
  defect into a harness workaround. That is the same refusal `CI-002` made when it declined an `else`
  branch that dismisses whatever is in the way.
- **No `CI-002` behaviour changes.** `ScreenEvidencePolicy`, the readiness gate and the prebuilt-APK
  precondition are untouched. This ticket adds a condition and relaxes none.

No new network access, no new permission, no change to what is captured or where it is stored.

## Decisions on the research's open questions

| Question | Decision | Why |
|---|---|---|
| Statistic | Fraction of sampled pixels differing from the **modal** sampled colour | Matches `DEVX-002`'s ink counting; robust to any background colour, including the reference site's near-white `#FFF7FA`. Mean brightness would pass a uniformly grey blank screen |
| Stride | Every 4th pixel on both axes (1/16 of the region) | ~40k samples on a 1080-wide page region: enough for a stable modal colour, cheap enough not to contend with `system_server` |
| Threshold | **1%** of samples differ from the modal colour | Justified by what is being detected, not tuned: the failure is *nothing drawn* (≈0%), not *too little content*. A rendered Bloom Flowers page is far above 1%; a blank one is far below. The wide margin is the point — this is a liveness check, not a content-quality check, and a tight threshold would trade a real bug for flake |
| Which frames | `03-siteskin-integrated.png` only | Frame 01 is Home — Compose-only, no `WebView`, no page region. Frame 02's evidence is the consent dialog and its canonical origin; the dimmed page behind it is not what that frame exists to prove, and a scrim flattens exactly the statistic being measured |
| `BrowserErrorPage` in the region | Counts as rendered | It is browser-owned drawn content, and it is legitimately non-blank. Whether an error page is *correct* is the journey's assertions to decide; this check answers "did anything draw", and pretending an error page is a blank screen would make one failure impersonate another |

## Files

### New — `app/src/screenshotPolicy/java/app/webora/browser/evidence/RenderedContentPolicy.kt`

Pure, in the source set shared into `test` and `androidTest` and into no variant — the placement
`ScreenEvidencePolicy` already established, and the reason the rule can fail `./gradlew test` on a
machine with no `/dev/kvm`.

```kotlin
sealed interface ContentVerdict {
    data class Rendered(val differingFraction: Double) : ContentVerdict
    data class Blank(val differingFraction: Double, val modalColor: Int, val sampleCount: Int) : ContentVerdict
}

object RenderedContentPolicy {
    const val MINIMUM_DIFFERING_FRACTION = 0.01
    fun verdict(samples: IntArray): ContentVerdict
}
```

It takes an `IntArray` of ARGB values, **not** a `Bitmap` — an Android type would drag the policy
back into a source set the gate cannot compile, which is the whole reason this file exists separately
from the guard. An empty array is `Blank`, never an exception and never a pass: no samples is not
evidence of rendering.

### Modified — `app/src/androidTest/java/app/webora/browser/visual/ScreenEvidenceGuard.kt`

Gains `captureWhenRendered(label: String, region: Rect?): Bitmap`. Interaction only, per the existing
split: take a screenshot, read the region with a stride into an `IntArray`, hand it to the policy,
poll to a deadline, record. A `null` region means no content requirement — capture once and return.

Returns **the bitmap that satisfied the check**, so the caller saves the frame it verified rather
than taking a second screenshot that could differ from the one that passed.

On deadline: writes `diagnostics/rendered-<label>.txt` with every sample taken — fraction, modal
colour, sample count, elapsed — then throws, matching how `window-<label>.txt` explains a refused
capture. The file lands in the diagnostics artifact beside `CI-002`'s.

### Modified — `app/src/androidTest/java/app/webora/browser/visual/LiveSiteScreenshotTest.kt`

`captureDeviceScreenshot(name, requirePageContent = false)`; frame 03 passes `true`. When required,
the region is read from `BROWSER_CONTENT_TAG`'s semantics bounds and the bitmap comes from
`captureWhenRendered`; otherwise the existing single capture is unchanged.

### Modified — `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

`BROWSER_CONTENT_TAG = "browser_content"` on the `Box` at line 469 that wraps `HardenedWebView`.
A test tag in `main` beside `BROWSER_SECURITY_TAG` and `BROWSER_STATUS_TAG` — established pattern,
not a new exception. No behaviour change; `BrowserSurfaceConventionsTest` is unaffected because a
`testTag` is not a `Text(` or an accessible name.

## Tests

JVM, in `./gradlew test`, so `scripts/pre-commit-check.sh` and CI both carry them — criterion 4.

`app/src/test/java/app/webora/browser/evidence/RenderedContentPolicyTest.kt`:

| Test | Asserts |
|---|---|
| `aUniformRegionIsBlank` | every sample identical → `Blank`, fraction 0.0 |
| `aUniformWhiteRegionIsBlankToo` | the modal colour is whatever dominates; white is not special-cased |
| `aRenderedPageIsRendered` | 10% differing → `Rendered` |
| `justBelowTheThresholdIsBlank` / `atTheThresholdIsRendered` | the boundary is where the constant says, in both directions |
| `noSamplesIsBlank` | empty array → `Blank`, never a pass and never a throw |
| `oneStrayPixelIsNotRendering` | a single differing sample in 40k → `Blank` — the case that would let a cursor artefact or a compression fringe pass for a page |

**Negative control:** invert the comparison so any non-empty sample array returns `Rendered`.
`aUniformRegionIsBlank`, `justBelowTheThresholdIsBlank`, `noSamplesIsBlank` and
`oneStrayPixelIsNotRendering` must fail while the two positive cases still pass — proving the
positives cannot stand in for the rule. Recorded in the tasklist.

**Not verifiable here, and stated as such:** the guard's polling, the semantics-bounds read and the
hosted outcome need an emulator. `/qa` records them as instrumented evidence from a hosted run, never
promoted to a gate claim — `docs/accessibility/CONFORMANCE.md` sets that precedent for this
repository.

## Out of scope

The integrated chrome's own rendering, the inspector overlay (`DEVX-003`), frame selection, artifact
layout (`DEVX-002`, shipped), and any golden-image comparison. If the hosted run shows the top bar
still blank on a page that has demonstrably rendered, that is a product defect and gets its own
ticket — `/qa` criterion 8 requires the answer to be written down either way.
