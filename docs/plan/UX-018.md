# UX-018 plan — Opaque dismissible privacy modal

Status: PLAN_APPROVED

## Overview

Keep `PrivacySettingsScreen` as scrollable content and introduce a small
`PrivacySettingsDialog` host beside it. The host owns the modal window, full-size opaque Material
surface, safe insets, and dismissal. `BrowserScreen` renders that host instead of placing settings
content directly over the WebView.

## Flow

1. A browser-owned Settings command sets `settingsVisible`.
2. `PrivacySettingsDialog` opens a platform Compose `Dialog` with non-default full width.
3. A full-size `Surface` paints the app background and blocks the underlying browser window.
4. The existing scrollable settings content receives safe drawing padding inside that surface.
5. Close, outside dismissal policy, or Android Back invokes the same browser-owned `onDismiss`
   callback and clears `settingsVisible` before the underlying browser handles Back.
6. Clear browsing data continues to open its explicit confirmation above settings; cancel returns to
   the still-open settings dialog.

## Origin and trust boundary

No website-controlled capability enters this flow. The current page origin may remain visible only
in the underlying WebView, which is fully covered and input-blocked. Canonical origins in stored
consent rows are browser persistence data, not styling or lifecycle commands. Webora owns dialog
visibility, background palette, geometry, insets, labels, callbacks, clear-data confirmation, and
dismissal. Manifest colors/assets remain structurally outside the dialog.

## Security and accessibility

- Use a real modal window so pointer and Back dispatch cannot fall through to WebView/history.
- Use `MaterialTheme.colorScheme.background`, not active SiteSkin presentation roles.
- Apply `WindowInsets.safeDrawing` exactly once within the dialog window.
- Preserve vertical scrolling, localized content, named controls, and 200% font-scale coverage.

## File-by-file plan

### Modified: `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt`

- Replace direct sibling composition with `PrivacySettingsDialog`.
- Pass one dismissal callback and stop passing the underlying window's inset modifier.

- Prove Android Back invokes dialog dismissal and removes settings before underlying navigation.
