# CI-005: Plan
Status: PLAN_APPROVED

Input: [`../research/CI-005.md`](../research/CI-005.md) (`RESEARCH_READY`).

## Flow

```
before                                     after
──────                                     ─────
requireAppOwnsScreen(label)                requireAppOwnsScreen(label)      ← unchanged, CI-004 owns it
captureWhenRendered(label, region, …)      captureWhenRendered(label, region, …)
  while (before deadline)                    while (before deadline)
    bitmap = takeScreenshot()                  bitmap = takeScreenshot()
    content = verdict(sample(bitmap))          content = verdict(sample(bitmap))
    Rendered → record; RETURN bitmap ✗         Rendered → focus = focusVerdict(readWindowDump())
    Blank    → record sample                             candidateVerdict(focus, content)
    sleep                                                  Accept        → record; RETURN bitmap
                                                           Retry(reason) → record; keep polling
                                             Blank    → record sample     ← no dump, unchanged cost
                                             sleep
```

**One dump per *passing* candidate, none per blank poll.** Research §4: the loop can run forty times
and a naive per-iteration check would multiply dump traffic by forty, against a System UI whose ANR
on run 13 was raised by its own dump service. Blank polling stays exactly as cheap as it is today.

## Trust boundary

**No origin is contacted, no manifest is parsed, and no website-controlled value reaches any decision
here.** Recorded explicitly per `PROJECT_RULES.md`: the ticket adds no website-controlled capability
and no path for one.

The boundary it serves is `CI-002`'s — *what the harness may hide from the person looking at the
picture* — and this plan is bound by it in four ways.

- **The change may only ever make the harness refuse more.** Every edit here adds a condition to
  acceptance. If any change could make a frame acceptable that is rejected today, it is the wrong
  change. This is the ticket's single strongest constraint and the one to check a diff against.
- **Ownership is read from the OS, never from pixels.** Research §3 refuses pixel inference: it is
  the recognise-it-by-looks heuristic `CI-002` rejected, it cannot separate a System UI ANR from a
  Webora crash dialog, and a website controls the third thing it would confuse them with. Ownership
  stays `dumpsys window` → `ScreenEvidencePolicy.focusVerdict`.
- **The obstruction is a reason to refuse, never a region to exclude.** Masking the dialog's rect out
  of the measurement would score a page that is still blank and still covered. `excluded` keeps its
  existing meaning — browser-owned chrome composed inside the page box — and gains nothing.
- **The threshold is not touched.** The blank page measured `0.0023` and the obstruction `0.3048`; no
  bar separates them, so raising `MINIMUM_DIFFERING_FRACTION` fixes nothing and would weaken a check
  that is working correctly on the wrong region.

## Security / integrity

| Rule | Mechanism |
|---|---|
| The frame saved is the frame validated | ownership is asserted on the returned bitmap, not only before polling |
| Both existing policies keep their contracts | `candidateVerdict` **composes** `FocusVerdict` and `ContentVerdict`; neither is edited, and both fixture suites pass unedited |
| No new way to give up | `CandidateVerdict` has `Accept` and `Retry` only — the deadline already owns "stop", and a third case would be a second place to decide the run is over |
| The deadline is not extended | discarded candidates consume it like any other poll; no compensation for time lost to a contested screen |
| A discarded candidate costs no dismissal budget | `captureWhenRendered` never dismisses; the budget lives in `requireAppOwnsScreen` and is untouched |
| Gate-testable | `candidateVerdict` is pure, in `src/screenshotPolicy/java`, run by `./gradlew test` with no emulator |

## Files

### New: `app/src/screenshotPolicy/java/app/webora/browser/evidence/CandidateVerdict.kt`

```kotlin
/** Whether the bitmap just taken may be kept as evidence. */
sealed interface CandidateVerdict {
    data object Accept : CandidateVerdict
    data class Retry(val reason: String) : CandidateVerdict
}

fun candidateVerdict(focus: FocusVerdict, content: ContentVerdict): CandidateVerdict
```

| `focus` | `content` | Verdict |
|---|---|---|
| `OwnedByApp` | `Rendered` | `Accept` |
| `OwnedByApp` | `Blank` | `Retry("the page region has not rendered")` |
| `DismissableSystemAnr` | any | `Retry("$title owned the screen when the frame was taken")` |
| `Blocked` | any | `Retry(reason)` — carries the blocking reason through |

Two properties worth stating because they are what a later edit would break:

- **Content never decides alone.** `Rendered` appears in exactly one accepting row, and it is the row
  where Webora also owns the screen. That is the defect, expressed as a table.
- **A dismissable ANR is still a `Retry` here, not a dismissal.** `captureWhenRendered` must not
  press anything; clearing obstructions is `requireAppOwnsScreen`'s job and `CI-004`'s ticket. If the
  dialog persists, the deadline fails the run and the *next* frame's `requireAppOwnsScreen` will deal
  with it.

### Modified: `app/src/androidTest/java/app/webora/browser/visual/ScreenEvidenceGuard.kt`

`captureWhenRendered` reads the window dump **only** when content passes, classifies it with the
existing `focusVerdict`, and asks `candidateVerdict`. `Accept` returns the bitmap; `Retry` appends a
sample line and keeps polling. The final failure message distinguishes *never rendered* from
*rendered but contested*, so the next reader is not sent back to first principles — research risk 1.

`requireAppOwnsScreen`, `dismissSystemAnr`, `sampleRegion`, `renderedReport` and every constant are
untouched. `CI-004` edits the first two; these two tickets share a file and no function.

### Modified: `rendered-<label>.txt`

Gains a line per candidate discarded for ownership, and states on the accepted frame that ownership
was verified:

```
attempt=4 elapsed=4143ms differing=0.3047 modal=#ff1a1a1a REJECTED focus=Application Not Responding: com.android.systemui
PASSED differing=0.7530 after 5210ms owner=app.webora.browser.debug/app.webora.browser.MainActivity
```

Per-attempt ownership for *blank* attempts is deliberately absent — it would need the dump per poll
that §4 rules out. The honest record is "verified on the frame that was kept", plus every rejection.

## Tests

| Test | Asserts |
|---|---|
| `ownedAndRenderedIsAccepted` | the one accepting combination |
| `renderedUnderASystemDialogIsRetried` | `DismissableSystemAnr` + `Rendered` → `Retry`; **run 14's exact case** |
| `renderedUnderABlockedScreenIsRetried` | `Blocked` + `Rendered` → `Retry`, carrying the reason |
| `ownedButBlankIsRetried` | today's behaviour survives |
| `everyRetryCarriesAReason` | no empty reason reaches the record |
| `contentAloneNeverAccepts` | swept over every `FocusVerdict`: `Rendered` accepts **only** with `OwnedByApp` |
| `ScreenEvidencePolicyTest`, `RenderedContentPolicyTest` | unchanged and green, unedited |

**Negative control — and it must reproduce an interleaving, not a state** (research risk 4). A
sequence test drives the run-14 order: `Blank`, `Blank`, `Blank`, then `Rendered` while focus is the
System UI ANR. With `candidateVerdict` reverted to "content decides", the sequence is accepted and
the test fails. This is the control that matters, because feeding a contaminated pair to a pure
function proves the function while the defect was in *when* the function is called.

**Second negative control:** make `Blocked` + `Rendered` accept. `renderedUnderABlockedScreenIsRetried`
must fail alone, proving the System UI case is not standing in for every non-owned focus.

**Not verifiable here:** that a contested capture is now retried on a real device. Hosted run,
recorded as instrumented evidence, never promoted to a gate claim.
