# NET-003 — Brand asset pipeline implementation plan

Status: PLAN_APPROVED

## Overview

Add a narrow app-layer pipeline that turns one trusted `SiteSkinConfiguration` into a closed brand
asset result. It owns transport, format validation, bounded Android decoding, fallback, and request
lifecycle. It deliberately does not render the result or apply SiteSkin mode.

## Flow

1. `BrandAssetLoader` derives a deterministic monogram from trusted bounded site identity before
   starting remote work, so every non-cancellation failure has an immediate complete fallback.
2. If the trusted configuration has no logo, it returns that fallback without network work.
3. `OkHttpBrandAssetSource` re-parses the trusted configuration origin and logo URL, requires HTTPS
   and exact `SiteOrigin` equality, and manually follows at most two exact-origin redirects.
4. A successful response must declare exactly PNG or WebP. The source rejects a known oversized
   body and reads only through a 512 KiB plus one-byte sentinel.
5. Pure signature inspection must agree with the declared media type before bytes reach Android.
6. A decoder probe obtains format and dimensions without allocating the bitmap. The loader rejects
   invalid, mismatched, zero, over-axis, overflowing, or over-pixel bounds, then performs one full
   decode and returns only a non-null bitmap.
7. `BrandAssetCoordinator` owns at most one coroutine job, cancels superseded/disposed work, and
   checks cancellation before publishing. Cancellation publishes nothing; other failures already
   resolve to the browser-owned monogram.

## Data and trust boundary

The input is a validator-constructed `SiteSkinConfiguration`, not a DTO or raw manifest. Its
`origin`, `branding.logoUrl`, `site.shortName`, and `site.name` are trusted normalized values, but
the network response remains untrusted. Rechecking URL provenance at the fetch boundary prevents a
future caller from accidentally separating a trusted URL from its origin.

The website can select only a same-origin path and the remote bytes. The browser owns request
construction, redirects, timeouts, MIME allow-list, signature parser, size/dimension policy,
decoder implementation, dispatcher, fallback derivation, and lifecycle. The output hierarchy is
closed: `BitmapAsset(Bitmap)` or `Monogram(String)`. It carries no URL, MIME string, SVG, stream,
decoder selector, or executable content into later UI.

No persistent storage or cache key is introduced. If a later ticket caches decoded assets, the key
must include the complete canonical origin and trusted absolute asset URL and must not weaken this
pipeline.

## Security

- **Origin binding:** both initial URL and every redirect compare complete canonical `SiteOrigin`
  values. Subdomains, ports, schemes, and credentials cannot cross the boundary.
- **Allow-list:** only exact normalized `image/png` and `image/webp` media types and matching PNG or
  RIFF/WebP signatures proceed. SVG is rejected even if mislabeled.
- **Resource bounds:** 512 KiB transfer, 1024 pixels per axis, and 1,048,576 total pixels. Pixel
  multiplication is performed in `Long`.
- **Threading/cancellation:** source and Android decoder run on `Dispatchers.IO`; async OkHttp calls
  cancel at the socket when the coroutine is cancelled. Superseded jobs cannot publish.
- **Fallback:** missing, rejected, malformed, timed-out, oversized, or undecodable input becomes a
  deterministic monogram. Cancellation is rethrown/suppressed rather than misreported as failure.
- **Privacy:** no response body, URL, origin, or remote metadata is logged.

## File-by-file plan

### New: `app/src/main/java/app/webora/browser/siteskin/BrandAsset.kt`

Define the closed output hierarchy, limits, allowed formats, pure byte-signature recognition,
dimension policy, and deterministic Unicode-safe monogram derivation.

### New: `app/src/main/java/app/webora/browser/siteskin/OkHttpBrandAssetSource.kt`

Define a narrow source result and implement exact-origin HTTPS fetch, manual bounded redirects,
MIME policy, sentinel reads, explicit timeouts, and coroutine/OkHttp cancellation.

### New: `app/src/main/java/app/webora/browser/siteskin/BitmapBrandAssetDecoder.kt`

Define the injectable decoder contract and thin `BitmapFactory` implementation. Use
`inJustDecodeBounds` for the probe and only perform full decode after loader policy accepts bounds.

### New: `app/src/main/java/app/webora/browser/siteskin/BrandAssetLoader.kt`

Orchestrate trusted input, fallback, source result, signature/type agreement, dimension checks,
decode, exception policy, and off-main execution.

### New: `app/src/main/java/app/webora/browser/siteskin/BrandAssetCoordinator.kt`

Own one cancellable load job and suppress stale/cancelled publication for later composition use.

### New: `app/src/test/java/app/webora/browser/siteskin/BrandAssetPolicyTest.kt`

Cover PNG/WebP signatures, disguised SVG/short input, dimension ceilings/overflow, and monograms.

### New: `app/src/test/java/app/webora/browser/siteskin/OkHttpBrandAssetSourceTest.kt`

Use MockWebServer TLS to cover allowed responses, exact-origin redirects, redirect limits,
subdomain/port/cross-origin rejection, media types, byte sentinel, timeouts, and cancellation.

### New: `app/src/test/java/app/webora/browser/siteskin/BrandAssetLoaderTest.kt`

Use fake source/decoder seams to cover absent logos, type mismatch, bounds-before-full-decode,
successful bitmap, every failure fallback, exception fallback, and cancellation propagation.

### New: `app/src/test/java/app/webora/browser/siteskin/BrandAssetCoordinatorTest.kt`

Use coroutine test scheduling to prove superseded and cancelled requests do not publish and current
fallback/success results do.

### New: `app/src/androidTest/java/app/webora/browser/siteskin/BitmapBrandAssetDecoderTest.kt`

Exercise real `BitmapFactory` probe/full decode with a small generated PNG. Compile this test in
managed cloud; run it only when a connected device is available.

### Modified: `CLAUDE.md`, `docs/ROADMAP.md`, reports and ticket artifacts

Record the resulting browser-owned asset contract and close out review, QA, and validation.

## Tests

- Focused policy/transport/orchestration: `./gradlew :app:testDebugUnitTest --tests 'app.webora.browser.siteskin.*BrandAsset*'`.
- Instrumentation compilation: `./gradlew :app:compileDebugAndroidTestKotlin`.
- Runtime instrumentation when hardware exists: `./gradlew :app:connectedDebugAndroidTest`.
- Full task gate: `bash scripts/pre-commit-check.sh`.
- Negative controls: remove origin equality, signature agreement, byte sentinel, or dimension check,
  and allow stale coordinator publication; the corresponding focused test must fail.

## Rollout / versioning

Additive app-internal code only. No schema, protocol diagnostic, permission, public core API, cache,
or visible UI changes. Failed loading leaves later rendering with a monogram and regular browsing
unchanged.

## Open questions

None. Limits and decoder seam are approved here; changing them during implementation requires a
plan update before code changes.
