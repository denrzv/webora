## Overview
Extend the existing live screenshot test after its accepted integrated frame. Use the fixed,
browser-owned Back affordance to leave Bloom, submit `example.com` through Webora's visible address
field, wait for the complete regular chrome layer set, and capture `04-regular-browsing.png` through
the unchanged ownership/rendered guard. Generalise the contact-sheet test fixture to pin all four
ordered frames, update the human-facing inventory, and let the existing dynamic count flow report four.

## Flow
1. Run the unchanged cold Home → Bloom consent → accepted integrated journey and capture frames 01–03.
2. Assert integrated identity/navigation are present before departure.
3. Invoke the visible browser-owned Back affordance, wait for Webora's address input, enter
   `example.com`, and perform its IME Go action.
4. Wait for `BROWSER_SECURITY_TAG` and `BROWSER_NAVIGATION_SHELL_TAG`; require their displayed state
   and the expected browser-authored `Secure · example.com` identity.
5. Assert `SITESKIN_SECURITY_TAG`, `SITESKIN_BOTTOM_NAV_TAG`, and `SITESKIN_QUICK_ACTIONS_TAG` do not
   exist. Only then capture `04-regular-browsing.png` with page rendering required.
6. The existing emulator collector copies all four PNGs, the composer discovers them in filename
   order, and the workflow compares `tiles=4` with the collected `png_count=4` before publishing.

## Origin and trust boundary
`https://denrzv.github.io` and `https://example.com` are distinct exact origins. Bloom's trusted
manifest may affect only the already-accepted integrated presentation. It cannot choose the ordinary
destination, frame filename, semantic predicates, capture verdict, contact-sheet caption, or job
count. The example response is untrusted page content; no title, body text, colour, or layout from it
is an acceptance signal.

Only browser observations may project `BrowserMode.Regular` and render the stable browser identity
and navigation tags. The transition is accepted only when browser-owned regular layers exist and all
three SiteSkin layer tags from the previously proven integrated state are absent. This preserves
`UX-012`'s mutual exclusion and `ADR-006`'s security ownership rather than inferring mode from page
pixels. Exact origin comparison, manifest discovery, consent, and validation are unchanged.

## Security and evidence integrity
- Keep `ScreenEvidenceGuard`, its ownership policy, render threshold, deadline, exclusions, and
  dismissal allow-list byte-for-byte unchanged.
- Capture the bitmap returned by the existing combined ownership/render check; never take a second
  unchecked screenshot.
- Wait for app state reached through visible browser controls; do not seed state, inject a controller
  URL, hide UI, dismiss arbitrary windows, or add a screenshot mode.
- Derive the regular identity from browser-observed origin state and assert fixed browser resource
  text. Do not trust page or manifest labels.
- Continue deriving contact-sheet captions solely from filenames and comparing discovered tile count
  against actual collected PNG count.
- Retain diagnostics in their separate artifact and full-device canonical frames at the review root.
