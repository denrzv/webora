# CI-009: Implementation plan
Status: PLAN_APPROVED

## Overview
Expand the already-complete DEMO-005 interaction into eight guarded canonical frames. The test will
photograph the storefront, product, both browser-history restorations, and native hub at their actual
action seams, then retain final regular teardown. Pure source and contact-sheet tests pin the ordered
inventory. Reviewer docs and final architecture notes will describe the accepted M9 story.

## Flow
1. Capture native Home and first-use consent exactly as today.
2. After normal manifest discovery, validation, consent, asset loading, and exact-origin activation,
   require expressive identity/dock and capture the rendered Bloom storefront.
3. Use the accessible live product link, re-require integrated chrome, and capture rendered Happy
   Days product detail.
4. Require the browser-owned dock Back control displayed/enabled, click it, re-require integrated
   chrome, and capture the restored storefront.
5. Require the browser-owned dock Forward control displayed/enabled, click it, re-require integrated
   chrome, and capture the restored product.
6. Open the hub through its fixed dock control; require its Compose tag and browser-authored `Site
   navigation` / `Webora controls` headings plus expected trusted bounded items; capture the rendered
   page behind the native hub.
7. Select trusted Home, return through browser-owned history to native Home, enter `example.com`,
   require ordinary chrome and complete expressive/hub absence, then capture rendered regular mode.
8. Collection remains glob-based. The composer sorts the zero-padded filenames, and workflow YAML
   compares its emitted `tiles=8` against the eight collected PNGs before upload.

## Origin boundary and browser-owned contract
The only integrated origin is `https://denrzv.github.io`; manifest, brand asset, storefront and
product route are same-origin. `https://example.com` is a distinct regular origin. CI-009 does not
alter discovery, origin comparison, consent, validation, normalization, activation, or teardown.

Remote content may influence only the already-trusted bounded SiteSkin projection and the pixels in
the WebView rectangle. `Happy Days Bouquet` is permitted solely as an accessibility locator for a
normal remote link. It cannot authorize integrated mode, name a frame, caption a tile, or pass a
capture. Those decisions require browser-owned tags/resources and the existing full-device guard.
The native hub must be identified by its Compose tag and browser-authored section headings, not by
page resemblance or site item labels alone. Final teardown requires browser identity/navigation
presence and explicit absence of expressive header, dock, hub, and legacy quick-action surfaces.

## Data
- No DTO, domain, protocol, persistence, network, or cache change.
- Eight zero-padded filenames are the closed evidence inventory and sole caption source:
  `01-home.png`, `02-siteskin-consent.png`, `03-bloom-storefront.png`,
  `04-happy-days-product.png`, `05-bloom-storefront-back.png`,
  `06-happy-days-forward.png`, `07-siteskin-hub.png`, and `08-regular-browsing.png`.
- The frame list belongs in a JVM-testable contract rather than production or manifest state.

## Security
- Keep `ScreenEvidenceGuard`, focus/ANR dismissal policy, page-content threshold, exclusions,
  candidate verdict, deadlines, and returned-bitmap write path unchanged.
- Every WebView-bearing frame uses `requirePageContent = true`; Home and consent retain their
  documented exceptions because they evidence native Home and the browser-owned dialog.
- Never inject a URL/controller state, seed consent/history, add a JavaScript bridge, hide UI,
  dismiss arbitrary windows, infer trust from remote prose, or take an unchecked second bitmap.
- Require browser controls displayed and enabled immediately before Back/Forward clicks. Assertions
  may make an existing run refuse earlier but may never permit a previously rejected capture.
- Missing, duplicated, undecodable, reordered, or partially composed evidence fails closed through
  the pinned source inventory, composer tests, and existing runtime PNG/tile cardinality comparison.

## Tests
- For each code/test change run focused `./gradlew :app:testDebugUnitTest`,
  `./gradlew :evidence-sheet:test`, and/or `./gradlew :app:compileDebugAndroidTestKotlin` as relevant,
  plus linters (`./gradlew detekt`; ShellCheck/YAML extraction remains in the repository gate).
- Mutate/remove one required filename or reorder captures and prove the JVM source contract fails,
  then restore it. The unsafe fixture must prove retired navigation cannot authorize the story.
- Contact-sheet tests use eight distinct marker colours to prove sorting and totality, verify caption
  ink per tile, and require `tiles=8` for the canonical directory.
- Run `bash scripts/pre-commit-check.sh` before every task commit.
- If no `/dev/kvm` or connected device exists, compile instrumentation and report local runtime and
  screenshots as an environment limitation; do not provision a software-only emulator.
- Final QA dispatches the committed branch twice from cold hosted runners. Both runs must publish
  eight uncontested PNGs, an eight-tile preview, matching rendered/focus/window diagnostics, and no
  incomplete artifact. Record run ids, commit SHA, and human visual verdict.
