# UX-017 plan — Branded integrated dock and coordinated lower edge

Status: PLAN_APPROVED

## Flow

For the selected tab's exact-origin `BrowserMode.Integrated`, continue deriving one
`ExpressiveSiteSkinPresentation` from the trusted configuration and platform theme/motion inputs.
Continue loading the logo once in `BrowserScreen`, publishing it only through the configuration
identity guard. Pass that current bounded asset into `SiteSkinDock`.

The dock keeps its fixed five equal slots. Four browser commands become transparent content over the
guarded `secondary` pill with guarded `onSecondary` foreground. The center slot uses a dedicated
browser-owned circular control: guarded `primary` surface, stable compiled geometry, decorative
bitmap/monogram content, and the unchanged browser-authored Brand Hub semantics/callback.

Keep the current sibling layout: top chrome, status, weighted WebView/error region, then the dock.
This reserves the dock's measured height before `safeDrawing` is consumed once at the outer shell.
Regular/Home continues through `BrowserNavigationShell`; no persistent SiteSkin navigation is added.

## Origin and trust boundary

The presentation exists only while the selected state holds an authorized exact HTTPS origin and its
trusted `SiteSkinConfiguration`. Colors have passed core contrast guarding. A bitmap has passed the
existing same-origin, MIME, byte, dimension, decode, and configuration-identity publication gates.
A monogram derives from bounded validated site identity. Hub items remain normalized semantic tokens
and typed `NavigationItem`s.

The browser owns command count/order, labels, local Back/Forward/Tabs/More icons, enabled states,
callbacks, circle/pill/slot geometry, minimum targets, asset clipping, fallback order, layout
reservation, inset consumption, and teardown. No raw manifest URI/color/resource/layout directive
enters a new seam. Leaving the mode makes the branded projection structurally unreachable.

## Security and accessibility

- Render a remote-derived bitmap only inside the Brand Hub slot; never use it for browser commands or
  security identity, and never initiate another fetch.
- Preserve `publishesBrandAsset` identity checks and use only the already guarded current asset.
- Keep logo pixels decorative; the enclosing hub button supplies the localized semantic action.
- Preserve literal browser drawables and fixed call order as a negative control against manifest
  command influence.
- Use guarded content roles and a non-color enabled semantic state; retain at least 48 dp per control.
- Keep the closed site-icon map and generic fallback. Expose its pure resource lookup as `internal`
  only for direct deterministic tests.

1. `app/.../siteskin/SiteSkinDock.kt`
   - accept the current `BrandAsset`;

     content color;

     fallback rendering.
2. `app/.../browser/BrowserScreen.kt`
   - pass the configuration-guarded current brand asset into the protected integrated dock;
   - retain the sibling content/dock layout and neutral branch.

   - keep the existing closed semantic map and make the pure fallback lookup internally testable.
4. `app/src/androidTest/.../SiteSkinDockTest.kt`
   - assert five targets/order/geometry, palette continuity, bitmap and monogram center identity,
     stable fallback geometry, semantic hub description, and disabled behavior at 320 dp/200%.
5. `app/src/androidTest/.../BrowserSiteSkinLayoutTest.kt`
   - measure that the content region ends before the dock, persistent SiteSkin navigation is absent,
     and regular mode removes branded dock/reservation.
6. `app/src/test/.../SiteSkinNavigationContractTest.kt` and focused icon tests
   - pin literal browser command inventory/order, sole hub asset seam, supported Bloom semantic
     mappings, and deterministic unsupported fallback.
7. Workflow, review, QA, shared architecture, and evidence artifacts
   - document the stable ownership/layout contract and available runtime evidence.
