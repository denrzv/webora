# UX-012 — Mode-aware chrome handoff plan

Status: PLAN_APPROVED

## Flow

1. Browser observations synchronously update only their owning tab's `BrowserState`.
2. Exact-origin changes turn an integrated mode into regular mode before the state is published.
3. The selected tab's `BrowserMode` is projected through one exhaustive pure chrome-handoff model.
4. `BrowserScreen`/`RegularBrowser` render the top, quick-action, and bottom layers authorised by that
   projection; Home and regular share the existing browser shell, integrated uses SiteSkin's bottom
   slot and browser-protected top layer.
5. Consent refusal makes no activation transition. Consent acceptance can activate only a still-
   current candidate. Selecting another tab immediately changes the source state for the projection.
6. Existing `OnBackPressedDispatcher` integration remains independent of visible bottom chrome.

## Origin and trust boundary

The main-frame URL observed from the WebView is the sole runtime origin input. `SiteOrigin` exact
scheme/host/port equality remains the activation and retention boundary. A trusted manifest can
populate SiteSkin presentation only after browser-owned validation and consent; it cannot construct
`BrowserMode`, select the active tab, or influence the chrome-handoff projection. Home and regular
states expose browser chrome. Integrated state alone exposes site bottom navigation/actions, while
its top layer always includes browser-authored domain/TLS identity and Back. Inactive tab state,
stale candidates, and stale assets have no authority over the selected tab's projection.

## Security and accessibility

- Use a closed enum/sealed projection rather than independent booleans that can authorise conflicting
  chrome layers.
- Keep security identity and escape as an indivisible browser-protected integrated top layer.
- Retain the existing closed SiteSkin action resolver and do not expose raw manifest commands.
- Retain accessible labels, fixed 48 dp targets, test tags, safe-drawing inset ownership, and existing
  system/predictive Back dispatch.
- Add negative controls for manifest suppression and for projecting a previous tab instead of the
  currently selected tab.
