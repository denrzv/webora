## Tasks

- [x] TASK-1: Lift the WCAG contrast helper where both palettes reach it
  - New: `app/src/main/java/app/webora/browser/design/WcagContrast.kt`
  - **Deviation:** the plan named the file `Contrast.kt`. Detekt's `MatchingDeclarationName` requires
    a file with one top-level classifier to be named after it, and the file declares `object
    WcagContrast` alongside the `contrastRatio` function. Renamed rather than split — the thresholds
    and the ratio that measures against them belong together.
  - Modified: `app/src/main/java/app/webora/browser/siteskin/SiteSkinTheme.kt`,
    `app/src/test/java/app/webora/browser/siteskin/SiteSkinThemeTest.kt` (import only)
  - `contrastRatio`, `relativeLuminance` and their sRGB constants move verbatim; the private
    `BODY_CONTRAST` / `UI_CONTRAST` become `WcagContrast.BODY_TEXT` / `WcagContrast.NON_TEXT`.
  - Acceptance: the move is behaviour-preserving — `SiteSkinTheme`'s projection, guard, defaults and
    dark derivation are untouched, and no call site changes except its import.
  - Tests: `SiteSkinThemeTest` passes unchanged, including its 10 curated failure modes and the
    120-case seeded sweep. It keeps its own `4.5` / `3.0` literals rather than importing the shared
    ones — a test that shares a threshold with production stops asserting it the day someone lowers it.

- [ ] TASK-2: The browser colour role model, measured
  - New: `app/src/main/java/app/webora/browser/design/WeboraColorScheme.kt`,
    `app/src/test/java/app/webora/browser/design/WeboraColorSchemeTest.kt`
  - Fourteen roles, two compiled projections, values transcribed from `ADR-013` and
    `docs/design/directions/index.html:437-455`. No factory taking an argument.
  - Acceptance: every pair in the plan's contrast table clears 4.5:1 body / 3:1 non-text in **both**
    projections, and the published `ADR-013` figures (12.44 / 6.80 / 7.65 light, 10.49 / 7.94 / 8.50
    dark) come out of the code rather than out of the document. `divider` and `scrim` are the only
    exemptions and each carries a written reason.
  - Tests: `WeboraColorSchemeTest` — the pair table; a completeness assertion reflected over the
    declared roles; an assertion that every exemption has a non-blank reason.
  - **Negative control:** add a fifteenth role with no table entry → completeness fails. Record the
    result here.

- [ ] TASK-4: `WeboraTheme`, and no Material default behind it
  - New: `app/src/main/java/app/webora/browser/design/WeboraTheme.kt`,
    `app/src/test/java/app/webora/browser/design/WeboraThemeTest.kt`
  - New: `app/src/main/res/values-night/themes.xml`
  - Modified: `app/src/main/java/app/webora/browser/MainActivity.kt`
  - `WeboraTheme(darkTheme = isSystemInDarkTheme(), content)` supplies `MaterialTheme` with the
    derived `ColorScheme`, `Typography` and `Shapes`. `darkTheme` is a parameter with the framework
    read as its default, so a test can pass the other value.
  - Acceptance: every Material colour role is assigned from a browser role and the mapping contains
    no `Color(...)` literal; the night theme gives `Theme.Webora` a dark platform parent so the
    pre-composition frame and the system-bar regions agree with the palette.
  - Tests: `WeboraThemeTest` — colour closure over the derived `ColorScheme`; size closure over
    `Typography`; corner closure over `Shapes`; light and dark are distinct.
  - **Negative controls:** (a) drop one Material role from the mapping so it takes a
    `lightColorScheme()` default → closure fails; (b) make `WeboraTheme` ignore `darkTheme` → the
    projection test fails. Record both results here.

- [ ] TASK-5: `C2` — prove no manifest value can reach a browser token
  - New: `app/src/test/java/app/webora/browser/design/BrowserTokenIsolationTest.kt`
  - Two halves, because neither can fail for the other's reason: a runtime sweep projecting real
    manifests through the real `SiteSkinValidator` and asserting browser tokens are bit-identical
    **while the SiteSkin scheme did move**; and a source scan asserting nothing under
    `design/` mentions `dev.siteskin.core`, `app.webora.browser.siteskin` or `SiteSkinConfiguration`.
  - Acceptance: the sweep includes branding that is conspicuously not Direction A's, and fails if the
    projection stops being exercised.
  - **Negative control:** wire a manifest-derived colour into one browser token → both halves fail.
    Record the result here. This is the ticket's security test; `ADR-013` hands it over by name.
