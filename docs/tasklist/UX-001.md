- [x] TASK-FIX-1: Render the selected direction in the two scenes that decide it
  - Source: field observation — the owner asked to see the chosen design on a regular site and on
    the integrated Bloom Flowers site before treating the decision as final.
  - New: `docs/design/directions/selected-b.html`
  - Modified: `docs/adr/ADR-013-browser-owned-design-tokens.md`
  - Acceptance: five frames in direction B's own tokens — a regular site light and dark, the address
    bar's edit state, and Bloom Flowers with SiteSkin active light and dark. The integrated frames
    show the *existing* `SKIN-002`/`SKIN-003` chrome under the new browser strip, not a redesign,
    since `UX-005` is descoped.
  - Result: rendering falsified the ADR's own cost estimate. The amendment was recorded as "one
    extra token concept"; a strip that never follows the theme cannot reuse the theme's foregrounds,
    so `#146C43` (TLS) measures **2.56:1** on the fixed graphite and `#1552C4` (action) **2.38:1**.
    It needs four theme-independent tokens. The ADR now carries the measured table and the
    correction, and `UX-002`'s consequence line was updated with it.
  - Note: the branded bar is drawn at `#B83A6E`, not the manifest's `#D94F8A`. White body text on
    the raw value is 3.86:1 and fails AA, so `SKIN-001`'s guard darkens it to 5.43:1 — a sketch
    showing the raw colour would show something the browser never renders.
  - Deviation: this is decision-support material rather than a task the plan listed. Recorded as a
    fix because it changed the decision document rather than merely illustrating it.

- [x] TASK-FIX-2: Render direction A in the same two scenes
  - Source: field observation — the owner asked to compare A against the rendered B before
    finalising, saying A looks "more proper".
  - New: `docs/design/directions/selected-a.html`
  - Acceptance: the same five frames as `selected-b.html`, in A's own tokens and with A's components
    (`.a-pill`, `.a-idchip`, `.a-dockbar`) reproduced from `index.html` rather than approximated, so
    the two pages are comparable frame for frame. No amendment applied — A answers `C1` unaided.
  - Result: frame 03 shows the effort gap concretely. A's chip sits beside the field in both states,
    so edit mode is a focus change on an ordinary text field; there is no second component and no
    state machine. That is `C1` satisfied by layout rather than behaviour, and it is the whole
    difference in cost between A and B.
  - Finding the static sketches could not show: in frames 04–05 A's tonal rounded chrome sits
    directly above the site's tonal rounded bar, so the boundary reads more softly than B's fixed
    graphite did. Not a `C1` failure — the chip is still browser-owned text from
    `securityPresentation` — but it is the thing `ADR-006` is ultimately protecting.
  - Correction (`TASK-FIX-3`): this task claimed the softness was "recoverable by applying the same
    fixed-identity amendment to A at the same four-token cost". Measurement says otherwise — a fixed
    graphite chip separates from A's dark ground `#0E1414` at **1.13:1**. The claim was made from the
    mechanism's description rather than from its numbers, which is the same mistake `TASK-FIX-1`
    caught in the ADR.
  - Deviation: decision-support material, as `TASK-FIX-1`. The decision itself was unchanged pending
    the owner's call; `ADR-013` still recorded B at the end of this task.

- [x] TASK-FIX-3: Record direction A as the selection
  - Source: the project owner, after comparing the two renders — *"Yeah let's go / For A"*.
  - Modified: `docs/adr/ADR-013-browser-owned-design-tokens.md`, `docs/adr/README.md`,
    `docs/prd/UX-001.prd.md`, `docs/research/UX-001.md`, `docs/tasklist/UX-001.md`,
    `docs/design/directions/selected-a.html`
  - Acceptance: `ADR-013` names **A — "Soft instrument", unamended**, states A's `C1` mechanism (a
    separate identity chip fed by `securityPresentation(state.mode)`) with its violation condition,
    carries A's measured token pairs, records why the selection changed after rendering, and keeps
    the `C2` compiled-tokens rule and the `UX-002` handoff unchanged. Every other artifact that
    asserted B either states A or is explicitly marked superseded. No source, test, resource or
    build file changes.
  - Tests: `git diff --stat` confirms `docs/` only; `bash scripts/pre-commit-check.sh`
  - Result: the amendment was **tried against A and rejected on numbers**, not dropped for
    simplicity. A fixed chip measures 1.13:1 (`#1C1F26`), 1.41:1 (`#00363A`) and 1.62:1 (`#04413F`)
    against A's dark ground, because the mechanism works in B only where the fixed thing is a
    full-bleed band that *is* the surface; A's identity is an element *on* a surface. A's chip needs
    an ordinary light/dark pair instead of B's four theme-independent tokens — measured at 12.44:1 /
    10.49:1 identity text, 6.80:1 / 7.94:1 TLS secure, 7.65:1 / 8.50:1 not-secure.
  - Note: the chip separates from its ground at only 1.27:1 light / 1.29:1 dark, and the ADR says
    explicitly that this is correct and must not be "fixed". It is a status display, not an
    interactive control, so WCAG 1.4.11 does not require a contrasting boundary; the identity is
    carried by its text, and TLS state by a lock glyph and the word "Secure" as well as by hue.
  - Note: `docs/research/UX-001.md` was marked superseded rather than rewritten. Its account of what
    B would have cost is half the reason A won; deleting it would leave the ADR asserting a
    comparison with nothing behind it.
  - Deviation: none. No source, test, resource or build file was touched.
