## Tasks

- [ ] TASK-1: the pure height rule
  - New: `app/src/main/java/app/webora/browser/siteskin/HubDrawerGeometry.kt` —
    `HubDrawerHeight(min, max)` and `hubDrawerHeight(available: Dp)`.
  - New: `app/src/test/java/app/webora/browser/siteskin/HubDrawerGeometryTest.kt`.
  - `max = available * HUB_DRAWER_MAX_FRACTION` (0.85), `min = HUB_DRAWER_MIN_HEIGHT (180 dp)`
    coerced under `max`. Total: a non-positive available height returns `(0.dp, 0.dp)`, never a
    negative bound and never `min > max`.
  - Acceptance: PRD criteria 6, 9, 14 (the type half).
  - Tests: the bounds table; `min <= max` at every input including zero and a viewport under the
    minimum; the reflective assertion that every parameter and the two component types are `Dp`.
  - Negative controls: (a) add an `itemCount: Int` parameter — the reflective assertion must fail;
    (b) raise the fraction to `1f` — the fraction assertion must fail; (c) drop the `coerceAtMost`
    — the small-viewport case must fail with `min > max`.

- [ ] TASK-2: a scrim that closes, and a panel that does not
  - Modified: `SiteSkinHubDrawer.kt` — `pointerInput { detectTapGestures { onDismiss() } }` on the
    scrim; a consuming pointer-input node on the panel; `Alignment.CenterStart` → `TopStart`.
  - Modified: `SiteSkinHubDrawerContractTest.kt` — the alignment case restated (not relaxed), plus
    new cases for the gesture, the absence of `clickable`, and the panel consuming.
  - Acceptance: PRD criteria 1, 2, 3, 4, 5.
  - Tests: `SiteSkinHubDrawerContractTest`; instrumented cases land in TASK-4.
  - Negative controls: (a) delete the gesture — the contract case must fail, and research F1 is why
    the framework path cannot carry it; (b) replace the gesture with `clickable` — the no-`clickable`
    case must fail; (c) delete the panel's consuming node — the contract case must fail.
  - Note: no `BackHandler` is added and `BrowserBack.kt` is untouched — criterion 4 continues to
    hold structurally, through `UX-022`'s dialog window.

- [ ] TASK-3: a panel the size of its menu
  - Modified: `SiteSkinHubDrawer.kt` — `Box` → `BoxWithConstraints`, `fillMaxHeight()` →
    `heightIn(min, max)` from TASK-1, `windowInsetsPadding(safeDrawing)` moved from the content
    column to the measuring box.
  - Acceptance: PRD criteria 7, 8, 10, 11.
  - Tests: `SiteSkinHubDrawerContractTest` — no `fillMaxHeight`, the height comes from
    `hubDrawerHeight`, exactly one `safeDrawing` read, and the file names no item count.
  - Negative controls: (a) restore `fillMaxHeight()` — the contract case must fail; (b) pass a
    literal `heightIn(max = 600.dp)` — the "height comes from the rule" case must fail.
  - `HubDrawerContent` keeps its signature and body, so every existing instrumented case that drives
    it must pass unedited.

- [ ] TASK-4: the evidence a device can see
  - Modified: `app/src/androidTest/.../SiteSkinHubDrawerTest.kt` — scrim tap closes and dispatches
    nothing; a tap on the panel does not close; a short menu's panel height is materially under the
    viewport; a twenty-entry menu is bounded at the maximum and its last row is still reachable.
  - Acceptance: PRD criteria 1, 2, 3, 7, 8, 16.
  - Tests: `./gradlew :app:compileDebugAndroidTestKotlin` (this checkout has no emulator, so
    compilation is the local gate and the assertions are instrumented evidence, never a gate claim).
  - Sizing is asserted as **bounds**, never `assertIsDisplayed()` — `UX-009` and `UX-023` both record
    that semantics keep full text and unclipped bounds, so a presence assertion cannot see a sizing
    defect.

- [ ] TASK-5: the hosted journey's dismissal stops depending on the menu's height
  - Modified: `app/src/androidTest/.../LiveSiteScreenshotTest.kt` — the scrim tap moves from the
    node's default centre to a point outside the panel at every permitted content height (research
    F3).
  - Acceptance: PRD criterion 17.
  - Tests: compilation locally; hosted acceptance is `CI-010`'s and must be re-taken.
  - Frame 04's own checks from `UX-022` and `UX-025` are **not** edited, and no capture policy,
    deadline, threshold, exclusion or screenshot mode is added — `CI-005`'s constraint: this may only
    ever make the harness refuse earlier.

- [ ] TASK-6: record the convention
  - Modified: `CLAUDE.md` — the section this ticket establishes; `docs/DEVELOPMENT_PLAN.md` if it
    indexes the ticket.
  - Acceptance: PRD criterion 19 and `/validate`'s last bullet.
