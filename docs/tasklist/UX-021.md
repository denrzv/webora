  - Acceptance:
    - `TransportSecurity` has four values with `UNKNOWN` declared first.
    - `BrowserState.transport` defaults to `UNKNOWN`; `BrowserSessionSnapshot` is untouched.
    - `BrowserObservation.MainFrameCompleted` exists as its own case and `toBrowserObservation` no
      longer collapses `WebViewEvent.MainFrameCompleted` into `Page`. `WebViewEvent` gains no case.
    - Transitions: `PageStarted` → `UNKNOWN` unconditionally; `Page` → preserved only when the
      observed `SiteOrigin` equals the committed one, else `UNKNOWN`; `MainFrameCompleted` →
      `completedTransport(origin, failure)`; `PageFailed(TLS)` → `TLS_ERROR`, every other kind →
      `UNKNOWN`, never preserved.
    - `completedTransport` returns `SECURE` only for `https` with no recorded failure; `http` is
      `NOT_SECURE`; a null origin, a non-HTTP(S) scheme and a non-null failure are all `UNKNOWN`.
    - `navigateFromHome` resets to `UNKNOWN`; `activateSiteSkin`/`deactivateSiteSkin` preserve.
    - `securityPresentation(mode, transport)` still returns `null` for `Home` and for an origin-less
      `Regular`; `BrowserScreen:698`'s `checkNotNull` still holds.

      signature on the path.
  - Tests:
    - `BrowserStateTest` — the nine rows in the plan's table (issue reqs. 1–5).
    - `SecurityPresentationTest` — four states carried through, null contract preserved,
      `completedTransport` table including the non-HTTP(S) row.
    - `RendererOwnershipTest` — issue req. 6: a background tab's transport transition updates that
      tab only.
  - Negative controls — all five run, results recorded:
    - `completedTransport` → `SECURE` whenever `origin != null`: **5 failed** — `a completed https
      main frame is the only thing that earns secure`, `a completed http page is known to be
      insecure`, `completion without evidence is unknown rather than a guess`, `a completion
      arriving after a recorded failure cannot go green`, `a scheme redirect resolves to the final
      committed transport in both directions`.
    - `PageStarted` preserves instead of resetting: **first run failed nothing.** The control found a
      real gap rather than confirming coverage — every transport case started from a fresh
      `BrowserState`, whose transport is already `UNKNOWN`, so "reset" and "preserve" were
      indistinguishable and the most security-relevant transition had no test at all. Two cases added
      (`leaving a secure page clears the claim before the next one is known`, `reloading a secure
      page clears the claim until it is confirmed again`), both reached from a genuinely `SECURE`
      state. Re-run: **2 failed**, both of them.
    - `MainFrameCompleted` mapped back onto `BrowserObservation.Page`: **3 failed** — `a page change
      is not a completion, so it cannot earn secure on its own` plus both cross-tab transport cases.
    - `PageFailed` preserves transport: **3 failed** — `no green survives a certificate failure`,
      `a non-TLS failure is unknown rather than a certificate claim`, and the background-failure case.
    - Router re-pointed at `session.activeId`: **7 of 11 failed**, including both new transport
      cases, while the file's discriminator `an event from the selected tab still updates the
      selected tab` **still passed** — `BROWSE-009`'s requirement that the control changes the
      addressing and nothing else.
  - Deviations:
    - **TASK-2's mapping work landed here.** Growing `TransportSecurity` to four values makes both
      consumers' `when` non-exhaustive, so `BrowserChrome` and `SiteSkinTopBar` could not compile
      until they handled the new states — the strings and both exhaustive mappings are therefore in
      this commit. TASK-2 is reduced to its test coverage.
    - `siteskin_tls_secure` / `siteskin_tls_not_secure` deleted here rather than in TASK-4. They were
      verbatim duplicates of `security_secure` / `security_not_secure`, so one guarantee could have
      drifted between modes through a translation edit; both modes now read the shared four strings.
      `siteskin_security_separator` stays until TASK-4 deletes the row that uses it.
    - `completedTransport` has no third scheme arm. `SiteOrigin`'s constructor is private and
      `parse` refuses every scheme but `http`/`https`, so an `else -> UNKNOWN` arm would have been
      unreachable by construction — and the test written for it would have passed through the `null`
      row while proving nothing. Written as *only `https` earns `SECURE`*, with the type-level
      guarantee pinned by its own assertion.
