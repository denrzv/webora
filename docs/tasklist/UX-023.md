## Tasks

- [x] TASK-1: decide the placement in one pure function
  - `HeaderIdentityPlacement` (`INLINE` / `OWN_ROW`) plus
    `headerIdentityPlacement(availableWidth, fontScale, domainLength)`. Total, pure, no Android
    type in its signature. The arithmetic table lives at the declaration.
  - Inputs are platform facts and a browser-derived domain length. `model.title` and
    `model.subtitle` are deliberately not inputs — plan's trust-boundary section.
  - Acceptance: PRD criteria 3 (decision half), 10.
  - Tests: `HeaderIdentityPlacementTest` — every row of the plan's table, zero/negative width,
    both values reachable.
  - Negative controls: read a title length → the isolation case fails; return `INLINE` always →
    the 200% row fails; return `OWN_ROW` always → the anti-vacuity and 100% rows fail.
  - Result: **done**. `bash scripts/pre-commit-check.sh` green. All three controls bite:

    | Control | Failing cases |
    |---|---|
    | rule gains a `title: String` parameter and branches on its length | `the decision reads no site-controlled value` |
    | `INLINE` unconditionally | table, reachability, monotonicity (3) |
    | `OWN_ROW` unconditionally | table, reachability, monotonicity, degenerate inputs (4) |

    The reachability case is the one worth keeping: a rule returning one constant satisfies half the
    measured table — `INLINE` passes both default-scale rows, `OWN_ROW` passes both large-scale rows —
    so a table read one row at a time cannot catch either.

- [x] TASK-2: consume it in the header
  - One `BoxWithConstraints` in `SiteSkinTopBar`; `BrandRow` gains `inlineIdentity`; new
    `SiteSkinIdentityRow` composed between the brand row and `BROWSE-011`'s control row.
  - `SECURITY_CHIP_MAX_WIDTH`, `LOGO_SLOT_SIZE`, `EXPRESSIVE_*` and `BrowserControlRow` untouched.
    Not joining the control row — plan's TASK-2 note gives the named mechanism.
  - Acceptance: PRD criteria 4, 5, 8, 9.
  - Tests: existing contract cases must pass **unedited** (`the security identity is laid out after
    the flexible title`, `the browser control row does not compete with the brand row for width`).
  - Result: **done**, and both existing cases do pass unedited — but only after a fix the plan did
    not predict.

    **The plan said `the security identity is laid out after the flexible title` would pass
    unedited. It did not.** That assertion locates the chip by the file's *first*
    `SiteSkinSecurityChip(`, and `SiteSkinIdentityRow` was declared above `BrandRow`, so the new
    branch became the first occurrence and the index comparison inverted. Fixed by moving the
    declaration below `BrandRow` — file order is incidental — rather than by relaxing the assertion.

    That is worth recording rather than tidying away: a security assertion keyed on *first
    occurrence in a file* is fragile in exactly this way, and its own KDoc had already worried about
    declaration order mattering "for an unrelated reason". TASK-3's branch-complete assertion is the
    durable statement; this one survives as the in-row check.

- [x] TASK-3: make both branches contractual
  - New `both identity placements keep the chip away from site content` and `the placement decision
    reads no manifest value` in `SiteSkinTopBarContractTest`.
  - Instrumented: 320 dp × 200% (chip displayed, at/above `SECURITY_CHIP_FLOOR`, title non-empty)
    and 320 dp × 100% (chip still inside the brand row).
    `compactLargeTextKeepsBrowserIdentityInsideTheBrandRow` is renamed and re-pointed, never
    deleted — its floor assertion is criterion 6.
  - Acceptance: PRD criteria 1, 2, 6, 7, 11.
  - Negative control: compose the identity row unconditionally → the 100% case must fail.
  - Result: **done**. `bash scripts/pre-commit-check.sh` green;
    `./gradlew :app:compileDebugAndroidTestKotlin` green.

    Two assertions were wrong before they were right, both in the repository's own recorded ways:

    - `one width read` counted bare `BoxWithConstraints` and scored the **import** as a read. Fixed
      to count `BoxWithConstraints(` — `UX-020`'s "assert the application, not the declaration".
    - The title check was `onNodeWithText(...).assertIsDisplayed()`, which passes over a title
      measured to zero: `UX-009` recorded that clipping happens in the parent's draw while the
      semantics tree keeps full text and unclipped bounds. It is now
      `assertWidthIsAtLeast(TITLE_FLOOR)` at 100 dp — the same lesson `UX-021` learned when
      `width > 0f` passed on a chip showing one character.

    Negative control: `OWN_ROW` unconditionally fails 4 JVM cases. The instrumented 100% case would
    also fail it, but needs a device — recorded as evidence, never a gate claim.

    `compactLargeTextKeepsBrowserIdentityInsideTheBrandRow` became
    `compactLargeTextGivesBrowserIdentityItsOwnRow`: at that exact scale and width the identity is no
    longer inside the brand row, so the old name was a claim the layout stopped making. Its
    `SECURITY_CHIP_FLOOR` assertion is untouched, which is criterion 6.
