# UX-024 tasklist — the browser's navigation commands become one control

Status: TASKLIST_READY

References:

Each task is a green checkpoint: `bash scripts/pre-commit-check.sh` passes, then commit, then push
before the next one starts. Source changes that break an existing assertion carry that assertion's
re-statement in the same commit — a task that leaves the gate red is not a checkpoint.

## Tasks

- [x] TASK-1: the command list and the overlay value, as pure types
  - New: `app/src/main/java/app/webora/browser/siteskin/BrowserNavigationCommands.kt` —
    `BrowserNavigationCommand { BACK, FORWARD, REFRESH }`, `BrowserNavigationAction(command, enabled)`,
    and `browserNavigationActions(canGoBack, canGoForward, canRefresh)`. Total, compiled order, no
    Android type in the signature, nothing constructible from a `SiteSkinConfiguration`.
  - New: `app/src/main/java/app/webora/browser/siteskin/IntegratedOverlay.kt` —
    `IntegratedOverlay { SITE_HUB, BROWSER_NAVIGATION }`, with the KDoc recording why one nullable
    value replaces two booleans (`UX-022`'s three resets, and criterion 13's exclusion becoming
    structural).
  - Nothing consumes either type yet. The wiring is TASK-2 and TASK-3; this commit is the seam the
    JVM gate can drive, per `BROWSE-009`'s reason for `routeRendererEvent`.
  - Acceptance: PRD criteria 3 (list half), 8 (source half), 12 (type half).
  - Tests: new `BrowserNavigationCommandsTest` — exactly three actions in declared order for all
    eight flag combinations; each `enabled` tracks its own input and no other; the enum has exactly
    three constants.
  - Negative controls, with results recorded here:
    - order the list `FORWARD, BACK, REFRESH` → the order assertion must fail;
    - hard-code `enabled = true` → the per-flag assertions must fail **while count and order still
      pass**, which is why they are separate assertions;
    - give `browserNavigationActions` a `List<SiteSkinItemModel>` parameter → must not compile
      against a file that imports no site type.
  - Result: **done**. `bash scripts/pre-commit-check.sh` green. Four controls run, and each one
    fails a *different* subset — which is the separation the file argues for rather than an
    incidental one:

    | Control | Failing cases |
    |---|---|
    | `FORWARD` declared before `BACK` | `the list is always the three compiled commands in declared order` |
    | every `enabled` hard-coded `true` | `each enabled flag tracks its own command and no other`, `every combination reaches both enabled states` |
    | `FORWARD` reads `canGoBack` | `each enabled flag tracks its own command and no other` **only** |
    | a fourth `STOP` constant | `the command vocabulary is closed at three` |

    The third row is the one worth keeping. Wiring Forward to Back's flag still lets Forward be
    observed both enabled and disabled across the eight combinations, so the reachability guard
    passes and only the per-flag comparison catches it. A test that asked "does every command vary?"
    would have been green on a bouquet reporting Forward's availability from Back's history.

  - Deviation, recorded because it cost a red run: the reflective inventory first read
    `declaredFields.filterNot { it.isSynthetic }` and failed on correct code with
    `expected:<[command, enabled]> but was:<[command, enabled, $stable]>`. The Compose compiler adds
    a `public static final int $stable` to every stable class, and it is **not** marked synthetic.
    The assertion is about what an *instance* carries — which is what a call site could populate —
    so it filters static fields too. Worth knowing before the next reflective model test in this
    repository.

  - Deviations from the plan, recorded:
    1. **`BrowserControlTile` moved** into `BrowserNavigationHub.kt` rather than staying in

       whose name differs from the file's; the types file already declares two, so it is the correct
       home for a third.
    5. **Two extractions to stay under detekt's ceilings**, both recorded at their declarations:
       `ProtectedIntegratedTopBar` and `dispatchBrowserNavigation`/`integratedNavigationHub`.
