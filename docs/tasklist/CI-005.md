- [x] TASK-1: The candidate verdict, as a pure function
  - New: `app/src/screenshotPolicy/java/app/webora/browser/evidence/CandidateVerdict.kt`
  - New tests in: `app/src/test/java/app/webora/browser/evidence/CandidateVerdictTest.kt`
  - Acceptance: `candidateVerdict(focus: FocusVerdict, content: ContentVerdict): CandidateVerdict`
    with a **sealed** `Accept` / `Retry(reason)` and no third case — the deadline already owns "stop",
    and a `Reject` would be a second place to decide the run is over. `Rendered` accepts **only**
    alongside `OwnedByApp`; every other pairing retries with a reason naming which half failed. It
    composes the two existing policies and edits neither, so both fixture suites stay untouched.
  - Tests: the seven in the plan's table, including `contentAloneNeverAccepts` swept over every
    `FocusVerdict` — the coverage guard that fails if a later edit lets content decide alone.
  - Negative control: replace the body with "content decides" (`Rendered → Accept` regardless of
    focus). `renderedUnderASystemDialogIsRetried` and `renderedUnderABlockedScreenIsRetried` must
    fail while `ownedButBlankIsRetried` still passes.
  - Second negative control: make `Blocked` + `Rendered` accept.
    `renderedUnderABlockedScreenIsRetried` must fail **alone**, proving the System UI case is not
    standing in for every non-owned focus.
  - Result: 6 tests in `CandidateVerdictTest`, 0 failures. `bash scripts/pre-commit-check.sh` OK.
  - Negative control 1 (content decides alone): **4 of 6 fail** — the two dialog cases, the sweep,
    and `every retry carries a reason`, whose floor drops when combinations stop retrying.
    `owned and rendered is accepted` and `owned but blank is retried` still pass, which is the point:
    the happy path cannot tell the two implementations apart.
  - Negative control 2 (`Blocked` + `Rendered` accepts): **3 fail, not 1.** The plan predicted this
    would fail `renderedUnderABlockedScreenIsRetried` alone; the sweep and the retry floor catch it
    too. Recorded as run rather than as predicted — the protection is stronger than planned, and a
    tasklist that quietly restates the prediction is how a control stops being evidence.
  - Both controls restored from a copy taken before editing, and the gate re-run green afterwards.
  - Gate: `bash scripts/pre-commit-check.sh`

- [x] TASK-2: The guard asks the verdict about the bitmap it is about to keep

    SUCCESSFUL.
