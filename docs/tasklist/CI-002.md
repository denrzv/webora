- [ ] TASK-2: A readiness gate that observes instead of sleeping
  - New: `scripts/android-emulator-ready.sh`
  - New: `scripts/android-emulator-ready-selftest.sh`
  - Modified: `scripts/android-screenshot-ci.sh`, `scripts/pre-commit-check.sh`
  - Acceptance: `readiness_verdict` is a pure shell function of four observed values — `boot_completed`,
    `bootanim_exit`, `pm_path`, `focus_line` — returning `ready` or a specific reason. `main` polls
    `adb`, requires `READY_SETTLE_SAMPLES` (default 3) consecutive `ready` verdicts, is bounded by
    `READY_DEADLINE_SECONDS` (default 180), and appends every sample with a timestamp to
    `artifacts/readiness.txt` whether it passes or fails. Sourcing the script executes nothing. It
    records the focused window's title and does **not** classify it — TASK-3 owns that knowledge, and
    a second copy in shell would be free to drift. `android-screenshot-ci.sh` runs the gate before
    Gradle and fails the run when it does not reach `ready`, with logcat and diagnostics still
    collected. `pre-commit-check.sh` runs the self-test unconditionally.
  - Tests: `android-emulator-ready-selftest.sh` — a fully ready sample is `ready`; each of the four
    conditions individually missing is not; a null `mCurrentFocus` is not; a device still showing the
    boot animation is not.
  - Negative control: remove one condition from `readiness_verdict` and confirm its case flips to
    `ready`; restore.

- [ ] TASK-3: One owner for what may be dismissed, and a JVM test that can fail
  - New: `app/src/screenshotPolicy/java/app/webora/browser/evidence/ScreenEvidencePolicy.kt`
  - New: `app/src/test/java/app/webora/browser/evidence/ScreenEvidencePolicyTest.kt`
  - Modified: `app/build.gradle.kts`
  - Acceptance: `focusVerdict(dumpsysWindowOutput, appPackage)` is pure Kotlin with no Android import
    and returns `OwnedByApp`, `DismissableSystemAnr(processName, title)` or `Blocked(reason)`. It
    parses every `mCurrentFocus=Window{… u0 <title>}` occurrence and requires exactly one distinct
    title. `DismissableSystemAnr` is reachable only for
    `Application Not Responding: com.android.systemui` — a System UI *crash* dialog, a Webora ANR, an
    unknown window, an absent or null focus and two disagreeing focuses are all `Blocked`. The
    allow-list is one constant containing one process name; there is no `else` branch that dismisses.
    `app/build.gradle.kts` shares `src/screenshotPolicy/java` into the `test` and `androidTest` source
    sets with both `java.srcDir` and `kotlin.srcDir`, and **not** into `main`;
    `:app:assertInspectorAbsentFromReleaseVariants` and `BrowserSurfaceConventionsTest` stay green.
  - Tests: `ScreenEvidencePolicyTest` — the six rows of the plan's decision table, plus `processName`
    extraction, plus a dump containing no `mCurrentFocus` at all.
  - Negative control: (1) add the app package to the allow-list — the Webora-ANR case must fail;
    (2) accept `Application Error:` as dismissable — the System-UI-crash case must fail; (3) drop the
    distinct-title requirement — the two-window case must fail. Restore after each.

- [ ] TASK-4: Refuse to photograph a screen Webora does not own
  - New: `app/src/androidTest/java/app/webora/browser/visual/ScreenEvidenceGuard.kt`
  - Modified: `app/src/androidTest/java/app/webora/browser/visual/LiveSiteScreenshotTest.kt`
  - Acceptance: `requireAppOwnsScreen(label)` reads `dumpsys window windows` through the
    `UiAutomation` the test already holds, classifies it with `ScreenEvidencePolicy`, and returns only
    on `OwnedByApp`. `Blocked` fails the test with the reason and writes the raw dump to
    `diagnostics/window-<label>.txt`. `DismissableSystemAnr` finds a clickable node by view id
    (`android:id/button2`, then `android:id/aerr_wait`), requires exactly one, records view id, node
    text and window title to `diagnostics/interference.txt`, clicks it and re-checks — at most two
    attempts, exhaustion fails. `FLAG_REPORT_VIEW_IDS` is set once on the service info, because
    without it the view-id lookup returns nothing and a recoverable run would fail as "no Wait
    button". `captureDeviceScreenshot` calls the guard after `waitForIdle()` and before
    `takeScreenshot()`; the journey, its matchers, the three file names and the storage path are
    unchanged. Diagnostics go through `PlatformTestStorage` into the tree the workflow already
    uploads, so no artifact path moves and `DEVX-002` starts from the layout it planned against.
  - Tests: `./gradlew :app:assembleDebugAndroidTest` compiles; `bash scripts/pre-commit-check.sh`
    passes. Execution is the hosted run — `AGENTS.md` forbids a software-only emulator here.
  - Negative control: not available on the JVM; the decision this task consumes carries its negative
    controls in TASK-3, which is why the classification was separated from the interaction.
