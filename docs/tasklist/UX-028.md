# UX-028 tasklist — the writer, the projection, the control, the boundary

Status: TASKLIST_READY

References:
- Issue: [#130](https://github.com/denrzv/webora/issues/130)
- PRD: `docs/prd/UX-028.prd.md`
- Research: `docs/research/UX-028.md`
- Plan: `docs/plan/UX-028.md`

Order is deliberate. The writer is content-blind and testable alone; the projection is the ticket's
policy and needs the writer to exist; the control needs a document to copy; the boundary check needs
the classes it names to exist. Nothing later is a prerequisite of anything earlier.

## Tasks

- [x] TASK-1: a total JSON writer over a closed tree
  - New: `app/src/debug/java/app/webora/browser/inspector/JsonDocument.kt`
  - New: `app/src/test/java/app/webora/browser/inspector/JsonDocumentTest.kt`
  - `JsonValue` as `JsonNull`/`JsonBool`/`JsonNumber(Long)`/`JsonString`/`JsonArray`/
    `JsonObject(List<Pair<String, JsonValue>>)`, plus `render()`. Ordered pairs, not a `Map`; `Long`
    only, no floating point, so `NaN` is not representable.
  - Acceptance: PRD criteria 2, 6, 7, 14.
  - Tests: `JsonDocumentTest` — the quote and the backslash escape; a `U+0001` renders as its
    six-character `\uXXXX` escape; newline and tab take their short forms; non-ASCII passes through
    literally; empty array and empty object render empty; nesting indents two spaces per level; key
    order is declaration order; a number is unquoted and a string is quoted.
  - Negative control: delete the sub-`U+0020` branch from the escaper, and the control-character case
    must fail. Applied to the real source, run observed, reverted.
  - Result: **done.** 12 cases green. The control replaced the escaper's `else` with a bare
    `append(character)` and produced exactly one failure — `a control character with no short form
    becomes a six-character escape` — so it is targeted rather than a file that fails wholesale.
    Deviation: the writer emits `\b` and `\f` too, which the plan did not name. They are the two
    remaining short forms JSON defines, and leaving them to the `\u00XX` branch would have produced
    a valid document that disagreed with every other JSON writer for no reason.

- [x] TASK-2: project one snapshot into one document, bounded at one site
  - New: `app/src/debug/java/app/webora/browser/inspector/InspectorJson.kt`
  - New: `app/src/test/java/app/webora/browser/inspector/InspectorJsonTest.kt`
  - `inspectorJson(snapshot: InspectorSnapshot): String`. Top-level keys are the snapshot's declared
    property names in declaration order. Exactly one `JsonString(` construction site, inside
    `bounded()`, which applies `inspectorValue`. Absent values are `null`, never the panel's dash.
  - Acceptance: PRD criteria 3, 4, 5, 6, 7, 8, 9.
  - Tests: `InspectorJsonTest` —
    1. golden document for a fully populated snapshot (pins names, order and nesting in one place);
    2. an all-null snapshot serializes to a valid document of nulls;
    3. a hostile diagnostic pointer — 400 characters carrying a right-to-left override and a newline
       — arrives bounded and flattened;
    4. a 20-item menu and 5 nav items serialize in full, so the payload is not a function of layout;
    5. serializing the same snapshot twice is byte-identical;
    6. a rejected record and a no-record snapshot both serialize validly;
    7. **totality**: every declared field of every reachable inspector record appears as a key;
    8. **closure**: the reachable type graph is `String`/`Int`/`Long`/`Boolean`/enum/`List`/inspector
       record and nothing else;
    9. **signature**: `inspectorJson` takes exactly one parameter, declared `InspectorSnapshot` —
       arity and erasure from the compiled method, the declared type from the declaration line.
  - Note: both sweeps must filter **static** fields, not only synthetic ones. The Compose compiler
    adds `public static final int $stable` and does not mark it synthetic; `UX-024` failed a correct
    implementation on exactly this.
  - Negative controls, each applied to the real source:
    - `bounded()` drops `inspectorValue`, and case 3 must fail.
    - the projection omits `applied`, and case 7 must fail.
    - `InspectorSnapshot` gains `val headers: Map<String, String>`, and case 8 must fail.
  - Result: **done.** 11 cases green; all three controls bit, each on the intended case — the
    unbounded `bounded()` on the hostile pointer alone, the dropped `counts` on the totality sweep
    (and the golden, as expected), the `Map` field on the closure sweep (and the totality sweep,
    since an unserialized field is also a missing key).
  - Deviations, both recorded rather than smoothed over:
    - The control-C field needed `= emptyMap()`. Without a default the snapshot's eight call sites
      stop compiling and the run reports `compileDebugKotlin FAILED` — which reads exactly like a
      control that bit nothing, `UX-024`'s trap. A control has to compile to be a control.
    - Case 3 first asserted a *line-length ceiling* and failed at 151 against a fudge constant. It
      now asserts the emitted value **equals** `inspectorValue(hostile)`. That is the stronger
      statement and the one the issue actually asks for: a serializer bounding at some *other* limit
      would satisfy a ceiling and still disagree with the surface it claims to mirror.

- [x] TASK-3: a copy control that copies what is on screen
  - Modified: `app/src/debug/java/app/webora/browser/inspector/SiteSkinInspectorPanel.kt`
  - Modified: `app/src/debug/res/values/strings.xml`
  - New: `app/src/test/java/app/webora/browser/inspector/InspectorCopyContractTest.kt`
  - `WeboraOutlinedButton` in the `dismissButton` slot; `Close` stays the filled confirm. Feedback is
    a persistent `Box` under the title carrying `contentDescription` + `LiveRegionMode.Polite` only
    once a copy has happened — `BrowserStatusRegion`'s pattern, in the one region of an `AlertDialog`
    that neither scrolls nor competes with the reflowing action row. `LocalClipboard` +
    `rememberCoroutineScope`, `ClipData.newPlainText` with a resource label. The document is
    `remember(snapshot) { inspectorJson(snapshot) }`.
  - Acceptance: PRD criteria 1, 2, 10, 11, 12.
  - Tests: `InspectorCopyContractTest` — executable lines only, comments stripped before matching:
    1. `InspectorJson.kt` constructs `JsonString(` on exactly one line;
    2. the panel serializes its `snapshot` parameter;
    3. the panel names no recorder, `BrowserState`, `BrowserMode` or `latest(`;
    4. the copy path does not call `onClose`;
    5. the feedback flag is set after the clipboard write, not before.
  - Negative controls: key the `remember` on nothing, and rule 2 must fail; call `onClose()` in the
    copy lambda, and rule 4 must fail.
  - Deviation to record if taken: if detekt's ceilings are crossed, extract rather than baseline.
  - Result: **done.** Eight contract rules; four controls applied to the real source, all four bit —
    an unkeyed `remember`, a dismissal callback reaching the control, confirmation moved before the
    write, and a second `JsonString` site. Deviations:
    - **The `remember` rule was wrong on its first run and the control is what said so.** It was
      `Regex("\\bremember\\(")`, which matches a *wrongly keyed* remember and walks straight past an
      **unkeyed** one — and unkeyed is the likelier mistake and the exact shape of the issue's
      tab-change requirement. `remember { … }` left the test green. Now `\\bremember\\s*[({]`,
      which still does not match `rememberCoroutineScope()` because the brace or parenthesis has to
      follow the word itself.
    - **The dismissal control did not compile on its first attempt.** Adding `onClose` as the last
      parameter re-binds the call site's trailing lambda, so `onCopied` went unpassed and the run
      reported `compileDebugKotlin FAILED` — `UX-024`'s trap, which reads exactly like a control that
      bit nothing. Declaring it *before* `onCopied` compiles, and then it fails the rule it should.
    - **Kotlin block comments nest.** The contract test's own KDoc quoted a comment opener while
      explaining that comment openers are stripped, which opened a second comment and swallowed the
      rest of the file. `BROWSE-009`'s "a comment participating in the rule it describes", arriving
      through the compiler instead of through a scan.
    - Eight extra rules rather than the five planned: the plan's five plus "the one site is the
      bounding helper" (counting alone passes if the single site stops bounding — `UX-020`), "the
      panel reads no browser state of its own", and an anti-vacuity check on the slice itself.
