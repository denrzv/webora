  - New: `app/src/test/java/app/webora/browser/siteskin/UntrustedTextTest.kt`

  - Acceptance: `untrustedText(raw: String?, limit: Int)` carries the character walk verbatim from
    `inspectorValue` — whitespace and ISO control characters collapsed to a single space, leading
    runs dropped, `Character.FORMAT` characters removed, the walk itself terminating at the bound
    rather than only its result being trimmed. Both explanatory comments survive: why it is a
    character walk rather than a regex (`\s` in `java.util.regex` matches neither `U+2028` nor
    `U+00A0`), and why the loop may overshoot by one character. `inspectorValue` remains in place as
    a one-line delegation passing `SiteSkinLimits.MAX_SUBTITLE_LENGTH`, so the panel's call sites and
    `InspectorTextTest` are untouched. No behaviour changes for any existing caller.
  - Tests: `UntrustedTextTest` — the bound parameter is honoured at a value other than
    `MAX_SUBTITLE_LENGTH` (proving the limit is not hard-coded behind a parameter); `U+202E` is

    behaviour cases still passed, which is the point: they would have masked the regression on their

  - Result: `bash scripts/pre-commit-check.sh` OK.

- [x] TASK-2: The consent projection — the only path from a configuration into the sheet
  - New: `app/src/main/java/app/webora/browser/siteskin/SiteSkinConsentModel.kt`
  - New: `app/src/test/java/app/webora/browser/siteskin/SiteSkinConsentModelTest.kt`
  - Acceptance: `SiteSkinConsentModel.from(configuration, darkTheme)` is pure — no Compose runtime,
    no `Context`, JVM-testable — and returns exactly six fields: `title`, `subtitle`, `brandColor`,
    `navigationCount`, `quickActionCount`, `menuCount`. `title` resolves as
    `toolbar.title ?: site.name`, matching `SiteSkinTopBarModel.kt:18`, bounded by
    `untrustedText(_, SiteSkinLimits.MAX_TITLE_LENGTH)`; `subtitle` is bounded by
    `MAX_SUBTITLE_LENGTH` and is null when it flattens to empty. `brandColor` is non-null **only**
    when `branding?.primaryColor != null`, and its value is
    `SiteSkinTheme.from(configuration).scheme(darkTheme).primary` — the contrast-guarded projection,
    not the raw hex. Counts are `coerceAtMost` the matching `SiteSkinLimits` constant. Every limit is
    read from core, never copied. The projection is total: it cannot throw on any trusted
    configuration, and a configuration with every optional field absent yields a complete model.
    KDoc records what is excluded — `logoUrl` (a preview fetch would make refusal cost the user a
    second request to the site), `homeUrl` and action payloads (the sheet describes, it does not
    offer navigation), and item labels (five × 32 attacker-chosen characters above an Allow button is
    a site-authored message, not a description).
  - Tests: `SiteSkinConsentModelTest` — a `site.name` of 200 characters is bounded at 64; a name
    containing `U+202E` is stripped; a name containing `\n` flattens to one line; `toolbar.title`
    wins over `site.name` when both exist and `site.name` is used when it does not; no `branding`
    yields a null `brandColor` rather than Webora's compiled `#3F51B5`; `#FFFFFF` on a white
    background yields a guarded, non-white swatch; six navigation items report 5; an empty
    configuration yields a model with a title and three zero counts.
  - Negative control 1: dropped the `untrustedText` bound from `title`. 3 of 13 failed — the
    over-length, `U+202E` and newline cases — and the ten others passed, so none of them stands in
    for the bound. Restored.
  - Negative control 2: made `brandColor` unconditional. 2 of 13 failed — the absent-branding case
    and the complete-sheet case — proving the null is genuinely conditional on the manifest having
    supplied a colour rather than on the projection happening to return one. Restored.
  - Result: 13 tests, 0 skipped, 0 failures. `bash scripts/pre-commit-check.sh` OK.
  - Deviation: the swatch's guarded value is proven twice over, because core's `SecurityValidator`
    already corrects `primaryColor` against `textColor` at 3:1 before the app layer sees it. The
    white-on-white case therefore asserts the outcome of both corrections rather than isolating
    `guardContainer`, which is the honest assertion for a sheet that promises what the chrome paints.
