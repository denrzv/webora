# CI-009: Expressive SiteSkin visual acceptance
Status: PRD_READY

## Context / Problem
M9's expressive browser surfaces and live Bloom product journey are implemented, but the canonical
hosted evidence still records only the older four-frame story. A green journey therefore does not
let a reviewer see the expressive storefront, product-detail history, native SiteSkin hub, and
exact-origin teardown as one complete visual contract. M9 cannot close until deterministic hosted
evidence covers that story and two consecutive cold runs accept it.

## Goals
- Expand the canonical live journey into an ordered visual narrative covering Home, consent,
  expressive Bloom storefront, Happy Days product detail, native SiteSkin hub, history traversal,
  and ordinary browsing after exact-origin departure.
- Keep every frame behind the existing browser-owned semantics, ownership, rendered-content, and
  uncontested-window evidence gates.
- Make contact-sheet accounting and documentation describe the expanded inventory exactly.
- Record two consecutive cold hosted runs whose complete evidence is accepted.

## Non-goals
- Changing production chrome, SiteSkin protocol, trust decisions, Bloom content, or action dispatch.
- Adding screenshot mode, seeded controller state, a JavaScript bridge, arbitrary window dismissal,
  pixel-perfect concept-art comparison, or weaker capture thresholds.
- Making hosted runtime available in a managed checkout without KVM, a connected device, or a
  push-capable remote.

## User stories
- As a reviewer, I can open one contact sheet and judge the complete M9 visual story in order.
- As a maintainer, I get a failing run rather than partial evidence when any canonical frame is
  missing, contested, unrendered, or semantically owned by the wrong layer.
- As a security reviewer, I can see browser identity and controls remain present in integrated mode
  and that all Bloom branding disappears after exact-origin departure.

## Acceptance criteria
1. The canonical hosted journey captures distinct accepted frames for Home, first-use consent,
   expressive Bloom storefront, Happy Days product detail, the open native SiteSkin hub, restored
   product/storefront history states, and final ordinary browsing.
2. Each integrated frame requires browser-owned expressive identity and dock semantics; the hub
   frame additionally requires its native browser-authored section boundaries; the final regular
   frame requires regular identity/navigation and the absence of integrated identity, dock, and hub.
3. Every frame uses the existing full-device ownership, rendered-content, and candidate-verdict
   capture path without staging product/controller state or weakening refusal policy.
4. JVM tests pin the expanded canonical filename order and contact-sheet captions, and the workflow
   continues to fail when PNG cardinality and composed tile cardinality disagree.
5. Screenshot documentation and the walkthrough enumerate the expanded visual story and explain
   what each browser-owned layer proves.
6. Two consecutive cold `Android screenshots` workflow runs for the final CI-009 commit publish the
   complete uncontested frame inventory and matching contact sheet.
7. `bash scripts/pre-commit-check.sh` passes.

## NFR
- Security/privacy: Remote page text may locate accessible web content but never establishes trust;
  no page URL/body or manifest data is added to release logs or captions.
- Reliability/fallback: Missing or contested evidence fails closed and retains diagnostics; no
  partial screenshot set is presented as acceptance.
- Performance: Keep the workflow manual and reuse existing bounded readiness/capture deadlines;
  avoid additional APK builds or a second journey.
- Accessibility: Assertions use the shipped browser-owned accessibility semantics and stable test
  tags; visual evidence supplements rather than replaces semantic coverage.

## Risks
- A larger inventory can become brittle if it asserts remote decorative copy rather than stable
  browser ownership; constrain trust assertions to browser-owned semantics and use remote text only
  to perform the black-box product navigation.
- Capturing an open modal can accidentally validate a page-controlled lookalike; require the native
  hub's browser-authored headings and controls in addition to visibility.
- Hosted-only acceptance cannot be completed locally; compile instrumentation and exhaust all pure,
  unit, workflow, and shell checks before dispatching the final commit, then preserve run links and
  artifact verdicts in QA.

## Open questions
- None. The development plan fixes CI-009 as the final M9 evidence owner and requires two
  consecutive cold accepted runs.
