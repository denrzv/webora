# UX-016 — Evenly distribute controls across the regular browser dock

Status: PRD_READY

## Problem

The Home and ordinary-browsing dock renders six fixed browser commands in a Row that neither fills
the pill nor assigns equal slots. The controls consequently bunch at the leading edge and leave a
visibly larger unused region at the trailing edge.

## Goal

Make the neutral Webora dock geometrically balanced and deterministic without changing its actions,
order, semantics, enabled states, ownership, safe-area treatment, or SiteSkin presentation.

## User stories

- As a person using Home or an ordinary website, I see a deliberate, centered browser dock.
- As a person using a compact display or accessibility font scale, all six commands remain operable.
- As a reviewer, I can verify equal logical slots from geometry assertions rather than icon presence.

## Acceptance criteria

1. Home and regular browsing docks use the full available inner width of the pill.
2. Back, Forward, Reload, Home, Tabs, and More remain in that order and occupy equal-width slots.
3. The first and last slot produce symmetric outer inset and no trailing unused region.
4. Callbacks and Back/Forward/Reload disabled behavior remain unchanged.
5. Every command retains a minimum 48 dp interactive target.
6. The shared shell remains operable at 320 dp and 200% font scale without changing existing system-inset or shell padding ownership.
7. Compose coverage compares slot bounds, centers, widths, and dock edges rather than only asserting command presence.
8. Home-screen visual QA records the balanced dock, or explicitly records a managed-environment runtime limitation.
9. SiteSkin branding, integrated chrome, palette, command vocabulary, and overflow design are unchanged.
10. `bash scripts/pre-commit-check.sh` passes.

## Non-goals

- Reordering or replacing browser actions.
- Changing Webora colours, SiteSkin chrome, or the overflow menu.
- Adding manifest-configurable geometry.

## Risks

- Weighting the 48 dp controls themselves can shrink their semantic targets; equal wrapper slots must
  preserve the existing button contract.
- Loose geometry tolerances can pass the original leading-packed layout; assertions must include
  equal slot width/spacing and symmetric outer geometry.
