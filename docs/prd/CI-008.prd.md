# CI-008: Pin the hosted Back-to-Home evidence contract
Status: PRD_READY

## Context / Problem

`BROWSE-008` fixed the product defect exposed by hosted `CI-007` runs 30 and 31: SiteSkin Back on
the first loaded page was disabled because native Home is not a WebView history entry. The canonical
journey already clicks that control, but it does not explicitly prove the control is displayed and
enabled before the click. A regression can therefore fail later as an address-field timeout and
obscure the actual broken contract.

## Goal

Make the hosted journey name and assert the browser-owned prerequisite that unlocks its
integrated-to-regular transition, while preserving all existing screenshot acceptance gates.

## Requirements

1. Before leaving the accepted integrated frame, the journey asserts that the SiteSkin Back control
   is displayed and enabled.
2. The journey continues through the same visible Back and address-field controls; it does not
   inject Home, controller state, a URL, or test-only product behavior.
3. Existing screen-ownership, rendered-content, readiness, timeout, artifact, and contact-sheet
   policies remain unchanged.
4. Android instrumentation sources compile and a negative control demonstrates that requiring a
   disabled Back control would fail.
5. Documentation records that `CI-008` diagnoses the Back prerequisite locally while the two cold
   hosted `CI-007` runs remain rollout evidence requiring a durable remote branch.
6. `bash scripts/pre-commit-check.sh` passes.

## Out of scope

- Changing browser Back behavior; `BROWSE-008` owns the product implementation.
- Weakening screenshot guards or extending evidence deadlines.
- Claiming hosted screenshots that were not run.
