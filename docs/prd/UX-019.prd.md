# UX-019 — Separate the SiteSkin action bouquet from the Webora menu

Status: PRD_READY

## Context / Problem

In integrated mode the flower hub and the three-dot command both set the same `siteMenuExpanded`
flag. The resulting standalone `ModalDrawerSheet` mixes site navigation, quick actions, favourites,
browser commands, and debug tools into one tall unhosted panel. It has no real modal/drawer owner,
so Android Back reaches browser navigation and sends the user Home instead of dismissing the panel.

## Goal

Give the two dock commands distinct, intentional jobs. The flower opens a compact SiteSkin-coloured
"action bouquet" of circular site actions immediately above the hub. Three dots opens a polished,
neutral Webora bottom sheet containing only browser-owned controls. Both surfaces dismiss before any
page or browser navigation.

## Non-goals

- Adding manifest capabilities, arbitrary remote icons, site-defined geometry, or more than five
  native action shortcuts.
- Moving browser controls into the site action bouquet or applying SiteSkin colours to Webora menus.
- Redesigning regular-mode overflow, the top security identity, tabs, settings, or WebView content.

## User stories

- As a Bloom user, tapping the flower reveals round themed shortcuts for Home, Catalog, Cart,
  Profile, and Call rather than a long settings drawer.
- As a browser user, tapping three dots reveals a clear Webora-only control sheet.
- As a user, Back, outside tap, Close, or selecting an action dismisses the active surface without
  unexpectedly navigating Home.

## Acceptance criteria

1. The integrated flower toggles a popup action bouquet above the hub containing at most five unique
   validated site items in navigation → quick-action → site-menu priority.
2. Every site shortcut is a circular minimum-48-dp control using only guarded SiteSkin
   primary/onPrimary or secondary/onSecondary roles and a closed local semantic icon.
3. Bloom's Home, Catalog, Cart, Profile, and Call actions appear as five distinct accessible icons
   arranged in a shallow flower/petal arc; manifest labels are accessible names, not crowded text.
4. Selecting a site shortcut dismisses the bouquet first and dispatches the unchanged typed
   `NavigationItem`; active-route semantics remain limited to navigation items.
5. The bouquet toggles closed from the flower and dismisses on outside tap, Android Back, tab/site
   generation change, Home, or integrated-mode departure before browser navigation occurs.
6. Integrated three dots opens a browser-owned modal bottom sheet containing Favourite, Page
   information, Tabs, Settings, and debug-only SiteSkin inspector when available; no site action is
   present.
7. The Webora sheet uses only the neutral app Material theme, local icons, large rounded tiles, and
   browser-authored labels/callbacks; SiteSkin colours and remote assets cannot enter it.
8. Close, outside tap, Android Back, swipe dismissal, and selection close the Webora sheet without
   changing page/history unless the chosen command explicitly does so.
9. Only one of the two surfaces can be open, all controls remain reachable at 320 dp and 200% font
   scale, and reduced-motion users are not required to follow animation.
10. Automated Compose and pure contract tests prove separation, bounded action priority, circular
    geometry, typed dispatch, Back dismissal, and browser/site trust isolation.
11. `bash scripts/pre-commit-check.sh` passes.

## NFR

- Security/privacy: website influence remains exact-origin, validated, typed, bounded, and absent
  from browser-owned menu inventory/presentation.
- Reliability/fallback: empty site actions produce no popup; dismissal never falls through to page
  or browser history.
- Performance: no new network, image, cache, or WebView path.
- Accessibility: 48 dp targets, semantic labels/state, deterministic focusable modal boundaries,
  compact-width support, and no label-dependent icon guessing.

## Risks

- A non-focusable popup would repeat the Back fall-through bug; the bouquet must own focus and
  dismiss-on-Back/outside behavior.
- More than five actions would not fit compact width; priority and deduplication must be explicit.
- Reusing branded colours in Webora's sheet would blur the trust boundary; the sheet must read only
  `MaterialTheme`.
