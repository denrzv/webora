# UX-017 — Finalize integrated SiteSkin dock branding and layout

Status: PRD_READY

## Problem

Protected integrated mode already presents five fixed browser commands in an expressive floating dock,
but neutral command tiles obscure the guarded SiteSkin palette, the center hub uses a generic local
flower instead of the already resolved brand asset, and WebView layout does not clearly reserve the
dock's occupied region. The result reads as neutral browser chrome pasted over a second lower surface
rather than one coordinated, site-adapted browser boundary.

## Goal

Make protected integrated bottom chrome a coherent browser-owned, SiteSkin-branded surface. Reuse the
validated color scheme, bounded brand-asset pipeline, and closed semantic icon vocabulary while
preserving fixed browser commands, typed site dispatch, exact-origin lifecycle, accessibility, and
neutral-chrome restoration.

## User stories

- As a user of Bloom Flowers, I see one intentional pink integrated dock with Bloom's validated logo
  as its identity anchor, without actionable page content hidden beneath it.
- As a user navigating away or switching tabs, I immediately return to neutral Webora chrome without
  stale Bloom color, logo, spacing, or actions.
- As an assistive-technology user, every command remains a stable 48 dp target with a meaningful
  browser-authored description and perceivable disabled state.
- As a reviewer, I can prove that presentation adapts only through guarded colors, a bounded decoded
  brand asset, and closed semantic tokens—not arbitrary remote native UI.

## Acceptance criteria

1. Protected integrated mode paints one continuous dock from guarded SiteSkin `secondary` /
   `onSecondary` roles; neutral per-command tiles do not mask that surface in light or dark theme.
2. The fixed command order remains Back, Forward, Brand Hub, Tabs, More with unchanged typed
   callbacks and browser-observed enabled states.
3. The center hub is a stable circular, visually prominent, minimum-48-dp control using guarded
   `primary` and the current configuration's already decoded `BrandAsset` when available.
4. Loading, absent, rejected, failed, or superseded brand assets render a deterministic local
   monogram/flower fallback without a size jump, blank control, or second network path.
5. Back, Forward, Tabs, and More retain local browser-authored icons; manifest input cannot hide,
   reorder, rename, rebind, or replace them with remote assets.
6. Native SiteSkin hub rows map supported validated semantic tokens—including Home, Catalog, Cart,
   Profile, and Call—to consistent local icons, and unsupported tokens fall back deterministically.
7. Integrated browser layout reserves deterministic space for the floating dock and system navigation
   inset so actionable WebView content is not covered, with no DOM/CSS injection or per-site geometry.
8. No retired persistent SiteSkin bottom navigation or duplicate lower browser surface is rendered;
   opening/closing the native hub does not create stale chrome.
9. At 320 dp and 200% font scale the five logical slots remain balanced and every interactive target
   remains at least 48 dp.
10. Exact-origin departure, Home, tab switch, or configuration-generation replacement removes the
    branded dock, asset, palette, hub, and integrated reservation before neutral chrome appears.
11. Automated negative controls prove remote input cannot alter browser command inventory/order/icons,
    escape the closed semantic icon vocabulary, or retain a stale brand asset.
12. Canonical Bloom and regular-browsing screenshot evidence is captured when a connected supported
    Android runtime is available; otherwise the prescribed managed-cloud limitation is recorded.
13. `bash scripts/pre-commit-check.sh` passes.

## Non-goals

- New manifest fields, action types, arbitrary remote native icons, or site-defined dock geometry.
- DOM/CSS modification of Bloom or a general JavaScript bridge.
- Restyling browser security identity or Android system navigation.
- Redesigning the website, neutral regular dock, or SiteSkin schema.
