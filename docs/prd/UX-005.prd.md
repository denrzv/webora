# UX-005: SiteSkin integrated chrome & semantic icon set
Status: PRD_READY

## Context / Problem
The integrated SiteSkin surface is the project's headline experience, but its navigation still
renders prototype Unicode characters (`⌂`, `▦`, `▣`, `●`, `☎`) and its quick-action
launcher is a generic `+`. Live Pixel 6 evidence made the mismatch visible after `UX-002` established
the browser-owned vector mechanism that this ticket was waiting for.

## Goals
1. Replace every supported SiteSkin placeholder glyph with a bundled, browser-owned vector.
2. Keep the protocol semantic: manifests select from a small allow-list of names, never Android
   resources, URLs, fonts, or arbitrary artwork.
3. Make selected bottom-navigation state and quick-action purpose visually deliberate while
   preserving the existing trusted models and dispatch path.
4. Document a useful vocabulary covering home, catalog/flowers, cart, account, call, share, menu,
   search, and deterministic generic fallback.
5. Capture canonical Pixel 6 evidence of the integrated surface when runtime infrastructure is
   available.

## Non-goals
- Remote or manifest-provided artwork in trusted chrome.
- New action types, URI schemes, navigation behavior, consent behavior, or origin activation rules.
- Browser navigation controls in integrated mode; `UX-008` owns that separate browser affordance.
- A schema-major version bump or an icon dependency.
- Redesigning the reference Bloom Flowers website; `DEMO-003` owns final demo fidelity.

## User stories
- As a user, I can recognize Home, Flowers, Cart, Account, and Call without deciphering symbols.
- As a TalkBack user, the existing item label and selected state remain the accessible contract;
  decorative icon geometry is not announced twice.
- As a site owner, I can choose a documented semantic icon name without gaining access to an
  Android resource identifier or remote trusted-chrome artwork.
- As a reviewer, I can see a selected navigation state and meaningful quick-action affordance in
  canonical device evidence.

## Acceptance criteria
1. No supported SiteSkin navigation or quick action renders the old Unicode placeholder set.
2. The trusted icon vocabulary covers `home`, `catalog`, `flower`, `shopping_cart`, `person`,
   `call`, `share`, `menu`, `search`, and `generic`, retaining `grid_view` compatibility.
3. Bloom Flowers' conformance fixture demonstrates Home, Flowers, Cart, Account, and Call through
   meaningful browser-owned icons.
4. Unknown icon names still normalize to deterministic `generic` with `SS-W-ICON-UNKNOWN`; a
   negative control proves resource-like input cannot address arbitrary Android artwork.
5. Bottom navigation renders icon-plus-label states with explicit selected semantics, and changed
   controls retain at least 48 dp targets, TalkBack labels, contrast, and 200% font-scale behavior.
6. Quick actions use the semantic icon of the primary trusted action instead of a generic plus,
   while the expanded menu continues to expose all bounded actions.
7. Pixel 6 visual evidence shows a deliberate selected state and no icon/label collision, or the QA
   report records why runtime capture is unavailable in the managed environment.
8. `bash scripts/pre-commit-check.sh` passes.

## NFR
- Security/privacy: the manifest supplies only a validated semantic token; all resource selection
  is a closed browser-owned mapping and performs no network or dynamic resource lookup.
- Reliability/fallback: null and unrecognized values render the same bundled generic icon.
- Performance: vectors are compiled resources and icon selection is constant-time.
- Accessibility: vectors are decorative beneath the item's bounded accessible label; selected
  state remains programmatic and layouts remain usable at 200% font scale.

## Risks
- Expanding the vocabulary in UI only would drift from core validation and published fixtures.
- Treating a manifest string as a resource name would cross the trusted-chrome boundary.
- A visually dense selected state could collide with labels at large font scale.

## Open questions
None. The roadmap fixes the vocabulary floor, bundled-vector mechanism, fallback, and evidence gate.
