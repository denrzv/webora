# UX-011: Persistent browser-owned navigation shell
Status: PRD_READY

## Context / Problem

Webora already gives ordinary loaded pages a browser navigation dock, but Home/new-tab uses a
separate Tabs button and has no persistent browser controls. This makes browser navigation appear
only after a page loads and turns two states of one tab into visibly unrelated products. The M8
shell must unify those surfaces without imitating Android system navigation or allowing a SiteSkin
manifest to influence browser-owned controls.
## Goals

- Reuse one browser-owned navigation dock on Home/new-tab and ordinary browsing.
- Expose Back, Forward, Reload, Home, tabs, and overflow with state derived from the active tab.
- Keep Home search and the regular address/security presentation coherent with that shell.
- Respect Android navigation insets and system/predictive back without drawing platform controls.
- Preserve accessible names, minimum 48 dp targets, and a usable 200%-font layout.
## Non-goals

- Changing SiteSkin's integrated-mode bottom navigation or the mode-transition contract owned by
  `UX-012`.
- Replacing Android Back/Home/Recents or changing WebView history semantics.
- Adding new tab/session behavior beyond the existing `BROWSE-006` model and switcher.
- Letting a manifest configure browser control labels, ordering, styling, enabled state, or actions.
## User stories

- As a user on Home, I can reach tabs, Home, and overflow in the same place as on an ordinary page.
- As a user, I can tell when Back, Forward, or Reload is unavailable rather than invoking a stale
  action from another tab.
- As a user of gesture or three-button navigation, browser chrome remains above system navigation
  and system Back continues to follow active-tab history.
- As a user with large text, I can identify and operate every shell action without clipping.
## Acceptance criteria

1. Home/new-tab and ordinary non-integrated pages render the same `BrowserNavigationDock`; Home
   disables Back, Forward, and Reload while keeping Home, tabs, and overflow discoverable.
2. The dock exposes tabs directly and invokes the real `BROWSE-006` switcher; ordinary Back,
   Forward, and Reload use only the active tab controller and observed state.
3. The shell consumes Android navigation-bar insets exactly once, does not render fake Android
   Back/Home/Recents, and system Back continues to delegate to active-tab WebView history.
4. Browser-owned address/search and security identity remain present on their applicable surfaces
   without creating a second navigation implementation.
5. A negative contract test proves no manifest/configuration input can hide, relabel, reorder,
   restyle, enable, or dispatch the Home/regular shell.
6. Compose tests prove shell controls have accessible names and at least 48 dp touch targets, and
   Home/regular controls remain displayed at 200% font scale.
7. Relevant JVM and instrumentation test sources compile; device-only gesture/three-button runtime
   evidence may be reported as an environment limitation when no device or KVM is available.
8. `bash scripts/pre-commit-check.sh` passes.
## NFR
- Security/privacy: the browser alone owns shell content and callbacks; no new network or telemetry.
- Reliability/fallback: Home exposes disabled history/load actions rather than stale or no-op state.
- Performance: reuse the existing stateless Compose dock and session/controller seams.
- Accessibility: 48 dp targets, stable semantic labels, disabled semantics, and 200% font support.
## Risks

- Applying navigation-bar padding at both the Activity root and shell could create excess spacing;
  ownership must be confirmed before changing modifiers.
- Six actions may not fit compact widths if the existing pill uses fixed sizing; layout tests must
  cover the repository's pixel-sized device profile and large text.
- Moving Tabs from overflow to the primary row must not remove the menu contract or change SiteSkin
  integrated chrome ahead of `UX-012`.
## Open questions

- None. The backlog fixes the command set, shared implementation, and platform boundary.
