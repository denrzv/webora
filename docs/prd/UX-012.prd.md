# UX-012 — Mode-aware chrome handoff

Status: PRD_READY

## Problem

Webora has a persistent browser shell in Home and regular browsing and a separately secure SiteSkin
surface, but the handoff between them is implicit in renderer branches. There is no single,
testable contract proving which chrome owns each state, so origin changes, consent outcomes, and tab
switches can regress into stale SiteSkin controls or an ordinary page without browser navigation.

## Goal

Make Home → regular → integrated → regular → Home and integrated/regular tab switches deterministic:
exactly one bottom product-navigation owner is visible, while browser-owned security identity and an
escape affordance remain independent of manifest input.

## In scope

- A pure, closed chrome-presentation contract derived from browser-observed `BrowserMode`.
- Rendering Home/regular browser navigation and integrated SiteSkin navigation from that contract.
- Immediate removal of SiteSkin navigation/actions when the observed origin changes, consent does not
  activate, SiteSkin is disabled, Home is selected, or a regular tab becomes active.
- State and structural negative-control tests for transition order, tab isolation, and immutable
  browser-owned integrated security/escape controls.
- Accessibility/instrumentation coverage that identifies the mutually exclusive bottom layers.

## Out of scope

- Changing manifest validation, consent persistence semantics, action resolution, or origin rules.
- Replacing Android system Back/Home/Recents or changing predictive-back dispatch.
- New animation, screenshot infrastructure (`CI-007`), or the M8 walkthrough (`DEMO-004`).
- Redesigning the regular dock (`UX-011`) or integrated top bar (`UX-005`, `UX-008`).

## Acceptance criteria

1. A state/transition test covers Home → regular → integrated → regular → Home and proves each state
   exposes exactly its intended top, content-action, and bottom chrome layers.
2. Declining or permanently denying consent leaves the current page in regular mode with the complete
   browser-owned navigation shell.
3. An observed non-integrated origin removes SiteSkin bottom navigation and quick actions before the
   resulting regular frame is accepted.
4. Switching between integrated and regular tabs derives chrome solely from the selected tab and
   never retains the other tab's identity, navigation, or action layer.
5. A negative control proves manifest configuration cannot suppress the browser-owned security
   identity or Back escape affordance in integrated mode.
6. Android system/predictive Back continues to dispatch through the existing controller and Webora
   does not draw Android system navigation.
7. Relevant unit tests, Android test compilation, lint, and detekt pass.
8. `bash scripts/pre-commit-check.sh` passes.
