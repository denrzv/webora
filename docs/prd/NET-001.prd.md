# NET-001 — Manifest fetcher

Status: PRD_READY

## Problem

The browser can render arbitrary pages and core can validate SiteSkin manifests, but the app has no browser-owned transport that discovers a site's manifest without weakening browsing or origin isolation.

## Scope

- Fetch `/.well-known/siteskin.json` for an observed HTTPS origin in the app layer.
- Enforce bounded timeouts, a 128 KiB response limit, and at most two same-origin redirects.
- Feed successful response streams into the shared `SiteSkinValidator` and expose a closed result model.
- Start discovery alongside navigation without delaying WebView rendering.
- Degrade every transport, policy, and validation failure to regular browser behavior.

## Out of scope

Caching, conditional requests, offline reuse, brand-asset fetching, consent, dynamic chrome, and SiteSkin mode transitions are reserved for later M3 tickets.

## Acceptance criteria

1. Only canonical HTTPS page origins can start manifest discovery, and requests target the well-known manifest path.
2. Redirects are followed only when they remain on the exact canonical origin, with no more than two redirects.
3. Connect, read, write, and call timeouts are explicitly bounded, and response consumption cannot exceed 128 KiB.
4. Successful HTTP responses are validated through `SiteSkinValidator`; non-success, invalid content, oversize, timeout, cancellation, and I/O failures return a closed failure result without leaking response content or page URLs.
5. Browser navigation starts page loading before/as discovery begins and does not wait for manifest discovery to render.
6. Automated tests cover success and negative controls for HTTP origin, cross-origin redirects, redirect overflow, response size, timeout/failure, validation rejection, and non-blocking navigation.
7. `bash scripts/pre-commit-check.sh` passes.
