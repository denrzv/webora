# UX-016 research — Regular dock distribution

Status: RESEARCH_READY

## Question

Where is regular dock geometry owned, and how can equal distribution be proved without changing the
browser command contract or widening website influence?

## Current flow

- `BrowserNavigationShell` is shared by Home and `RegularBrowser`; it owns the existing horizontal
  and vertical shell padding and carries `BROWSER_NAVIGATION_SHELL_TAG`.
- `BrowserNavigationDock` owns the 60 dp pill and renders the six commands in fixed order. Its inner
  `Row` wraps its children instead of filling the surface, which leaves the trailing imbalance.
- `WeboraIconButton` already owns the minimum 48 dp interaction target. The correction should give
  each command an equal full-width wrapper slot, not replace or shrink that target.
- The overflow menu is anchored from More and is not part of the six-slot geometry.

## Trust and origin boundary

No origin decision changes. Home has no active website origin; regular mode may display any observed
origin, but neither page content nor a SiteSkin manifest reaches this browser-authored dock. The six
icons, localized labels, order, enabled states, callbacks, 48 dp targets, pill geometry, shell inset,
and slot distribution remain compiled browser policy. Protected integrated mode continues to use its
separate expressive dock.

## Relevant decisions

- `ADR-013` selects the 60 dp floating pill and requires Webora geometry/tokens to remain compiled.
- `A11Y-001` and repository conventions retain at least 48 dp interactive targets.
- The M8/M9 architecture keeps ordinary browser navigation browser-owned and separate from validated
  SiteSkin navigation.

## Risks and controls

- **Menu anchoring:** More stays inside its own equal slot so the existing dropdown anchor remains local.
- **Rounding:** six fractional slots may differ by a pixel; tests compare with a one-pixel tolerance.
- **False-positive layout test:** assert the dock width, equal centers, equal widths, and symmetric edge
  gaps so simple presence or a still-wrapping row cannot pass.
- **Runtime evidence:** compile instrumentation everywhere; only claim a screenshot when a connected
  Android runtime exists, and never provision a software emulator in managed cloud.
