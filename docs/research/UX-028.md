# UX-028: Research
Status: RESEARCH_READY

## Question

Where does the clipboard document come from, what may it contain, and where must the code that
builds it live so that "not in a release build" is a structural fact rather than a promise?

Three sub-questions the plan cannot commit a file list without:

1. Is there an existing JSON representation of the inspector to reuse, or does one have to be built?
2. Which of the snapshot's values are website-controlled, and where are they bounded today?
3. Which Compose clipboard API is present at Compose UI 1.10.6, and what does it require of the call
   site?

## Origins involved

- **The serving origin** of the page the panel is describing. It is already the snapshot's identity:
  `InspectorBrowserState.origin` is a `SiteOrigin`, and the trace recorder is keyed by
  `SiteOrigin.canonical` — the same key `ManifestCache` and `SiteConsentStore` use.
- **The manifest origin**, which is the same origin by construction: `NET-001` requests only
  `/.well-known/siteskin.json` on the canonical HTTPS origin and follows at most two exact-origin
  redirects, so `transport.manifestUrl` cannot name a third party.
- **The brand-asset origin**, same again: `NET-003` rechecks the logo against the trusted
  configuration's complete canonical HTTPS origin.
- **No new origin is contacted.** The clipboard is a local OS surface; nothing in this ticket opens a
  socket. That is the entire reason the privacy question here is about *contents* rather than about
  *destinations*.

## Manifest-controlled surface

What a website can influence in the copied document, if this ships as scoped:

| Value | Where it comes from | Bounded today by |
|---|---|---|
| `origin` | the committed `SiteOrigin`, canonicalized | `SiteOrigin` construction, then `inspectorValue` |
| `transport.manifestUrl` | browser-composed from the origin | `inspectorValue` |
| `validation.schemaVersion` | the manifest's `schemaVersion` string | `inspectorValue` |
| diagnostic `pointer` | **arbitrary website text** — `SS-W-FIELD-UNKNOWN` reports the key it did not recognise | `inspectorValue` |
| `site.name`, `site.id`, `site.homeUrl` | the manifest | core's clamps, then `inspectorValue` |
| navigation `id`, `label`, `actionType` | the manifest | core's `MAX_LABEL_LENGTH` and the schema's `[a-z0-9_-]` id grammar; the panel additionally flattens the concatenated row through `inspectorValue` |
| colour role `trusted` | the manifest, **after** core's contrast correction | core's `#RRGGBB` normalization |
| every count, every stage, outcome, rejection, cache state, activation and consent value | a closed browser-owned enum or an `Int`/`Long` | the type |

A website can therefore cause a *value* to be selected and can supply *text* in exactly five places,
all of which the panel already routes through `inspectorValue` → `untrustedText` at
`SiteSkinLimits.MAX_SUBTITLE_LENGTH` (128). That walk flattens whitespace, ISO control characters and
Unicode `FORMAT` characters, which is what stops `RIGHT-TO-LEFT OVERRIDE` reordering a pasted
document and what stops a newline forging a second field in a text editor.

**The finding that decides the ticket:** the bounding lives at the *render* site, in
`SiteSkinInspectorPanel.kt`, not in the model. `InspectorSnapshot` holds the raw values. So a
serializer written against the snapshot's fields exports more than the panel shows — a widening of
the export surface achieved without adding a single field, which is precisely the shape the issue's
privacy section forbids. `inspectorValue` must be applied by the serializer at the same points.

## Browser-owned remainder

- **The document's shape.** Field names, nesting and order are browser-authored. No manifest value
  becomes a key. (`SS-W-FIELD-UNKNOWN`'s pointer is a *value*, never a key — a key built from website
  text would let a site invent fields in a document a developer reads as the browser's own report.)
- **The control.** Label and accessible description are resources in `src/debug/res/values/strings.xml`,
  the target is `WeboraButton`'s 48 dp, and nothing manifest-derived reaches its enabled state.
- **The trigger.** A user tap. There is no automatic copy, no copy-on-open, no timer.
- **The destination.** `ClipData.newPlainText`, and nothing else. No share sheet, no file, no network.
- **Availability.** `SITESKIN_INSPECTOR_AVAILABLE` and the variant source set. The panel is
  `src/debug/java`; the release stub is `src/release/java`, shared into `debugRelease` by an explicit
  `srcDir`.

## Prior art

- **`DEVX-001`** — the trace observes and never decides; untrusted text is bounded before it is
  displayed; availability comes from the variant source set, never `BuildConfig.DEBUG`; absence is
  asserted against compiled output. All four bind here unchanged.
- **`NET-004`** — the reason vocabulary is closed, and a reflective sweep keeps it closed as the model
  grows, "so a field added later is covered without anyone remembering". This ticket needs the same
  sweep for the same reason, one consumer along.
- **`DEVX-003`** — the inspector's affordance belongs in a menu, not floating over the product; a
  release build must not draw an entry whose handler does nothing.
- **`UX-026`** — `hubDrawerHeight(available: Dp)`: a pure decision with a two-sided signature
  assertion, because a site-controlled value entering through a parameter is invisible in the result.
  `inspectorJson(snapshot)` is the same shape and needs the same assertion.
- **`BROWSE-009`** — a source scan reads executable lines, never `readText()`, or the prose satisfies
  or violates the rule on the code's behalf; and forbid the mechanism, not a spelling.
- **`UX-020`** — assert the *application*, not the constant: a scan satisfied by a declaration in the
  same file proves nothing.
- **`PRIV-001`** — zero telemetry, no remote sync, and the trace recorder is cleared with browsing
  data. An export the user performs by hand is not telemetry; an export anything else performs is.
- **`A11Y-001`** — resources not literals, `WeboraButton`'s 48 dp, and the live-region rule: the
  region is a persistent node and the announcement is derived from state.
- **`UX-007`/`UX-009`** — `AlertDialog` is the confirmation shape; `WEBORA_SHAPES` now maps
  `extraLarge` to 28 dp, so a dialog no longer clips its own heading.

## Findings

**1. There is no JSON anywhere in the app module to reuse.** `kotlinx.serialization` is an
`implementation` dependency of `:siteskin-core`, so it is deliberately absent from `:app`'s compile
classpath, and core's `assertNoAndroidDependencies` exists to keep that boundary pointing the other
way. Adding the library to `:app` would put a parser on the browser's *release* classpath in service
of a tool that cannot run there. The payload is a closed tree of strings, longs, booleans, nulls,
arrays and objects; a writer for that is smaller than the test that would prove the library was wired
correctly, and it makes deterministic field order the default rather than a configuration flag.

**2. `src/debug/java` is compiled by the JVM gate.** `SiteSkinChromeModelTest` imports
`SITESKIN_INSPECTOR_AVAILABLE`, which is declared only there, and `:app:testDebugUnitTest` is green.
So placing the serializer beside the panel costs no testability, and it buys criterion 13 outright:
the code is not in the release variant's source set at all, rather than being dead code R8 is trusted
to remove.

**3. `AssertInspectorAbsent` would not have caught a new file.** Its `forbiddenClassPrefix` is
`"SiteSkinInspectorPanel"`, matched against compiled class *names*. A serializer in
`InspectorJson.kt` compiles to `InspectorJsonKt.class` and passes. The check needs the new name too,
or the guarantee is "the panel is absent" rather than "the inspector is absent".

**4. The snapshot is already the anti-mixing device.** `rememberInspectorSnapshot` assembles one
immutable value keyed on the recorder, its version and the origin, and `SiteSkinInspectorPanel` takes
it as a parameter. Nothing needs building for the issue's tab-change requirement; what needs
*preventing* is a copy handler that reaches past its parameter for live state. That is a signature
property and a call-site property, and both are assertable without a device.

**5. Compose UI 1.10.6 ships `LocalClipboard`.** Verified from the resolved artifact:

```
androidx.compose.ui.platform.Clipboard
  suspend fun setClipEntry(ClipEntry)
  suspend fun getClipEntry(): ClipEntry?
  val nativeClipboard: android.content.ClipboardManager
androidx.compose.ui.platform.ClipEntry(android.content.ClipData)
```

`setClipEntry` suspends, so the call site needs a `rememberCoroutineScope()`. `LocalClipboardManager`
still exists and is the deprecated predecessor. `ClipData.newPlainText(label, text)` takes a label
that Android 13+ surfaces in its clipboard preview, so it is user-visible copy and belongs in
`strings.xml` like every other label.

**6. The panel's body scrolls and its title does not.** `InspectorBody` is a
`Column(verticalScroll(...))` inside `AlertDialog`'s `text` slot. The two always-visible regions are
the `title` slot and the button row. Feedback placed in the body can appear off-screen at the moment
it is published, which is confirmation the user never sees — and `UX-009` is the local precedent for
an `AlertDialog` presenting text that is laid out and not seen.

**7. Material 3's `AlertDialog` wraps its action row.** `AlertDialogFlowRow` reflows the
`dismissButton`/`confirmButton` pair onto separate lines when they do not fit, which is what makes a
two-control row acceptable at 320 dp and 200% font scale without adopting `UX-007`'s explicit
full-width vertical stack. That stack is consent policy — it exists so a security decision's three
options cannot become a split row — and is not a general dialog rule to copy here.

**8. `—` is a display convention with no place in the document.** The panel prints
`R.string.inspector_absent` for a null. A serializer that reuses `orAbsent()` would emit `"—"` where
the model holds `null`, failing the issue's type-preservation requirement and quietly making an
em-dash the sentinel a consumer has to know about.

## Risks

- **The serializer reads raw model fields** → the plan applies `inspectorValue` at exactly the points
  the panel does, and the tasklist carries a negative control feeding an over-limit hostile string
  through a diagnostic pointer.
- **The serializer's field list is hand-written and drifts from the model** → the plan requires a
  reflective totality test over `InspectorSnapshot`'s declared properties, and a reflective closure
  test over the reachable type graph. The second is what makes "no cookies, no headers, no DOM" a
  compile-time-shaped fact instead of a review promise.
- **`$stable`** → the Compose compiler adds `public static final int $stable` to stable classes and
  does not mark it synthetic. `UX-024` recorded this: a reflective field inventory must filter static
  fields, not only synthetic ones, or it fails on correct code.
- **The capability compiles into a release variant** → the plan puts every new source file in
  `src/debug/java` *and* extends `AssertInspectorAbsent` to name it, because the source-set argument
  and the compiled-output check are independent and this repository keeps both.
- **The copy handler reads live state** → pure function of one parameter, asserted two-sidedly
  (arity and erasure from the compiled method, declared types from the declaration line, per
  `UX-026`'s note that `Dp` is a value class and erasure alone cannot answer it).
- **A control that does not compile is not a passing control** → `UX-022` and `UX-024` both lost a
  negative control to this. Every control in the tasklist must be applied to the real source and the
  run's failure observed, never written as an in-test example.
- **Detekt** → the panel file is already 221 lines with several composables; adding a control, a
  feedback state and a copy handler risks `LongMethod`/`CyclomaticComplexMethod`. The plan extracts
  rather than baselines.
