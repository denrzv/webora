# UX-013: Research
Status: RESEARCH_READY

## Question

What minimum model and Compose primitive layer can lock M9's expressive ownership boundary before
UX-014 and UX-015 integrate a curved header and floating browser dock?

## Origins involved

- The active page's exact HTTPS `SiteOrigin` remains the sole serving origin. UX-013 does not
  discover, fetch, activate, cache, or compare origins.
- An optional logo continues to resolve only through the existing same-origin brand-asset pipeline.
  The primitives must accept already-decided local presentation content, not a URL or bytes.
- External action destinations are unaffected. No action is resolved or dispatched by this ticket.

## Manifest-controlled surface

After core validation and normalization, the site may influence only the already-existing closed
`SiteSkinColorScheme`: primary/on-primary, secondary/on-secondary, and background/on-background.
Downstream callers may place trusted bounded brand text, a decoded/monogram brand asset, and trusted
semantic navigation models into explicitly site-owned content slots, but UX-013 adds no such data
and no new protocol role.

The current `SiteSkinTheme.from(SiteSkinConfiguration)` is already the correct trust seam: it takes
the trusted domain object, supplies deterministic defaults, derives light/dark schemes, and guards
all exposed foreground/container pairs. Extending this into a second palette would duplicate that
security work. The new presentation model should therefore wrap/select this existing closed scheme
and add only browser constants/closed policy values.

## Browser-owned remainder

- Curve shape and depth, corner radii, minimum heights, gutters, elevation/tonal treatment, dock
  placement, content-slot order, system-inset consumption, and minimum touch target are compiled.
- Light/dark selection comes from the platform/user preference; a manifest cannot choose it.
- Motion enablement comes from a browser/platform accessibility decision. A closed motion policy
  can expose immediate versus decorative transition behavior, but no duration or animation value
  comes from the configuration.
- Back, Forward, Tabs, More, security identity, canonical domain/TLS values, semantics tags,
  callbacks, and origin/tab generation remain outside the presentation projection. UX-014/UX-015
  must supply browser-owned content to primitive slots rather than receive it from the model.
- Regular chrome continues to use `WeboraTheme`, whose compiled palette and shapes must never be
  mixed into `SiteSkinConfiguration` or derived from its values.

## Prior art

- `docs/DEVELOPER_PLAN.md` defines UX-013 as the M9 trust-boundary/primitives prerequisite and
  requires 320 dp, 200% font, dark-theme, reduced-motion, and geometry-ownership coverage.
- `docs/ROADMAP.md` fixes M9's ownership split: Android navigation is OS-owned, the persistent dock
  is browser-owned, and validated site navigation/actions move to a branded native hub.
- `ADR-006` requires canonical domain/TLS identity to remain visible, browser-authored, and
  unsuppressible even beside richer branding.
- `ADR-013` establishes two non-interchangeable layers: compiled `WeboraTheme` tokens and the entire
  website-influenceable `SiteSkinColorScheme`. UX-013 must preserve, not broaden, that division.
- `SPEC.md` exposes bounded brand colours/text, semantic icons, typed actions, and a same-origin logo;
  it contains no dimension, path, order, motion, CSS, SVG, or appearance-preset field.

## Findings and decisions for planning

1. Add a presentation-policy file beside `SiteSkinTheme`, not in core: geometry and Compose styling
   are Android/app concerns, while core's security boundary remains platform-free.
2. Reuse `SiteSkinColorScheme`; the presentation model should expose the selected scheme plus closed
   layout/motion policy, avoiding a parallel colour projection.
3. Implement primitives as standalone, unused composables in this ticket. Wiring them into
   `BrowserScreen`, `SiteSkinTopBar`, or navigation would prematurely absorb UX-014/UX-015 scope and
   violate the ticket dependency split.
4. Use a browser-owned deterministic `Shape`/outline for the curved lower edge and a rounded floating
   container for the dock. Their APIs accept composable slots and closed presentation policy, never
   `SiteSkinConfiguration` or raw manifest values directly.
5. Insets are caller-provided padding/inset values or handled by the integration owner. The existing
   screen applies `safeDrawing` once, so primitives must not double-consume global insets.
6. Reduced motion is represented by a pure browser-owned policy choice and must have an immediate
   path. Since the primitives are not integrated yet, tests pin policy behavior/API structure rather
   than inventing visible transitions with no state change to animate.
7. Combine JVM tests for total projection/closed policies and source negative controls with Compose
   instrumentation tests for resolved curve geometry, 320 dp/200% layout, 48 dp targets, and both
   theme projections. Runtime instrumentation may be compiled but unavailable in managed cloud.

## Risks

- **Primitive becomes a generic remote layout seam** → keep site configuration out of primitive
  parameters and pin forbidden types/fields with a structural negative control.
- **Curve clips content at compact width/large text** → place content above a reserved curve depth,
  use minimum rather than fixed content height, and assert visible tagged content at 320 dp/200%.
- **Double safe-area padding wastes or clips space** → leave global safe-drawing ownership with
  `BrowserScreen`; accept only explicit integration padding where needed.
- **Decorative motion hides or delays controls** → closed policy selects immediate behavior under
  reduced motion and primitives never conditionally omit slot content.
- **Site colours visually absorb browser controls/identity** → primitives define branded containers
  only; UX-014/UX-015 retain browser-token sub-surfaces and separately tagged identity/commands.
- **Geometry token provenance test misses resolved clipping** → test actual `Shape.createOutline`
  bounds in addition to source structure, following the UX-009 lesson.

## Open questions

- Exact visual tuning of the curved header and dock may change when photographed in UX-014/UX-015;
  keep values centralized and closed so tuning does not alter the ownership model.
- Android exposes animator-duration preference through platform state rather than a simple Compose
  reduced-motion local. The downstream integration ticket must choose the thin wrapper that obtains
  that preference; UX-013 can define and test only the pure policy input/output.
