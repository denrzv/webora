# NET-003 — Brand asset pipeline research

Status: RESEARCH_READY

## Question

Where should bounded logo transport, type verification, Android decoding, cancellation, and fallback
live so later SiteSkin UI receives only safe renderable data?

## Origins involved

- The serving origin is the browser-observed HTTPS `SiteOrigin` attached to the accepted
  `SiteSkinConfiguration`; it is never derived from the logo URL alone.
- `branding.logoUrl` has already passed core normalization and is absolute and same-origin, but the
  app must re-parse both values and compare complete canonical origins at the network boundary.
- Every redirect target is another candidate origin. Only exact equality of scheme, canonical host,
  and effective port is allowed. A subdomain, alternate port, HTTPS downgrade, or userinfo URL is
  cross-origin and rejected.
- No CDN or third-party asset origin is trusted in v1.

## Manifest-controlled surface

The website may opt out of a logo by omitting `logoUrl`, and may select the path, response bytes,
declared `Content-Type`, dimensions, and same-origin redirect sequence. It can influence pixels only
after all browser-owned transport and decode checks pass. It cannot choose a decoder, accepted MIME
set, resource limits, coroutine dispatcher, cache, fallback text, or UI slot size.

## Browser-owned remainder

- Exact-origin HTTPS policy and the two-redirect limit.
- Explicit timeouts and cancellation of the underlying OkHttp call.
- PNG/WebP MIME allow-list plus byte-signature agreement; SVG is rejected whether declared or
  disguised.
- Transfer, per-axis, and total-pixel ceilings, checked before full bitmap allocation.
- Off-main-thread execution and stale-result suppression.
- A closed result containing either a decoded Android `Bitmap` or a deterministic monogram derived
  from trusted `site.shortName`/`site.name`; downstream UI never receives a remote URL to load.
- Browser-owned domain/TLS chrome and the final bounded logo slot remain later UI work.

## Decode seam findings

`BitmapFactory` is available at the minimum API and supports a bounds-only pass through
`Options.inJustDecodeBounds`; width, height, and `outMimeType` can therefore be checked before the
second full decode. The Android-touching decoder should be a thin implementation behind an
internal interface. Pure JVM tests can exercise orchestration with fake probe/decode outcomes,
while an instrumentation test compiles against and exercises real `BitmapFactory` when a device is
available. Byte signatures should be checked in pure Kotlin before Android decoding: PNG has a
fixed eight-byte signature and WebP requires `RIFF` plus `WEBP` container markers.

The limits are not fixed by the protocol. A 512 KiB transfer ceiling, 1024-pixel per-axis ceiling,
and 1,048,576-pixel total ceiling bound compressed input and worst-case ARGB allocation to roughly
4 MiB while comfortably exceeding a toolbar logo's display size. These are browser policy, not
manifest fields.

## Prior art

- `CORE-004` already removes cross-origin `logoUrl` values, including subdomains. Rechecking at
  fetch time is defence in depth at the point that exercises network authority.
- `NET-001` supplies the exact patterns required for manual redirects, bounded streaming, explicit
  timeouts, cancellable OkHttp calls, and silent rejection.
- `NET-002` shows that website metadata is never trust and that app-layer transport outcomes should
  be closed rather than nullable when policy depends on the failure class.
- The conformance corpus validates manifest URL provenance, not fetched asset bytes. NET-003 tests
  belong in `:app`; no schema or diagnostic change is required.

## Risks

- A generic Coil request could follow or decode more than v1 allows → do not expose Coil or a URL
  to UI; own transport and decoding behind narrow interfaces.
- `Content-Type` alone is spoofable → require one exact allow-listed media type and matching magic.
- A compressed image can expand dramatically → bounds-only decode and overflow-safe dimension/pixel
  policy must precede full decode.
- Coroutine cancellation alone does not necessarily stop a socket → cancellation handler must call
  `Call.cancel()` as in `OkHttpManifestSource`.
- Android local unit tests return framework defaults without Robolectric → keep policy pure, inject
  the decoder, and compile/run real-decoder coverage as instrumentation where hardware exists.
- A cancelled load returning a fallback could overwrite a newer image → coordinator generation/job
  ownership must suppress cancelled and stale publication; cancellation itself is not an outcome.

## Open questions

None. The plan should use the limits and `BitmapFactory` seam recorded above, without expanding the
ticket into rendering, persistence, or general image loading.
