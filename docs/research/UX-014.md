# UX-014: Research
Status: RESEARCH_READY

## Question

How can UX-014 replace only integrated top chrome with the UX-013 expressive header while keeping
canonical identity, Back, active-tab/origin teardown, loading/error state, and existing browser
destinations browser-owned, including at 320 dp and 200% font scale?

## Origins involved

- The selected tab's committed exact HTTPS `SiteOrigin` remains the sole serving origin and the
  upstream activation boundary. UX-014 does not discover, compare, broaden, or persist origins.
- The canonical registrable domain and transport state come from `securityPresentation(state.mode)`,
  derived from the browser-observed mode/origin rather than address text, document content, or any
  manifest string.
- An optional brand asset remains restricted by the existing same-origin asset pipeline. The header
  receives only the accepted `BrandAsset`, and `BrowserScreen` associates it with configuration
  identity so an obsolete load cannot decorate another origin or tab.
- Exact-origin departure already changes the selected tab out of `BrowserMode.Integrated` before
  `chromeHandoff()` projects top chrome. No header-local origin comparison should be added.

## Manifest-controlled surface

- Only values already present in `SiteSkinTopBarModel` may appear as site content: the bounded title,
  optional bounded subtitle, and accepted asset/browser-produced monogram.
- Only `ExpressiveSiteSkinPresentation.colors`, produced from the trusted configuration by the
  existing contrast-guarded `SiteSkinTheme`, may style the branded header container and site content.
- The manifest cannot supply header geometry, padding, shape, ordering, typography, animation,
  semantics, canonical identity, TLS state, browser icons/labels, enabled state, or callbacks.

## Browser-owned remainder

- `SiteSkinTopBarModel.security` stays browser-observed input. The tagged identity must remain a
  separately composed, always-present node with a full domain/TLS content description and visible
  non-colour text; it cannot share semantics with the editable regular address field or be replaced
  by title/subtitle/logo.
- Back stays first, always visible, and uses the existing Webora icon, localized label, 48 dp button,
  browser Material sub-surface, observed history state, and controller/session callback. At history
  root it is disabled rather than removed.
- M9 says UX-014 must preserve tabs/overflow, not relocate them. Today those destinations remain in
  the separately browser-authored SiteSkin menu/bottom contract; UX-015 owns their fixed floating
  dock placement. Adding them to the top header now would duplicate controls and cross ticket scope.
- `BrowserStatusRegion` remains immediately after top chrome, so browser-owned loading progress and
  errors keep their existing state/placement contract. `BrowserErrorPage` stays over WebView content.
- `BrowserScreen` remains the single consumer of `WindowInsets.safeDrawing`; the UX-013 primitive
  intentionally does not read global safe drawing.
- Browser/platform state chooses light/dark and reduced-motion policy. The current integration has
  no reduced-motion wrapper yet; UX-014 should add a thin platform read at the composition boundary
  and pass the boolean to the pure UX-013 presentation factory.

## Prior art

- `ADR-006` requires an always-rendered registrable domain and TLS indicator in browser-owned
  typography/contrast, alongside rather than replaceable by site branding; overflow and settings
  must remain reachable.
- `ADR-013` separates editable address content from browser identity and keeps the Webora palette,
  typography, and geometry compiled. Its identity chip measurements concern regular chrome; UX-014
  must preserve the same structural separation inside a SiteSkin-coloured container.
- UX-008 keeps Back visible in integrated top chrome and browser-token coloured.
- UX-012 makes `PROTECTED_INTEGRATED` an indivisible top projection selected only from the active
  tab's observed mode; exact-origin departure and tab switching remove inactive decoration.
- UX-013 supplies the closed presentation and curved header. It explicitly hands identity/control
  slot population and the platform animator-preference wrapper to UX-014.
- M9's plan assigns only the curved top header to UX-014; UX-015 owns the new browser dock and hub.

## Risks

- **Two-line brand plus identity clips at 320 dp/200%** → use an adaptive browser-owned structure
  that may reflow site content but never conditionally removes identity or Back; instrument bounds.
- **Identity inherits SiteSkin colours and reads as site-authored** → place it on a Webora-token
  sub-surface with its own browser typography/transport colours while retaining the branded frame.
- **Header primitive's 96 dp minimum becomes too short for reflow** → rely on `heightIn(min)` and
  content-driven growth; do not force a fixed height or caller-supplied geometry.
- **Reduced-motion detection introduces Android logic into the model** → keep a thin app wrapper and
  feed its boolean to the pure factory; do not add framework state to core or the projection.
- **Delayed asset changes wrong header** → retain the configuration-identity publication check and
  test the composition contract rather than moving asset loading into the header.
- **Source-only ownership tests become brittle** → combine focused source negative controls with
  Compose behavior/semantics/bounds tests and existing pure handoff tests.

## Open questions

- Android's animator duration scale can be read through `Settings.Global.ANIMATOR_DURATION_SCALE`;
  implementation should confirm the smallest testable wrapper and a conservative immediate fallback
  if the setting is absent or inaccessible.
- Real-device screenshot tuning may adjust only centralized browser-owned dimensions. It may not
  widen the presentation model or make required identity/controls conditional.
