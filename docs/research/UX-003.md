# UX-003: Research
Status: RESEARCH_READY

## Current surface map

`RegularBrowser` in `BrowserScreen.kt` owns the composition boundary. In regular mode it renders
`AddressBar`, then the persistent `BrowserStatusRegion`, then the page/error `Box`. In integrated
mode `SiteSkinTopBar` replaces `AddressBar`, while the status region and page remain shared and
SiteSkin navigation is added separately. The ticket must therefore change the regular branch and
shared error/status presentation without restyling integrated chrome.

`AddressBar` currently contains:

- one full-width `OutlinedTextField` bound to `BrowserState.addressText`;
- `BrowserSecurityIdentity(securityPresentation(state.mode))` below it;
- a `FlowRow` of back, forward, reload, home and more filled buttons;
- a `DropdownMenu` built from the shared closed `browserMenuCommands()` list.

`BrowserWebViewController` already owns `goBack`, `goForward`, `reload` and `navigate`; `BrowserState`
owns `canGoBack`, `canGoForward`, `isLoading`, address edit state and committed `BrowserMode`. The
visual rebuild needs no new state except local menu expansion. Reload can present as stop only if a
real stop command already exists; none does, so this ticket must not draw a non-functional stop
affordance merely because the sketch shows one.

`BrowserErrorPage` is an unspaced `Surface`/`Column` with title, optional registrable domain,
kind-specific copy, retry and home buttons. The retry tag and enabled rule (`retryUrl != null`) are
existing contracts. `BrowserStatusRegion` is deliberately persistent at 4 dp and publishes polite
loading/loaded or assertive failed announcements via pure `browserAnnouncement`/
`liveRegionMode` functions.

## Origin and influence map

### Origins involved

- **Committed page origin:** `BrowserMode.Regular.origin`, a validated `SiteOrigin` observed from
  committed main-frame navigation. `securityPresentation` reads this origin and exposes only its
  registrable domain and HTTPS-derived transport state.
- **Editable address candidate:** `BrowserState.addressText`; it may contain incomplete, stale or
  user-edited text and is resolved only on submit. It is not an identity source.
- **SiteSkin origin:** present only in `BrowserMode.Integrated`. Its manifest may theme integrated
  chrome after validation, but it has no authority over the regular chrome rebuilt here.
- **Error origin:** `BrowserLoadFailure.registrableDomain` and `retryUrl` are created from the failed
  observed navigation. The error page displays only the bounded registrable-domain projection, not
  an arbitrary page-authored title.

### What a manifest/page can influence

- Page navigation observations update address text, loading state, history availability and the
  committed regular origin through the existing state reducer.
- A validated manifest may activate the separate integrated-mode branch. It can affect
  `SiteSkinTheme` and SiteSkin components only.
- A page failure selects one browser-owned error string and may supply an already-sanitised retry
  URL through existing state.

### What stays browser-controlled

- All regular chrome colours, typography, shapes, spacing, icons, strings and command inventory.
- Whether and where identity appears; its domain/TLS content; the `BROWSER_SECURITY_TAG`; and the
  fact that it remains separate from address editing.
- Menu command availability/labels, progress/error announcements, retry/home controls and their
  semantics.
- Local vector inventory. No manifest icon, title, colour, or navigation item enters this branch.

The key negative case is an edited address visibly disagreeing with the committed origin. The chip
must continue to announce the committed origin. A test that only checks the happy path where both
strings match cannot protect `ADR-006`.

## Design/token findings

`UX-002` provides `WeboraTheme`, `WeboraColorScheme`, `WeboraSpacing`, `WeboraRadius`, typography,
and ten local vectors: back, forward, reload, home, menu, more, lock, warning, close and search.
`WeboraIconButton` requires a resource-backed accessible name and applies the shared 48 dp target.
Direction A specifies a 52 dp address pill, tonal identity chip and 60 dp floating dock.

The handoff from `UX-002` is important: Direction A's 38% opacity for unselected dock slots makes an
enabled control look disabled and can violate 3:1. Existing opaque `muted` on browser surfaces is a
measured role; enabled/unselected icons should use an opaque scheme role while truly disabled items
may use disabled semantics and styling.

`BrowserSurfaceConventionsTest` scans every Compose source for literal copy and direct Material
button imports. Keeping components in `BrowserScreen.kt` is possible but the file is already large.
A dedicated `BrowserChrome.kt` can hold the pure visual units without changing state ownership and
will automatically enter the scan.

## Existing evidence and tests

- `SecurityPresentationTest` pins committed-origin projection and secure/not-secure state.
- `BrowserAccessibilityTest` pins announcement selection, live-region mode and the 48 dp wrapper.
- `BrowserFailureStateTest` pins failure/retry state.
- `BrowserRecoveryInstrumentedTest` exercises the error overlay and retry/home tags on a real
  WebView.
- `BrowserFontScaleTest` already supplies 200% font scale, but currently targets consent and other
  screens rather than a standalone regular-chrome layout.
- `BrowserSurfaceConventionsTest` gates resource copy and touch-target wrappers.
- Screenshot/evidence tests use `BROWSER_CONTENT_TAG`; the rebuilt dock must remain outside that
  tagged page region or be explicitly excluded from rendered-content sampling.

There is no focused Compose test for the regular address chrome or the distinct identity node. A
new instrumentation test should compose the extracted chrome with a deterministic state, assert the
tag independently of the field, edit/focus the field, and confirm the chip still reads the committed
origin. Its negative-control helper/source contract must fail when the chip is omitted or fed the
editable text rather than merely asserting today's tree once.

## Likely file set

- `app/src/main/java/app/webora/browser/browser/BrowserScreen.kt` — keep orchestration; call rebuilt
  chrome/error components and preserve status/page ordering.
- New `app/src/main/java/app/webora/browser/browser/BrowserChrome.kt` — address pill, identity chip,
  dock, menu and error presentation.
- `app/src/main/java/app/webora/browser/design/WeboraDesignTokens.kt` (or the existing token owner) —
  only if the chosen opaque navigation role or exact chrome dimensions are not already named.
- `app/src/main/res/values/strings.xml` — resource-backed icon names or state descriptions absent
  from the current inventory.
- New/modified JVM tests for a pure chrome model/security negative control and source conventions.
- New/modified Android Compose tests for layout, edit-state identity, commands, live semantics and
  200% font scale.

No `:siteskin-core`, manifest, network, storage, Gradle dependency, ADR or protocol file needs to
change.

## Risks and mitigations

- **Security identity accidentally follows editable text.** Keep the chrome input typed as
  `SecurityPresentation`, not a domain string, and test a deliberate disagreement.
- **Command drawn without capability.** Derive items from the closed command set and controller
  callbacks; do not add stop until a controller stop contract exists.
- **Enabled and disabled states become visually indistinguishable.** Use opaque role for enabled
  slots, disabled semantics/style only for unavailable history commands, and assert contrast.
- **Floating dock contaminates rendered-content evidence.** Compose it outside
  `BROWSER_CONTENT_TAG`; verify screenshot-region structure in tests/source.
- **Large fonts clip an icon's accessible label or menu string.** Icon labels live in semantics, not
  in fixed visual text slots; menu rows remain Material-sized and are exercised at 200%.
- **Moving code breaks private test tags or recovery tests.** Preserve constants and retry/home tags
  as internal contracts.

## Open questions resolved by research

1. **Reload/stop:** preserve reload because the controller exposes no stop command. Visual fidelity
   does not justify a dead control or expanding runtime scope.
2. **Integrated mode:** explicitly excluded except for the shared status/error layer; SiteSkin
   appearance remains owned by `UX-005`.
3. **Identity test strength:** the meaningful negative control is committed origin versus edited
   address disagreement, plus independent presence of the tagged node.
