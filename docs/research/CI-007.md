# CI-007: Research
Status: RESEARCH_READY

## Question
Which deterministic ordinary HTTPS destination and existing journey seams can add a fourth canonical
frame that proves integrated-to-regular chrome handoff without weakening evidence integrity?

## Origins involved
- `https://denrzv.github.io` remains the live Bloom Flowers origin. Its deployed manifest and page are
  deliberately live inputs for frames 02–03, and the journey first proves this origin is integrated.
- `https://example.com` is the ordinary destination. It is the IANA-reserved example origin, has a
  stable minimal HTTPS document, is already the repository's canonical address-input example, and is
  a distinct complete origin from Bloom. Webora discovers no usable SiteSkin contract there, so its
  observed main frame settles in regular mode.
- No asset origin is added. The ordinary frame asserts only Webora semantics and rendered content;
  third-party decoration, title, or body copy is not an acceptance input.

The transition uses browser-visible operations: Android Back leaves the integrated page for Home,
then Home's browser-authored address field submits `example.com`. This is preferable to injecting a
URL into the WebView/controller because the frame should follow the same navigation seam a person
uses. The intermediate Home state does not receive another canonical frame; it is the browser-owned
escape step between the already-proven integrated state and the regular destination.

## Manifest-controlled surface
Bloom's already trusted manifest controls only frame 03's validated SiteSkin brand presentation,
closed navigation items, and quick actions. It does not choose frame names, destination, capture
acceptance, contact-sheet labels, or regular-frame assertions. The example origin's response may draw
inside the WebView and expose an untrusted page title, but neither is used to decide chrome ownership.

## Browser-owned remainder
- `BrowserMode` and exact scheme/host/port observation decide when integration ends.
- `BROWSER_SECURITY_TAG` and `BROWSER_NAVIGATION_SHELL_TAG` prove the regular identity/navigation
  surfaces are present; their copy is derived from browser-observed origin state.
- Absence of `SITESKIN_SECURITY_TAG`, `SITESKIN_BOTTOM_NAV_TAG`, and
  `SITESKIN_QUICK_ACTIONS_TAG` proves the prior integration's chrome was removed, not covered.
- `BROWSER_CONTENT_TAG` supplies the unchanged rendered-page measurement rectangle.
- `ScreenEvidenceGuard` remains the sole owner/rendered acceptance mechanism. The new frame uses it
  with page content required and gains the same diagnostics automatically.
- Frame filenames remain harness constants and the contact sheet derives captions only from them.

## Prior art

- `UX-011` supplies the persistent regular/Home browser shell and stable tags.
- `UX-012` makes regular and SiteSkin layers mutually exclusive and pins origin-exit handoff.
- `CI-003` requires rendered pixels from `BROWSER_CONTENT_TAG`; `CI-005` verifies ownership on the
  accepted bitmap; `CI-006` settles the device before the unchanged capture loop.
- `DEVX-002` makes the contact sheet total and keeps diagnostics out of the review artifact.
- `HomeScreenTest` already treats `example.com` → `https://example.com` as the canonical safe address
  resolution path.

## Risks
- Public availability can fail → retain the live-journey failure semantics and use the reserved,
  intentionally stable example origin; do not assert its mutable pixels or prose.
- Manifest discovery may still be in flight when regular semantics first appear → wait for the
  mutually exclusive regular layer set and absence of every SiteSkin tag before capture.
- System Back could behave differently from a direct callback → dispatch Android Back through the
  activity, matching the product contract and avoiding an internal controller seam.
- Keyboard/IME can contest the frame → submit with the existing IME action, wait for destination
  semantics and idleness, and let the unchanged ownership guard refuse any remaining obstruction.
- A fourth filename might be silently omitted from presentation → existing composer/count comparison
  is already cardinality-independent; add a unit fixture proving four ordered tiles and document the
  new inventory.

## Open questions
None. The reserved example origin and existing browser-visible Back/address path settle the fixture
and transition without adding product capability or changing the evidence trust boundary.
