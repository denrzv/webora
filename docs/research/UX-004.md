# UX-004: Research
Status: RESEARCH_READY

## Roadmap and decision inputs
`docs/DEVELOPMENT_PLAN.md` and `docs/ROADMAP.md` identify UX-004 as the final M6 browser-owned refresh after UX-002 tokens and UX-003 chrome. `docs/BACKLOG.md` explicitly names `HomeScreen`, `OnboardingScreen`, and `PrivacySettingsScreen`, requires the settings toggle to become a list row, and requires compact per-origin resets that keep the canonical origin accessible. `ADR-013` selects Direction A and requires compiled browser tokens that manifests cannot influence.

## Current surface map
- `HomeScreen.kt` is a `LazyColumn` with a title, direct Material `OutlinedTextField`, empty recents/favourites copy, and one `Card` plus filled button per compiled suggestion. Submission already passes through `resolveAddressInput`.
- `OnboardingScreen.kt` owns a saveable three-page index, vertical scrolling, centered copy, Skip, Next, and Start actions. It uses direct Material typography and raw dp spacing.
- `PrivacySettingsScreen.kt` renders an ungrouped `Column`: heading, sibling toggle label and `Switch`, a permissions heading, one full-width filled reset button per decision, and filled clear/close buttons. The switch has explicit name and state description. Reset labels include the full canonical origin.
- `WeboraDesignTokens.kt` and `WeboraComponents.kt` provide compiled colours, typography, spacing, shapes, `WeboraButton`, `WeboraTextButton`, and 48 dp icon buttons. UX-003 demonstrates the intended Direction A component density.

## Origin and influence map
### Origins involved
- Home suggestions contain compiled, credential-free HTTPS URLs constructed by `SuggestedSite.create`; they are browser-owned inputs, not remote discovery.
- Address entry is untrusted user input and remains gated by `resolveAddressInput` before navigation.
- Privacy decisions contain trusted persisted `SiteOrigin` values; presentation uses `origin.canonical`, not a page title or registrable-domain abbreviation.
- Onboarding has no website origin input.

### What a website or manifest can influence
Only the presence of previously stored consent decisions can determine which canonical origins appear in settings. No manifest label, colour, icon, URL payload, or action reaches these surfaces.

### What remains browser-controlled
All layout, copy, tokens, icons, section order, action inventory, suggestion metadata, state wording, and destructive-action confirmation remain compiled into the app. The global toggle controls whether SiteSkin may activate; a website cannot change it.

## Existing contracts and evidence
- `HomeModelsTest` pins launch destination and suggestion/address safety.
- `PrivacySettingsScreenTest` checks clear-data interaction but does not yet pin toggle semantics, canonical-origin reset naming, or compact row structure.
- `BrowserFontScaleTest` provides a Compose harness at 200% but does not cover these three surfaces.
- `BrowserSurfaceConventionsTest` scans browser Compose sources for literal UI copy and prohibited direct Material button imports.
- `docs/accessibility/CONFORMANCE.md` records current product-wide semantics and must be updated for the changed surfaces.

## Likely file set
- `HomeScreen.kt`, `OnboardingScreen.kt`, `PrivacySettingsScreen.kt` — restyle only, preserving callbacks and state.
- `strings.xml` — any new browser-owned section labels or action descriptions.
- `PrivacySettingsScreenTest.kt` and a new/extended surface instrumentation test — semantics, actions, and large-font layout.
- `HomeModelsTest.kt` only if a pure presentation model is introduced; destination security rules remain unchanged.
- `docs/accessibility/CONFORMANCE.md` — durable accessibility contracts.

## Risks and mitigations
- Preserve `resolveAddressInput` at the final navigation boundary rather than trusting compiled-looking input.
- Use a single merged toggle row to avoid duplicate switch actions while retaining `stateDescription`.
- Render `origin.canonical` as visible wrapping text and include it in the reset action description.
- Keep every screen scrollable and avoid fixed-height text containers at 200% font scale.
- Do not add Material icon dependencies; use existing vectors or text actions.

## Open questions resolved by research
1. No persistence work belongs here: empty recents/favourites remain honest empty states.
2. Reset should be a trailing text action rather than a filled full-width button; it stays named with the canonical origin.
3. Settings uses grouped cards/list rows, while the toggle remains one semantic control.
