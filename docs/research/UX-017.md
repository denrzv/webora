# UX-017 research — Integrated dock identity and lower-edge coordination

Status: RESEARCH_READY

## Question

Which existing trusted presentation and layout seams can finish integrated bottom chrome without
widening website influence, duplicating brand loading, or weakening exact-origin teardown?

## Current composition

- `BrowserScreen` owns one configuration-keyed `BrandAsset` state. It publishes only while
  `publishesBrandAsset` confirms the active `BrowserMode.Integrated` holds the identical trusted
  configuration; otherwise the current projection immediately falls back to a bounded monogram.
- `RegularBrowser` projects exhaustive `chromeHandoff()` state into a `Column`: protected integrated
  top bar, weighted WebView content, then `SiteSkinDock`; regular mode instead ends with
  `BrowserNavigationShell`. The dock is already outside the weighted WebView box, so its full measured
  height is reserved rather than drawn over web content. The app shell consumes `safeDrawing` once
  above this function, including Android navigation insets.
- `ExpressiveSiteSkinDock` owns the full-width inset, 60 dp minimum pill, 12 dp outer inset, 8 dp
  inner padding, equal `RowScope.weight(1f)` command slots, and guarded `secondary` background.
- `SiteSkinDock.DockCommand` currently wraps every weighted slot in neutral Webora
  `surfaceContainer`, visually hiding most of that guarded branded surface. The hub follows the same
  generic command path and hard-codes `ic_siteskin_flower` even though `RegularBrowser` already has
  the current bounded asset.
- Integrated mode no longer composes `SiteSkinBottomNavigation` or `SiteSkinQuickActions`.
  `SiteSkinNavigationHub` is the only native site-command projection and lifecycle code closes it on
  page generation/configuration/mode changes.
- `SiteSkinChrome.siteSkinIconResource` already provides the closed local mapping for `home`,
  `catalog`/`grid_view`, `shopping_cart`, `person`, `call`, and other accepted semantic tokens, with
  `ic_siteskin_generic` fallback. Core validation normalizes unsupported tokens before app projection.

## Origins and lifecycle

The only branded origin is the exact HTTPS `SiteOrigin` stored in `BrowserMode.Integrated`. Brand
colors, asset, navigation items, and actions come from that mode's validated
`SiteSkinConfiguration`. A cross-origin page start changes the mode before presentation; tab changes
project the selected tab; a configuration generation uses a distinct configuration identity. The
existing publication guard prevents late asset results from crossing any of those boundaries.
Regular/Home modes have no access to an integrated presentation and compose neutral chrome.

## Manifest-controlled surface

A validated manifest may select only:

- the existing contrast-guarded `SiteSkinColorScheme` roles;
- a same-origin bounded PNG/WebP that the existing fetch/decode pipeline has accepted;
- normalized site name/short name for deterministic monogram fallback;
- normalized semantic icon tokens and typed `NavigationItem` actions in the native hub.

No new raw color, resource name, URI, image request, layout value, callback, or generic command seam
is needed.

## Browser-owned remainder

Webora retains the five-command inventory/order, labels, browser command drawable resources,
enabled states, callbacks, equal slots, pill/circle geometry, target sizes, content reservation,
system inset consumption, decorative-logo semantics, fallback policy, and mode teardown. The decoded
logo is content inside the browser-owned Brand Hub action; it cannot replace the action's semantic
label or dispatch.

## Risks and negative controls

1. **Stale asset:** passing the unguarded stored pair would leak identity. Pass only
   `currentBrandAsset`, whose configuration identity is checked, and retain publication tests.
2. **Remote browser icon:** only the hub may render `BrandAsset`; Back/Forward/Tabs/More keep literal
   local drawables. A source contract test should pin that closed inventory.
3. **Palette masking/contrast:** remove neutral slot surfaces and explicitly use guarded
   `onSecondary`; center uses guarded `primary` with stable clipped asset geometry.
4. **Accessibility loss:** `Image`/monogram is decorative and the enclosing button retains the
   browser-authored hub content description and 48 dp target.
5. **False overlap fix:** do not inject DOM padding or double-read insets. Prove the existing sibling
   layout places the WebView content bottom at or above the dock top and that regular mode removes the
   dock entirely.
6. **Semantic-token escape:** retain the closed map and generic fallback; test supported Bloom tokens
   and an unknown input at the resource seam.
