# NET-001 research

Status: RESEARCH_READY

## Existing seams

- `:siteskin-core` defines `ManifestSource.fetch(origin): ByteArray?`, `SiteSkinSchema.WELL_KNOWN_PATH`, `SiteSkinLimits.MAX_MANIFEST_BYTES/MAX_REDIRECTS`, canonical `SiteOrigin`, and the total `SiteSkinValidator` pipeline.
- `:app` already depends on OkHttp, MockWebServer, coroutines, and core, but has no manifest transport or discovery coordinator.
- `BrowserScreen` owns the remembered controller and observes main-frame `PageChanged` events; `HardenedWebView` begins rendering independently through WebView.
- `:siteskin-lint` contains a synchronous transport with manual redirects and timeout policy. Its command-specific result/error semantics should not be imported, but it demonstrates the expected OkHttp primitives.

## Origins and remote influence

The browser observes a page URL, canonicalizes its complete HTTPS origin, then requests only `/.well-known/siteskin.json` on that origin. Every redirect target is resolved and canonicalized and must equal the starting origin, including scheme, host, and effective port. HTTP pages, malformed URLs, subdomains, alternate ports, protocol-relative cross-origin targets, and HTTPS-to-HTTP redirects fail closed.

Remote servers control status, headers, redirect locations, timing, and response bytes. They may not choose the request origin, bypass byte/time limits, trigger logging of page URLs/bodies, block WebView rendering, or construct trusted configuration. Only `SiteSkinValidator` can promote bytes to `SiteSkinConfiguration`.

## Browser-owned behavior

The browser owns request construction, HTTPS and exact-origin policy, redirect budget, timeouts, cancellation/lifecycle, response-size enforcement, validation invocation, and fallback. The manifest influences no UI in this ticket. A successful validation result is merely made available to later runtime tickets; all failures leave regular browsing intact.

## Risks and obligations

- OkHttp automatic redirects must remain disabled so policy is checked before each follow-up.
- `Content-Length` is attacker-controlled; preflight rejection is useful but bounded streaming is mandatory. Core already reads at most 131,073 bytes, but transport must itself satisfy the fetcher's 128 KiB contract.
- Cancellation must propagate rather than being converted to ordinary absence; obsolete navigation fetches must not affect newer pages.
- Discovery must be dispatched asynchronously and must never precede or gate WebView `loadUrl`.
- Tests need distinct MockWebServer ports for cross-origin negative controls and a deterministic fake for ordering/cancellation.
- Do not duplicate validator rules or move OkHttp into core.

## Open questions resolved for planning

- Return a closed app-layer outcome (`Available`, `Unavailable`) carrying trusted validation output only on completed transport; do not expose remote error detail to UI.
- Use a suspend fetcher on `Dispatchers.IO`; inject client/dispatcher for deterministic unit tests.
- Wire an internal navigation discovery coordinator at the controller seam so `loadUrl` is invoked synchronously before launching discovery. UI mode changes remain out of scope.
