# UX-019 research — Integrated action/menu separation

Status: RESEARCH_READY

## Question

Which presentation and lifecycle seams can turn the integrated hub into a compact branded action
launcher while giving browser overflow a real dismissible Webora-only modal boundary?

## Origins involved

The SiteSkin action origin is the exact authorized HTTPS `SiteOrigin` held by the active
`BrowserMode.Integrated`; Bloom is `https://denrzv.github.io`. No new asset origin exists. The current
bounded brand asset stays in the hub and action icons remain compiled Android resources. The Webora
sheet is originless browser UI.

## Manifest-controlled surface

After validation, a site may supply bounded navigation/quick/menu items containing normalized IDs,
labels, closed semantic icon tokens, match state, and typed actions. It may also supply colours, but
only the already contrast-guarded `SiteSkinColorScheme` roles reach the circular site controls. The
site cannot choose popup geometry, item count/priority, animation, browser commands, neutral sheet
palette, dismissal, or callbacks.

## Browser-owned remainder

Webora owns the five-action cap, deduplication and source priority, circle/arc geometry, target size,
local icon lookup/fallback, focusable popup, dismissal, command separation, and all three-dot sheet
inventory/layout. A platform `Popup` with focus plus dismiss-on-Back/outside is appropriate for the
anchored bouquet. A Material `ModalBottomSheet` is appropriate for browser overflow because it owns
scrim, Back, outside tap, swipe, accessibility pane/focus, and rounded modal geometry.

## Current failure

- `BrowserScreen.siteMenuExpanded` is set by both hub and More.
- `RegularBrowser` passes `onOpenSiteHub` to both `SiteSkinDock.onOpenHub` and `onMore`.
- Root `SiteSkinMenu` is a bare `ModalDrawerSheet`, not hosted by `ModalNavigationDrawer` or another
  modal owner. It mixes all site and browser rows and publishes no dismissal callback.
- The browser's custom `BrowserBackHandler` therefore wins and navigates Home under the sheet.

## Design exploration

### Token system

- Site petal primary: guarded `SiteSkinColorScheme.primary` / `onPrimary`.
- Site petal secondary: guarded `secondary` / `onSecondary`.
- Site backdrop: transparent; the distinct circles, not a generic panel, form the visual object.
- Webora sheet: app `surface`, `surfaceContainer`, `primary`, `onSurface`, and standard scrim only.
- Typography: existing Webora `titleLarge` for sheet identity, `labelLarge` for command tiles, and
  bounded accessible manifest labels without visible text in the compact bouquet.

### Layout candidates

Flat row was rejected as a generic toolbar duplicated above another toolbar. A radial full circle was
rejected because it steals WebView space and makes five targets hard to fit at 320 dp. The selected
shallow arc reads as petals opening from the branded flower while staying one-handed and bounded:

```text
          (Catalog)  (Cart)
     (Home)              (Profile)
                 (Call)
        [ Back  Forward  FLOWER  Tabs  More ]
```

The actual five-circle lift is symmetrical and labels remain accessible names. Browser overflow uses
a quiet two-column utility sheet:

```text
╭──────────── Webora ─── × ─╮
│ [ ★  Add favourite      ] │
│ [ ⓘ Page info ] [ ▣ Tabs ]│
│ [ ⚙ Settings  ] [ ◉ Dev  ]│
╰───────────────────────────╯
```

The deliberate visual risk is the floating petal arc; the browser sheet stays restrained so the two
surfaces cannot be confused.

## Prior art

UX-017 established the guarded branded dock, current bounded brand identity, fixed browser commands,
and sibling content reservation. UX-018 established real modal window ownership and Back priority.
`SiteSkinQuickActions` already proves `DropdownMenu.onDismissRequest`, but its generic vertical list
does not meet the integrated action design.

## Risks

- Popup alignment/compact overflow → cap at five, center on the hub, use 52 dp circles and symmetric
  bounded lifts, and assert geometry at 320 dp.
- Back dispatch → use focusable `PopupProperties` and `ModalBottomSheet`; connected tests must send a
  real Back event.
- Duplicate actions → dedupe by normalized ID after navigation → quick → menu concatenation.
- Stale exact-origin UI → close both states on tab/config/page generation and make the dock
  structurally unreachable outside integrated mode.
