Frame 03 is the whole cost of direction B

In frames 01–02 the address bar is not a text field. It renders securityPresentation(state.mode) as non-editable browser-owned text, derived from the committed SiteOrigin. Tapping it produces frame 03: the real editable field, with the identity moved to its own row underneath.

Two components where every other browser ships one, and a state transition between them. That is the extra effort — not the styling. Collapsing them into a single editable field that displays the domain is the thing ADR-006 forbids.

04–05Bloom Flowers — manifest accepted, branding applied

The site now supplies colour, a logo, a title, a bottom navigation and a Call quick action. The dark strip at the top does not change, in either theme. That is the amendment doing its job: the boundary between what Webora says and what the site says is a thing you can see, not a thing you have to read about.

What frames 04–05 are and are not proposing

The pink bar and the bottom navigation are the existing integrated chrome from SKIN-002/SKIN-003, not a redesign — UX-005 is descoped. What is new in these frames is only the strip above them.

The site asked for #D94F8A. White body text on it is 3.86:1, which fails AA, so the contrast guard darkened it to #B83A6E — 5.43:1. The browser already does this; it is drawn here because a sketch that showed the raw manifest colour would be showing something the browser never renders.

·What the amendment actually costs

The ADR said “one extra token concept”. Rendering it showed that is optimistic: a fixed dark strip cannot reuse the light theme’s foreground colours, so it needs its own set.

On the fixed stripLight theme’s valueNeeded instead
TLS indicator#146C43 — 2.56:1#5BC98A — 7.98:1
Action / focus#1552C4 — 2.38:1#8AB4F8 — 7.83:1
Body text—#EDEEF2 — 14.22:1
Secondary text—#99A0B0 — 6.29:1

So the amendment is four tokens, not one — an on-strip foreground set that is theme-independent. That is still cheaper than A’s identity chip, which costs chrome height on every screen, and it is checked once rather than per theme. But it should be recorded accurately before UX-002 builds from it.
