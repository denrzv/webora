# /review

Review the change: architecture, security, tests, complexity. Write
`reports/review/<TICKET>.md` from `reports/review/template.md`.

Include the **Not findings** section — things that look wrong but are not, with the reason. It stops
the next review re-litigating them.

Address findings as `TASK-FIX-N` micro-tasks with new commits, not by amending history.
